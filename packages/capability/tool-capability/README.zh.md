# @aeven/tool-capability

[English](README.md) | 中文

## 概述

`avn-tool-capability` 让 Aeven 在不询问任何人的情况下为会话所有者学习可复用的流程。使用 `store: memory`（默认值）时，每套已学流程就是一条长期记忆：它的完整 Markdown 是所存文本，而它的摘要则是被精简过的流程，因此轮次开始时的记忆召回本身就带着步骤，`memory_get` 读取其余部分。每次提炼之前，学习器会列出会话所在工作区能看到的所有流程（`ctx.memory.procedures`），因此已知那类任务的工作会合并进对应的流程；结果会替换以其名称存储的每条记忆，以及它声明已涵盖的每套流程。不同流程的数量超过 `consolidateAbove` 时，学习器还会把同一类任务的流程分组，并在后台合并每一组，每个进程中每个所有者与工作区只做一次；合并只保留对这类任务整体成立的内容以及没有被更新流程推翻的每条已验证事实，把各实例之间不同的值改为占位符，说明只有部分实例采取的步骤何时该采取，且长度不超过其中最长的一套。流程中的凭据（已知格式的令牌、私钥、URL 中的密码，以及凭据类键名的值）会在存储前被脱敏，因为召回会把流程重放进之后的请求。没有任何东西被写成 skill（技能）或能力文件。使用 `store: capabilities` 时，学习器改为写入能力候选，并如下文所述以 `<procedure_context>` 召回。

- **学习器。** 一次以至少 `minSteps` 次工具调用完成的轮次（不计 skill、capability、memory、todo、tool-search 与 job-output 这些记账），且最后一次调用成功，会在结束时就成为学习素材。一次走会话路由（或配置的 `provider`/`model`）的后台模型调用决定跳过它、创建一套流程，还是把它合并进同一类任务的既有流程，并写入“快速路径”（最少的调用次数与要避开的耗时点）、“何时使用”、“事实”（这份工作对工作区或应用验证过的内容，按原样写出）、“前置条件”（包括用户声明的偏好）、“步骤”、“验证”与“恢复”。该调用能看到每次工具调用的思考与运行时长，以及该轮次在思考与工具之间的时间分配，因此快速路径削减的正是耗时的部分。当用户的下一封消息纠正该轮次或抱怨它太慢时，同一份工作会带着那条消息再次成为学习素材，替换它产出的流程。同一所有者的提炼一次只运行一个。新能力记录它的来源：请求、用到的工具，以及该轮次的时长、工具调用、失败与 token，作为基线。在不失败的情况下遵循某项已学能力的工作不会教出任何新东西；它的执行反而是证据。已退役的能力绝不会被重新创建。
- **复用。** 在每个直接用户轮次的开始，一次有界模型调用按意图、结果与约束为符合条件的流程摘要打分。候选与已退役流程被排除。最多 `maxRecalled` 条高于 `recallMinScore` 的匹配被读入有界的建议上下文；没有合格项时不返回任何内容。
- **证据。** 只有报告自己确实使用了某条召回流程或被有意查看流程的轮次才记录一次执行，含其工具、重试、token 与模型的 `report`；下一轮次中的纠正与该回复上的评分稍后附上。注册表的规则把这些证据转化为状态变更。
- **工具。** `capability_manage` 提供 `learn`（用户要求时）、`view`、`list`、`update`、`write_file`、`report`、`retire` 与 `restore`。它们都不询问用户；删除留给 Settings → Memory。

## 使用本包

按 agent 挂载它，放在 host 的 `capability` 注册表旁边（`standard`、`cordis` 与 `ptc` preset 都包含它）。

| 字段 | 默认值 | 含义 |
|---|---|---|
| `promptOrder` | `116` | 能力指引段落的顺序 |
| `maxRecalled` | `3` | 每轮次召回的流程上限 |
| `recallTimeoutMs` | `15000` | 前台意图选择的截止时间 |
| `recallMinScore` | `0.8` | 最低意图相关性分数；该分数不衡量信任 |
| `recallMaxChars` | `6000` | 整个建议上下文的字符上限 |
| `store` | `memory` | 已学流程的存放处：`memory`（长期记忆，由记忆召回读出；没有记忆服务时加载失败）或 `capabilities`（能力文件） |
| `learn` | `true` | 是否从已完成的工作自动学习 |
| `minSteps` | `3` | 一个轮次需要多少工具调用才成为学习素材 |
| `timeoutMs` | `120000` | 一次学习模型调用的预算 |
| `maxOutputTokens` | `16000` | 一次学习模型调用的输出上限；推理模型会先用其中一部分思考再作答 |
| `maxInputTokens` | `32000` | 一次学习模型调用的输入预算，按每 token 四个字符估算；更长的 transcript（文本记录）先被精简，再被截断 |
| `consolidateAbove` | `40` | memory 存储：会话能看到的不同流程超过此数时，同一类任务的流程会在后台合并；`0` 表示从不合并 |
| `candidateTtlDays` | `30` | memory 存储：未获确认的 `candidate` 流程在归档前等待的天数；已归档的流程保留下来以便恢复，但既不被召回也不被合并 |
| `provider`、`model` | — | 显式的学习路由；缺省时使用各会话自己的路由 |

使用 memory 存储时，学习会等到人的下一条消息，并把它读作反馈：一次纠正或对耗时的抱怨会改变流程，而一条否定或质疑答案的回复意味着什么都不学。被记录为关于这个人本身的轮次记忆永远不会成为学习素材。写下的流程是 `candidate`，除非它在没有纠正的情况下替换掉一条 `active` 流程并保留其中大部分步骤；当它支撑了人未予纠正的工作后，记忆召回会把它提升为 `active`，而一次纠正或负面评价会把它退回 `candidate`。因为这个人要求而保存或导入的流程立刻就是 `active`。

<a id="model-experience"></a>
## 模型体验

### 能力指引

#### 模型看到什么

在有所有者的会话中，已学流程是不可信的历史参考。当前请求优先；流程绝不授权任何动作、扩大任务或要求遵循步骤。只有实际使用才作为证据上报。新候选需要经过有意验证才能进入自动召回。

#### Token 影响

在有所属者的会话中，这段固定指引随每个请求包含；其他会话没有。

#### KV Cache 影响

按会话固定。

### 流程召回

#### 模型看到什么

消费方追加一条持久的 `<procedure_context>` 消息，含建议性框架说明与 JSON 记录，记录里有名称、修订、状态、资源目录、描述与流程正文。被截断的记录会被标记。另一次选择器调用看到有界的摘要并返回名称/分数对；只接受来自合格输入的名称。有意查看使用 `capability_manage` 的 `view` 动作，带同样的建议性框架。

#### Token 影响

选择器使用学习的输入/输出上限以及它自己的前台截止时间。召回文本受 `recallMaxChars` 约束；在存在合格流程时，模型每个直接用户轮次都可能承担这次选择调用。

#### KV Cache 影响

在用户消息之后仅追加。

### 学习调用

#### 模型看到什么

学习器的模型调用是会话之外的一次独立请求；会话所用的模型永远看不到它。它的系统提示词是固定文本，说明要学什么、每套写入的流程都有的章节，以及 JSON 回复形式；它的用户消息是组装好的 transcript，包含该轮次的请求、它的时序、它的工具调用及其思考、运行秒数与结果、回答、当这份工作再次成为学习素材时用户的纠正或抱怨、现有流程清单，以及最多两项相关能力的完整流程（使用 memory 存储时，是按记忆召回与共有词排序的最多 120 套流程清单，以及其中三套的全文）。后台合并还会在同一路由上发出另外两种调用：一种列出最多 150 个流程的名称与描述，询问哪些属于同一类任务；另一种按从新到旧发送一组流程的全文，要求给出合并后的流程。该调用写出的内容只有通过 skill 工具加载该能力时才作为一条已记录的工具结果进入会话。

#### Token 影响

每个成为学习素材的轮次一次独立请求，位于会话自身请求之外。它的输入受 `maxInputTokens` 约束，按每 token 四个字符估算（而不是提供方自己的分词器），并计入固定提示词；输出受 `maxOutputTokens` 约束。超过输入预算时，学习器先缩短每次工具调用的参数与结果，使整次运行保持可见，再丢弃最旧的工具调用并说明省略了多少次；仍高于预算的文本保留开头并以截断标记结尾，因此最新的证据得以保留，且没有任何请求是无界的。

#### KV Cache 影响

对会话无影响：该调用是会话日志不携带的请求，只发送一次并带自己的固定提示词，因此它既不读取也不延伸对话的可复用前缀。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与延期工作

- **选择会带来延迟与成本** —— 召回使用模型相关性分数，而不是经校准的置信度估计。后台学习器中的相关能力查找仍使用关键词重叠。
- **候选需要有意验证** —— 自动学习存入候选，却不使其具备召回资格。
- **暴露不等于使用** —— 执行证据需要一次模型报告；查看或忽略一套流程不会记录任何成功使用。
- **指令优先级取决于模型行为** —— 建议性框架并不能证明模型总会拒绝相冲突的历史文本；冲突回归测试已延期。
- **纠正靠措辞识别** —— 纠正必须以“that's wrong”或“it didn't work”这类短语开头，才会算在前一轮次上。
- **单样本基线** —— “首次”指标来自学到该项能力的那一个轮次。
- **不变量省略** —— 不发布运行时不变量伴随模块，因为学习器不拥有自己的持久事实：使用 `store: memory` 时一套流程就是长期记忆服务会取代的一条记忆，使用 `store: capabilities` 时它是注册表拥有的能力文件，而一次执行通过 `ctx.capabilities.recordExecution` 成为证据，因此学习器持有的唯一关系就是进程内那个逐一提炼单一所有者工作的队列。
