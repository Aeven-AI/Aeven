# @aeven/client-ui-tts

[English](README.md) | 中文

## 概述

本浏览器插件在 composer 的前置控件行中添加一个扬声器开关。开关打开期间，每条助手回复都会逐片段朗读，音频由宿主合成、由本浏览器播放。

<a id="use-this-package"></a>
## 使用本包

与宿主的 [`text-to-speech`](../../speech/text-to-speech/README.zh.md) 各行一起加载。朗读按会话生效，且初始为关闭：开关只为当前打开的会话打开朗读，重新加载后回到关闭状态。在回复进行中打开开关时，它从那一刻起朗读，而不是朗读屏幕上已有的文本。

<a id="understand-the-implementation"></a>
## 理解实现

<details>
<summary>维护者细节——点击展开</summary>

开关通过标准的 `useChat` 席位读取实时步骤，展平其中的文本块（代码与表格会被丢弃），再把不断增长的文本交给每个会话一个引擎。引擎在句子结束时切分片段，或在某个分句携带足够文本、可以单独朗读时按分句切分（12 个字符，中文为 4 个字符），并且交给宿主的内容从不超过 120 个字符，因为 Edge 在返回音频之前大约要为每个字符花费 50ms。四个片段会在播放之前并行合成，解码后的缓冲区在单个 `AudioContext` 上调度，每个片段都有无缝的起始时间；打开朗读的那次点击同时会恢复该上下文，因此第一个片段不必等待取消挂起。宿主无法合成的片段会重试一次，然后被跳过，因此单次失败不会让回复的其余部分失声。新的步骤或已关闭的开关会停止所有已调度的源，并中止正在进行的合成。

朗读语言按片段选择：书写系统直接判定日语、韩语、中文、阿拉伯语、希伯来语、俄语、希腊语、印地语与泰语；其余情况由各语言自身的字母与停用词得分区分拉丁语系语言，并由当前正在朗读的语言打破平局。其他任何语言都会走宿主完整的 Edge 目录，由该语言的母语地区朗读它，因此本插件不参与评分的语言也能得到自己的语音。

</details>

<a id="dev-note"></a>
## 开发备注

三个决定共同支撑朗读器。引擎通过 `AudioBufferSourceNode` 把解码后的缓冲区首尾相接地调度，因此决定缺什么的是队列而不是播放器：`pump()` 保持预取四个片段、提前调度十二秒，`drain()` 在自己的 `finally` 中重新 pump。停止会在分句仍在进行时打断 drain；若没有那次重新 pump，下一次请求会发现通道正处于 pump 状态，从而什么都不播放。

针对单条消息的操作运行在自己的通道 `message:<id>` 上，因此朗读某条消息不会干扰正在进行的回复，回复也不会打断某条消息的朗读。会话开关沿用普通的会话通道。

`toSpeechText()` 会去掉 Markdown 强调标记，再去掉任何残留的强调或表格标记，因为收到这类标记的朗读器会把它念出来——例如读到粗体文本时念出「asterisk」。

不发布运行时 invariant 伴随模块：朗读器拥有一个音频上下文，以及在宿主已合成音频之上的一个队列，而它能够重述的那些事实属于那个语音 Remote。

<a id="model-experience"></a>
## 模型体验

无，因为朗读器只渲染模型已经产出的回复文本，不向模型发送任何内容。

#### KV Cache 影响

此处没有任何内容进入模型请求，因此不影响提供方的缓存复用。

## 已知限制与延期工作

<a id="known-limitations-and-deferred-work"></a>

- 开关以会话为范围：重新加载会恢复该标记，但两个会话会同时朗读，而 composer 行没有全局停止。语音选择器只在当前浏览器中写入按语言记录的偏好。
