# @aeven/client-ui-automations

[English](README.md) | 中文

## 概述

侧栏的 Bots 链接打开 `/bots`，支持直接访问和刷新。`/bots` 以卡片列出每个 Bot，卡片链接到它的页面，其后是看板，再后是按类别分组并显示本地计划的想法，底部是普通输入框。点击想法只会填入该输入框而不发送，方便先修改；账户还没有 Bot 时，想法上方显示空状态。`/bots/<id>` 是单个 Bot 的页面：固定的卡片显示名称、计划、立即执行或停止、暂停，以及包含删除的选项菜单，其后是下次执行、上次结果、任务和执行记录，再后是始终展开的高级卡片，包含重叠策略、已保存的批准、GitHub 和 webhook 触发器以及运行位置。它的输入框提示“修改这个Bot…”：从这里发送的第一条消息以 `avn-bot` 提及标明该 Bot，已发送的气泡把它显示为 Bot 标签，因此只需输入要修改的内容。`/bots/runs` 列出所有 Bot 的执行记录，支持重试、移除单条记录和清除已结束的记录，没有输入框。每条执行记录都链接到该次执行的对话，结果保存在对话中。删除 Bot、移除单条执行记录、清除执行记录、重试失败的执行，以及更换或移除 webhook 密钥，都会先在本页自己的对话框中确认。所有创建和修改仍需经过对话本身的批准。读取邮件、日历或 GitHub 的模板在当前账户没有该组已连接且已启用的连接器时显示连接操作，点击会在设置中打开对应连接器。这些页面使用与对话相同的已认证连接，不在浏览器中存储权威计划。

## 模型体验

### Bot 页面第一条消息中的 Bot 提及

#### 模型看到的内容

从 Bot 页面发送的第一条消息以 `@[<Bot 名称>](avn-bot:<Bot ID>)` 开头，后接读者输入的内容，模型由此得知修改针对哪个 Bot，并把该 ID 传给 `automation_update`。推荐模板只填入一份本地化草稿，在用户提交之前不会发送任何内容；这些页面不注册任何工具与提示词段落。

#### Token 影响

该提及只为这一条用户消息增加少量 token；不增加工具 schema、工具结果或按轮次变化的上下文。

#### KV Cache 影响

该提及是已记录用户消息的一部分，像普通输入一样进入对话，不改变可复用的提示词前缀。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与延期工作

页面可见历史每五秒刷新一次。在 Bot 页面上不经对话直接修改名称或计划仍待实现。已连接账户列表只显示原始连接器 ID，因此 Bot 页面不展示它。

- **不变量省略** —— 不发布运行时不变量伴随模块，因为此页面不拥有持久状态：它展示的每个自动任务事实都来自 `automation-control` RPC，页面只保留当前地址、读者自己的输入草稿以及每五秒的历史刷新。
