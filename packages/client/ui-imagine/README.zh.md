# @aeven/client-ui-imagine

[English](README.md) | 中文

## 概要

Imagine 是对话的启动地址 `/imagine`。插件在工作区的启动地址面上声明该地址；当它就是当前地址时，对话在空白 Session 的 Hero 位置显示本插件的灵感提示网格，常驻输入框位于该栏底部。选择一条提示会把它填入输入框；发送它就是一条普通的首条消息，之后由 `generate_image` 生成图片。侧边栏的 Imagine 行用于打开 `/imagine`。

网格按展示顺序排列灵感提示：先是 Instagram 原创，接着是 Instagram 优化，然后是航拍视角，最后是各个插画式创意。每条提示的卡片显示它从 Web 应用 `imagine-prompts/` 资源中随附的示例图；资源缺失或加载失败的卡片退化为仅有标题的卡片。点击卡片会打开该提示的弹窗：示例图——编辑照片的提示显示原图与结果并列，自创画面的提示则显示一张引导图——旁边是它的标题、带“展开更多”开关的一行说明、会标出像素尺寸的画面比例选项、在提示编辑照片时才出现的照片选择区，以及输入框将收到的完整消息，其上方带复制控件。

航拍视角是第二张编辑类卡片，与精修刻意相反。它的提示词只有一个要求——把同一个地点与同一个主体重新拍成真正的高空航拍照片——外加两条护栏：不是插画、不是地图，也不是微缩模型或移轴效果。没有工艺段落，因此光线、颗粒与质感都交给模型；卡片上的示例对照图就是它的验证：如此短的提示词是否仍然交付，而措辞写的是“地面或地板”而不是只写地面，因此厨房这类室内照片与泳池露台同样成立。

Instagram 原创每次打开都会自创画面。弹窗从十六个场景中抽取一个——光泽感十足的影棚色块、影棚肖像、街头迈步、黄金时刻的天台派对、霓虹小巷、镜面球舞池、落日冲浪、厨师的火焰、俯瞰的地中海海湾、海景早餐露台、赭黄老城小巷、青绿高山湖、黄昏沙丘、云海之上的攀登者、夜晚甜品柜台、闪光灯下的花束——再从六种色彩与质感中抽取一种，二者一起落入字典中固定的工艺段落：有意图的光照与清晰的高光、高光与暗部都留住细节、焦点锐利且背后有真实景深、细腻颗粒、干净的图形留白，以及同样的排除项。色彩始终饱和、绝不灰淡——池子就是为此写的：只有自带色彩、光线或鲜明图形想法的场景才会被收进来。`换一个` 会把场景池向前走一步，因此连续点击不会重复同一个场景；提示词预览始终显示将要发送的场景、色彩与尺寸。没有任何东西交给模型去发挥：随机性发生在读者能读到、也能修改的地方。

`Try it` 会把该消息写入输入框，并把所选照片登记为这份草稿的图片；它从不直接发送，因此读者可以像其他消息一样编辑并发送。照片通过对话输入的 `addImageFiles` 登记——与输入框自带附件控件使用同一入口——因此媒体类型、每条消息上限与预览 URL 的归属都留在 ui-conversation，被拒绝时弹窗内显示原因且不写入任何内容。编辑所供照片的提示在没有选择照片时仍保持 `Try it` 可用：它的消息中带有一句索要照片的话，因此读者既可以在弹窗里选照片，也可以在输入框里附上。

画面比例的选择以 `WIDTHxHEIGHT` 尺寸行的形式随该消息抵达模型，因为 Aeven 图片提供方不接受比例字段，而把 `size` 传给 `generate_image` 的正是模型。`自动` 不写尺寸，把画面交给模型与所供照片决定。尺寸属 2K 档——2048x2048、1638x2048、1152x2048、2730x1536——按 Instagram 自身的导出尺寸放大，使缩放后细节仍在。

同一插件把 `/image-model` 选择器挂载在对话输入框的宿主命令上：一份可搜索的部署图像模型列表，已存储的选择标记为当前项，选中后会提交 `/image-model <provider>/<model>`，也就是存储该选择的那一行。列表行由部署配置的 `choices`，加上 `listedProviders` 中 Provider 当前提供的模型组成，分别读取本客户端的 `media` 设置作用域与 Seam 自身的目录。在 Imagine 自身还没有模型控件之前，这是选择图像模型的入口；该选择属于部署的图像生成设置，因此与 `generate_image` 共用，而非本页面私有。`/video-model` 在 `media-video` 设置作用域上提供同样的选择器；其列表行只有该文档的 `choices`，因为没有列出的 Provider 提供视频模型。

对话中的图片生成由 `ImageToolView` 在工具调用位置渲染，注册的工具为 `generate_image`、`codex_image_generate`、`codex_image_edit` 和 `grok_imagine_image`。每个图片框左下角有一个圆形提示词控件：悬停时自述名称，点击后在与连接器技能弹窗相同的对话框中打开提示词，标题行带一键复制。调用运行期间该控件位于加载标记之上，失败框中同样保留。成功使用共享附件图库；失败时同一预留框保持空白，错误信息藏在框左上角承载 lucide `circle-alert` 字形的圆形告警控件之后，在与提示词相同的对话框中打开。框就是图片显示时所处的盒子，调用运行中已按请求自身给出的形状取框——参数中的 `WIDTHxHEIGHT` 尺寸或 `W:H` 宽高比——因此占位内容覆盖的正是图片随后填充的那一个盒子；请求未给出形状（分辨率档位、`auto` 或未指定尺寸）时，先按横图取框，直到图片到达。一次请求多张图片时，每张各预留一个框。这些调用在过程折叠时仍可见，包括嵌套代码派发；不新增进度事件或独立图片存储。`VideoToolView` 注册于 `generate_video`，渲染同样的框：任务运行期间是按请求宽高比显示的框上的加载标记，随后是由 `VideoPlayer` 自带播放控件承载的内联成片，从 `/api/attachment-file` 读取结果所引用的成片，元数据加载后框采用成片自身的形状。该控件栏属于产品自身而非浏览器：白色平面圆盘承载 lucide 的 `play` 字形、已播与总时长读数、进度条、`volume-2`/`volume-x` 圆盘及其音量滑杆、由竖排省略号圆盘打开的保存弹层（其 `download` 行按成片自身文件名下载，卡片与单元格沿用作曲器的弹层配方），以及全屏用的 `maximize-2`/`minimize-2` 圆盘。每个控件都是承载产品黑色字形的白色表面，全部外观由成片自身的事件驱动，全屏取在播放器元素上，因此控件始终随成片；播放中的成片在指针离开一段时间后收起控件栏，指针回到成片或暂停时立即恢复。其提示词控件位于左上角，避开控件栏；失败框中该位置留给告警控件，提示词控件退回左下角。

## 模型体验

无，因为本包不注册任何工具、schema 或提示词段落，而它写入输入框的灵感提示文字是读者自己的消息，该消息归对话所有。

#### KV Cache effect

无；本页不发送请求。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

- **只有三张卡片随附示例图** —— Instagram 原创、Instagram 优化与航拍视角；各插画式提示在资源落入 `apps/web/public/imagine-prompts/` 之前只显示标题。
- **自创画面的抽取不可复现** —— 场景与调性在弹窗打开时抽取，因此重新打开或点击换一个都会组出不同的消息；没有任何地方记录读者发出的是哪一次抽取。
- **比例选择以消息文本的形式传递** —— 尺寸行只在模型遵循它的范围内生效；没有任何机制把尺寸钉在生成本身，因为 Aeven 图片提供方接受的是 `WIDTHxHEIGHT` 尺寸而非比例。
- **精修提示并不强制要求照片** —— 没有选择照片时 `Try it` 仍可用，消息会索要照片，因此未附照片就发送的读者先得到的是这个问题而不是图片。
- **选择器的列表行重述宿主的选项列表** —— 本插件合并设置中的 choices 与已列出 Provider 的目录，因为该目录会随订阅的登录状态变化；宿主在提交行抵达时重新解析同样的两个来源，并拒绝之外的任何内容，因此宿主不再提供的行会以该命令的错误呈现。
