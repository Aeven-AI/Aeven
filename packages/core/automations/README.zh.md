# @aeven/automations

## 摘要

自动任务在新的 Aeven 对话中执行已确认的工作。Web 和桌面组合默认包含此服务。用户通过普通输入框创建和调整任务；`/automations` 页面展示计划和结果。任务定义属于创建账户；每次执行保留已批准的任务版本、执行设置和结果。

## 执行

一次性、间隔、每日及指定星期的计划可设置结束时间，且使用明确的 IANA 时区。间隔至少为五分钟。日期计算代码依据 MIT 许可改编自 [titanwings/dsh-automation](https://github.com/titanwings/dsh-automation/tree/0d73a4e03639d4f63d0771ae4490e2718b7e7aa0/src)；附带的 LICENSE 保留署名。夏令时转换中不存在的本地时间会被跳过。服务在启动智能体之前持久记录执行，并跳过重叠的工作。Host 延迟运行时仅考虑最近一次计划执行；若该次执行超过配置的宽限时间，则记录为已跳过。重启后，被中断的排队或运行记录标记为失败，绝不自动重放。

Host 使用现有的账户身份、智能体预设、模型选择、工作区、连接器和凭据服务。每次执行拥有独立会话和明确的插件来源。执行结束要求持久记录的轮次正常完成，但不能证明预期工作或外部操作成功。用户明确确认后才记录已验证结果。主动重试基于原始已批准任务创建关联执行，且同一任务有活跃执行时禁止重试。通过智能体工具创建或扩大任务需要批准。外部连接器写入仍受批准机制约束，无人值守执行不能回答这些请求。文件可以按照已确认的权限选项读取或编辑。

## 配置

组合配置提供 `maxConcurrentRuns`、`runTimeoutMinutes`、`misfireGraceMinutes` 和 `historyLimit`。内置 Web 配置允许两个并发执行，超时六十分钟，补执行宽限十五分钟，每个账户最多保留两百条已结束记录。服务总是保留排队及运行记录，并独立保留计划执行的接纳水位。任务定义和执行记录使用现有的 storage-domain 提供者，无需独立调度进程或数据库。账户可主动清除已结束的历史记录，排队及运行记录始终保留。

## 模型体验

根对话获得 `automation_create`、`automation_list`、`automation_update`、`automation_run_now`、`automation_retry` 和 `automation_confirm_result`。工具模式形成稳定的模型请求前缀，规范 JSON 结果追加到普通工具历史。每次执行以保存的任务、计划执行身份及验证指令开始，并记录为 `automations` 插件通知。它不继承源对话历史或批准授权。每次执行使用已保存的提供者和模型选择。

## 已知限制和后续工作

提供服务的 Host 必须运行，电脑必须保持唤醒。托管执行、操作系统启动管理、事件触发、混合交接、通知投递及持久批准续执行尚未实现。需要交互式外部写入批准的任务会拒绝执行；它们可准备文件，但无法绕过批准。版本 2 的存储域拒绝版本 1 数据。计划支持包含边界的结束时间；暂不支持每月、每年、自定义规则或限制时段的每小时计划。管理和调度读取相同的持久记录，因此服务没有独立的不变量安装器。
