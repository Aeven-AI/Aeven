# @aeven/sync-yjs

[English](README.md) | 中文

## 概述

`ctx.sync` 的提供方。每个账户在 `accounts/<hash>/sync/sync.db` 中保存设备 id、账户密钥及其持有方、文档更新、发件箱和重放计数器，并在持有中转服务器接受的凭据期间保持一条中转连接：该账户已登录的客户端在本 Host 出示的访问令牌，或第一条这样的连接取得的同步授权。中转服务器把授权绑定到那次登录，因此连接会一直保持到用户退出登录；被中转服务器拒绝的访问令牌不会再次出示，没有可用凭据时状态带有 `error: 'sign-in'`，直到有客户端重新登录。帧按中转顺序应用；文档在本地压缩并生成快照，以便中转服务器裁剪已覆盖的更新；未确认的帧保留在发件箱中。中转服务器暂时拒绝时，连接会关闭，发布通过已配置的重连循环恢复；其他拒绝会显示为上传失败。本地网络上互相连接的两台设备直接交换文档更新和流批次，因此中转服务器不可达时，正在流出的会话仍会到达另一台设备。设备通过 mDNS 互相发现；每台未设置 `keepConnected` 的设备还会在每次存在标记时，把自己的私有和 Tailscale IPv4 地址写入其设备条目；设备会拨打在 `routeWindowMs` 内打过标记的设备的这些地址，因此在丢弃组播的网络、跨子网和跨 tailnet 时也能建立连接。握手证明账户密钥，且只接受来自回环、私有、链路本地和 tailnet 地址的连接。设置了 `keepConnected` 的设备会在账户的设备列表中把自己标记为始终在线，会话同步据此把对话留在它上面；其他设备每隔 `presenceMs` 打一次 `seenAt` 标记，并在正常关闭时把自己标记为 `offline`，最多等待 `leaveMs` 让该标记到达中转服务器，因此始终在线设备会立即停止向它发送对话。relay 连接每隔 `heartbeatMs`（60 秒）发送一次 ping，使 NAT 或强制门户网关不会遗忘它；若在 `silenceTimeoutMs`（300 秒）内没有收到任何内容（包括 relay 自己的 ping）就重新连接；relay 至少每 120 秒 ping 一次空闲连接，而排在慢速上传之后的 ping 从不单独作出判断。配置：`relayUrl`、`credentialRef`、`deviceName`、`reconnectMs`、`connectTimeoutMs`、`heartbeatMs`、`silenceTimeoutMs`、`compactAfter` 和 `snapshotAfter`。见[账户同步分组](../README.zh.md)。

尚未取得账户密钥的设备（包括等待通行密钥解锁的设备，以及等待用户接受中转服务器收回的密钥的设备）保持 `starting` 状态；`connecting`、`online` 和 `offline` 状态允许打开本地文档。

状态区分中转连接已建立与下载追赶已完成。追赶失败后从持久化游标重连。上传队列操作复用预编译的 SQLite 语句，接收批次对更新分组时不会为每一帧复制该文档已累计的更新。

发送方计数器只增不减：每个计数器比已存储的计数器大一，且不低于以微秒计的当前时间；丢弃账户密钥时保留计数器，因此已存储计数器重新开始的设备不会被账户的其他设备当作重放旧帧而拒绝。每个存储在追赶完成后执行一次：设备在同步 worker 上把它写过的每个文档与中转服务器的副本（`docs.get`）比较，并把其他设备从未收到的结构和删除作为一条更新发布；中转服务器会删除被后续快照覆盖的帧，因此本设备的副本可能是唯一剩下的副本。不支持 `docs.get` 的中转服务器会让比较留到之后的连接。

收到的帧即使计数器不高于该发送方已见过的最高计数器，只要带有已存储副本缺少的结构，仍会被应用，因此在同一发送方更晚的帧之后才到达的帧（经由本地网络连接或中转积压）不会丢失。更新正在等待一条从未收到的更新的副本不会排队快照，因为快照的 `covers` 会让中转服务器删除携带缺失更新的帧。它会向账户的 `sync/repair` 文档写入请求，写明该文档及每个写入方第一个缺失的时钟，副本完整后删除该请求；存储该文档的每台设备对每个请求只回应一次：以新的计数器把自己存储的完整副本作为一条更新发布，任何版本的设备都会接受；与中转服务器副本的比较可能漏掉请求设备缺少的内容，因为中转服务器可能持有该设备自己声称拥有相同时钟的快照。

## 模型体验

无，因为账户同步在设备之间移动已存储的数据，不向模型请求添加任何内容。导入的对话和记忆只通过原本拥有它们的包到达模型。

无。
