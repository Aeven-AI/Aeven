# Agent Note: 长期记忆路线图

Status: proposed

[English](2026-09-28-long-term-memory-roadmap.md) | 中文

## 问题

agent（智能体）在会话之间忘记一切：用户是谁、某个仓库或应用里什么做法有效、哪些做法失败了。最重要的载荷是技术性的：让某个工具可用的命令、路径、地址、补丁或设置，以及证明它的结果。PR1–5 交付了 `packages/memory/` 家族，以 MemOS 为提供方，并包含按用户的作用域、领域与结果证据（[已实现说明](../../implemented/feature/2026-09-28-long-term-memory-memos.zh.md)）。

对已交付步骤的测试暴露出三个差距，它们塑造了计划的其余部分。MemOS 的相关性过滤器可能静默地把召回降到一次命中；PR6 为自动召回与显式搜索绕过它。技术召回需要工件与结果，但自动召回使用[已存储的摘要](../../implemented/feature/2026-10-01-memory-summary-recall.zh.md)；显式检索保留详细记录。一个会话只有在由已登录请求创建时才有记忆，这就排除了单次运行与 headless 的 CLI 运行、SDK、webhook 入口、ACP 自动化以及所有外部 agent。

余下的步骤必须让 Aeven 继续作为知识与已学流程的所有者，而 MemOS 仍是可替换的记忆引擎。现有 skill（技能）目录已经能发布摘要并按需加载完整指令，因此已学能力应当加入那条路径，而不是另建一个面向模型的加载器。

## 提案

按下述顺序构建其余部分。每一步是一个 PR，由 `pnpm run typecheck`、`pnpm run build` 与对运行中应用的浏览器测试验证；这一系列不运行单元测试。Aeven 拥有持久知识与能力记录、面向模型的上下文以及晋级决策。MemOS 提供记忆候选与学习信号；`ctx.skills` 为可执行指令提供现有目录与加载器。只有当某项具体的服务与消费方需要时，才新增包。

| # | 步骤 | 范围 |
|---|---|---|
| 1 | 记忆 API | `ctx.memory` 的 Service Definition、作用域、召回、捕获、读取。已交付。 |
| 2a | MemOS 提供方 | `@aeven/memory-memos`：进程内 `MemoryCore`、本地 SQLite 与嵌入、经 `ctx.llm` 的辅助 LLM 调用、输出语言规则。已交付。 |
| 3 | 生命周期集成 | `@aeven/memory-context` 在每个直接用户轮次前召回，并在 `turn/end` 捕获；`@aeven/tool-memory` 工具。已交付。 |
| 2c | 按用户记忆 | 在由已登录请求创建的每个会话上记录所属账户，并按该账户限定所有记忆。没有已知所有者的会话不获得记忆。已交付。 |
| 2b | 记忆操作 | `ctx.memory` 上的列出、读取、记住、编辑、遗忘与反馈；来自 `message-feedback` 的每条消息评分喂给提供方。已交付。 |
| 4 | 记忆领域 | person、experience、world 与 project 作用域，项目记忆以工作区为键。已交付。 |
| 5 | 结果捕获 | 从已记录事实推导重试、验证、纠正与目标完成，使一项技巧能与证明它的结果一同被召回。已交付。 |
| 6 | Aeven Context Builder | 让自动召回与显式召回可靠；从现有服务组装有界、带来源标签的技术知识与个人上下文。已实现并经浏览器验证。 |
| 7 | 能力学习 | 从明确请求与可复用的任务证据创建 Aeven 拥有的能力候选；通过 `ctx.skills` 发布已批准的可执行指令。已交付（[说明](../../implemented/feature/2026-09-29-capability-learning.zh.md)）；来自已记录证据的提案仍待完成。 |
| 8 | 能力生命周期 | 跟踪版本、执行、验证、基于证据的状态、降级与退役。已交付（[说明](../../implemented/feature/2026-09-29-capability-lifecycle.zh.md)）。 |
| 9 | Aeven 学到了什么 | 已交付：Settings → Memory（`api-memory-manager` + `client-ui-settings-memory`），含 About you、Projects、Knowledge 与 Capabilities 标签页以及 View、Correct 与 Forget 操作。 |
| 10 | Aeven Layer 可移植性 | 同步按所有者限定的逻辑知识与能力记录；原始执行轨迹默认留在本地。 |
| 11 | GUI 之外的记忆 | 决定哪些入口拥有会话：单次运行与 headless 的 `avn` 运行、SDK、webhook 入口、ACP 自动化与外部 agent。每个入口要么获得一个已配置的所有者，要么被记录为无记忆。 |
| 12 | 能力组合 | 让一项能力调用另一项，并在一次已验证的执行之后提出复合候选。 |
| 13 | 组织作用域 | 稍后：团队与组织所有权、评审、分发与主权部署。 |

### PR6：Aeven Context Builder

1. **让召回可靠。** MemOS 把它的相关性过滤器限制在两秒，并可能回退到一次命中；轻量模式即使 `retrieval.llmFilterEnabled` 为 false 也强制开启该过滤器。自动召回与显式 `memory_search` 通过 MemOS 的轮次开始路径请求未经过滤的候选。两者都在各自配置的截止时间内包含轨迹读取；显式搜索保留它按层配置的上限。
2. **组装彼此不同的来源，而不复制会话。** 使用现有的 `memory-context` 消费方与持久会话事件来框定个人事实、工作区知识、可复用的技术知识与经验或策略。每个来源都有自己的出处，并在总块内拥有自己的条目预算。身份来自会话所有者；近期任务上下文已经来自会话日志。两者都不需要第二份记忆副本。
3. **让工件与结果保持可检索。** 技术轨迹保留已存储的工具输入、输出、助手回答与结果标签。自动轨迹召回提供已存储的摘要与结果标签；显式搜索与读取在工具输出限制内提供细节。助手报告的验证被标识为一份报告，而不是独立证明。[摘要召回决策](../../implemented/feature/2026-10-01-memory-summary-recall.zh.md)负责这一区分。
4. **拥有最终选择。** Aeven 先按摘要相关性对候选排序，再排较长的工具文本；对完全相同的片段去重；限制每个领域；并框定注入的块。`world` 分类器要求可复用的操作或事实，而不是关于 Aeven 自身设计的讨论。带纠正标签的轨迹仍可作为历史搜索，并且在没有记录指称对象时不进入自动召回。一次浏览器检查检索到一条相关的 `world` 轨迹，而临时的纠正指令留在自动块之外。

PR6 不新增空的 `aeven-layer/` 包，也不新增占位的 capability 分区。现有 skill 目录已经提供渐进式披露；PR7 可以通过它让已批准的已学能力可用。每个新的模型可见条目都必须能从会话日志重建。

### PR7–8：学习与证据

每项能力步骤都遵守三条规则。**复杂的学习，简单的执行：** 可执行产物是一个 agentskills 的 `SKILL.md` 加配套文件，Aeven 元数据放在旁边。**立即记住，逐步信任：** 学到的任何东西都立刻作为候选保留；确认使它可执行，证据决定信任，而从不决定它是否被记住。**执行从不依赖记忆：** 能力存放在 Aeven 的注册表中，记忆提供方只帮忙找到它们并提出它们。

PR7 创建一个由 Aeven 拥有的持久 `CapabilityCandidate`，包含意图、描述、流程、所需工具与权限、作用域、配套工件、验证与恢复说明、出处与证据。“learn this workflow”这样的直接请求是强信号；反复发现、先重试后成功、纠正以及对现有流程的修改也可以提出候选。自动提案在可被调用之前需要评审。可执行表示是对现有 skill 服务的适配器，而不是源记录。在最终确定这个 PR 之前，先考察 Hermes 的显式捕获与配套工件流程，同时保留 Aeven 的审批与出处规则。

PR8 把每项能力版本与执行记录关联起来：模型、环境、时间戳、工具、重试、纠正、验证结果、结果，以及测量到的 token 或金钱成本。状态依据证据在 candidate、learned、trusted、needs-validation、degraded 与 retired 之间移动；应用或环境变更可能要求在重用之前先验证。仅有模型生成的置信度数字永远不能提升一项能力。只有在任务可比、成本已测量时，才比较前后运行。

### PR9–13：产品与触达

PR9 呈现“About you”“Spaces”与“Learned capabilities”，带状态、出处、使用历史以及 View、Correct 与 Forget 操作。MemOS Viewer 仍是开发期的临时手段。PR10 同步按所有者限定的逻辑知识、能力版本、策略、纠正、空间与选定的环境元数据；原始本地工具轨迹默认不同步。PR11 在声称记忆能在已登录 GUI 之外工作之前，先为 CLI、SDK、webhook、ACP 与外部 agent 会话解决所有权问题。PR12 在单项能力的执行与验证存在之后增加能力组合。PR13 引入带独立权限与审批规则的团队与组织作用域；不要在 PR6 中实现这些作用域。

### 技术知识是一等载荷

- 值得保留的记忆是关于工具、应用与环境的可复用实践：`world` 与 `experience` 领域。
- 一项可复用的技巧需要把它的工件与结果存在一起。自动召回呈现它的摘要；显式检索提供可操作的细节，第 5 步记录它是否成功。
- 召回必须先可靠，再谈聪明。漏掉一条个人事实的代价是一个问题；漏掉一项技巧的代价是需要它的那个会话。
- 只有后续轮次会重用的材料才属于记忆。关于 Aeven 自身设计的评论不属于。

### 每一步的产品规则

- 记忆属于一个已登录账户。没有任何东西跨账户召回、列出或同步记忆。
- 一个会话只有在由已登录请求创建时才有记忆。由 CLI、SDK、webhook 入口、ACP 或外部 agent 打开的会话没有所有者，直到第 11 步另有决定。
- 任何面向用户或面向模型的东西都不带 MemOS 品牌：工具名、提示词、召回的上下文、UI 文案、标题、标志与设置都是 Aeven 的。内部包名与 MIT 许可证声明可以提到 MemOS。
- 位于回环端口上的 MemOS Viewer 是第 9 步之前的临时手段。

## 考虑过的替代方案

**为已学能力另建一个面向模型的加载器。** 已否决：现有 skill（技能）目录已经能发布摘要并按需加载完整指令，因此已学能力加入 `ctx.skills`，而不是另开一条并行路径。

**为身份与近期上下文另存一份记忆副本。** 已否决：身份来自会话所有者，近期任务上下文已经来自会话日志，两者都不需要自己的存储。

**在 PR6 中新增空的 `aeven-layer/` 包或占位的 capability 分区。** 已否决：只有当某项具体的服务与消费方需要时，才新增包；占位会宣称一项还没有消费方的工作。

**由模型置信度数字，或直接由自动提案提升一项能力。** 已否决：由已记录执行产生的证据决定信任，仅有模型的置信度永远不能提升一项能力，而自动提案只有经过评审才可被调用。

**把已学流程只保留为可执行产物。** 已否决：可执行表示是对现有 skill 服务的适配器，而 Aeven 拥有的能力记录始终是源记录。

## 验收标准

- 每一步作为一个 PR 交付，由 `pnpm run typecheck`、`pnpm run build` 与对运行中应用的浏览器测试验证；这一系列不运行单元测试。
- 记忆属于一个已登录账户：没有任何东西跨账户召回、列出或同步记忆，且一个会话只有在由已登录请求创建时才有记忆。
- 任何面向用户或面向模型的东西都不带 MemOS 品牌，且每个新的模型可见条目都能从会话日志重建。
- 召回必须先可靠，再谈聪明：显式搜索返回已存储的细节，自动召回呈现已存储的摘要以及与之相伴的结果标签。
- 一项能力在没有记忆提供方时也能运行，而应用或环境变更可能要求在重用之前先验证。

## 风险

- 召回预算与过滤器上限是两件事：MemOS 取它自己 2 秒上限与剩余召回时间中的较小者，因此 `recallTimeoutMs` 无法为相关性过滤器买到超过两秒的时间。
- 捕获每个轮次只分配一个领域，因此把技术事实与对它的讨论混在一起的一个轮次会落到单一领域，而该分类是唯一把对话挡在 `world` 之外的东西。
- 在按用户作用域之前创建的会话没有所有者，也不会被迁移：本说明写作时磁盘上 230 个会话中的 222 个，其中包括第一个端到端控制 Ableton Live 的会话。只有在某个有所有者的会话中再次陈述之后，它们的内容才作为记忆存在。
- 只有当 Aeven 拥有持久知识与能力记录、面向模型的上下文以及晋级决策时，MemOS 才保持可替换；任何把这些交给提供方的步骤都会放弃这一点。

## 后果

- 按用户作用域（2c）改变的是会话创建，而不只是记忆包，因此会话也获得一个所属账户。
- 在 2c 之前创建的会话没有所有者，并留在一个没有任何账户读取的 preset profile 中：本说明写作时磁盘上 230 个会话中的 222 个，其中包括第一个端到端控制 Ableton Live 的会话。没有任何东西会迁移它们；只有在某个有所有者的会话中再次陈述之后，它们的内容才作为记忆存在。
- 召回预算与过滤器上限是两件事。MemOS 取它自己 2 秒上限与剩余召回时间中的较小者，因此 `recallTimeoutMs` 无法为过滤器买到超过两秒的时间。
- 捕获每个轮次只分配一个领域，因此把技术事实与对它的讨论混在一起的一个轮次会落到单一领域，而分类是唯一把对话挡在 `world` 之外的东西。
