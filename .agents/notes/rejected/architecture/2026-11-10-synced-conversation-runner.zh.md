# Agent Note：由哪台设备运行同步对话

Status: rejected — 第 1、2 阶段已作为 synced-conversation-home 记录交付；第 3–5 阶段（无窗口运行的桌面设备、默认远程、文件夹会话路由）因超出问题所需而放弃。

[English](2026-11-10-synced-conversation-runner.md) | 中文

## 问题

同步账户的对话没有固定的归属设备。回合运行期间，其他设备把输入转发给正在运行它的设备；对话一旦空闲，用户在哪台设备上输入，哪台设备就会认领它并运行下一回合（`packages/api/session-controller/src/commands.ts` 中的 `claimRunnerAccount`，`packages/session/session-sync/src/mirror.ts` 中的 `runnerOf`）。这条规则会在两个方向上丢失工作。

2026-11-10，一个托管对话在 Aeven Cloud 的账户文件夹中克隆了仓库并启动了 `pnpm install`。用户在 Mac 桌面应用中输入的下一条消息在 Mac 上运行，而那里既没有克隆的仓库也没有该后台任务，因此停止安装的请求无法到达它。文件、后台任务和沙箱状态都留在创建它们的设备上，而下一回合却落到了另一台设备上。

在另一个方向上，从网页开始的对话总是在 Aeven Cloud 的监狱中运行，即使用户自己的电脑在线，带着他们的文件夹、工具和电脑操控能力。VS Code 中的 Claude Code 和 Codex 可以从别处在用户的机器上运行回合；Aeven 做不到。

## 提案

对话留在最近运行它的设备上（包括 Aeven Cloud），除非用户移动它，或者该设备无法连接。从网页开始的新对话在用户的电脑在线时就在该电脑上运行（"远程"），否则在 Aeven Cloud 中运行。

### 规则

每台设备都基于同一份同步状态执行同一条规则，因此它们无需协调就能达成一致：

1. 有回合正在运行：留在该设备上。
2. 用户通过"在这台电脑上继续"或"在 Aeven Cloud 中继续"移动了对话：由所选设备运行。
3. 还没有任何设备运行过它：一台可连接且能运行它的桌面设备，已设置且可连接时优先主桌面，否则选最近活跃的那台；都没有时，由用户输入所在的设备运行。
4. 最近运行它的设备可连接且能运行它：由该设备运行。
5. 该设备无法连接：对于文件夹会话，选一台拥有该工作区文件夹的桌面设备，主桌面优先，其次最近活跃的；对于没有文件夹的聊天，按同样顺序选一台可连接的桌面设备，否则选 Aeven Cloud。
6. 其他设备都无法连接：由用户输入所在的设备运行。

"能运行它"指：该设备按中继存活判断在线，运行的构建能读取日志中的每种事件类型，允许运行回合，并且对于文件夹会话拥有该工作区的文件夹。

输入从不阻塞。用户输入所在的设备通过同步收件箱转发输入，并等待一小段可配置的时间（约 3 秒）让所选设备接手；无人接手时，规则继续执行第 5 步，然后第 6 步。中继租约和日志折叠已经能防止同一回合运行两次，落后设备写入的批次会被丢弃，其提示会被重新提交。

### 产品决定

- 远程对每个账户默认开启；在下列所有阶段交付之前，不显示设置，也不弹出逐设备授权提示。普通用户永远不会被问到它。
- 转发的输入按桌面设备的常规权限预设运行，与在该桌面上输入的内容相同。
- 运行对话的桌面设备是最近活跃的那台；显式设置的主桌面优先于它。在计划完成之前，主桌面没有界面。
- 界面保持最少，并按需呈现：两个"继续……"操作放在工作区或对话现有的选项菜单中，在计划完成之前不显示其他任何内容。其具体位置和文案（中文、英文、西班牙文）仍需确认。

### 阶段

1. **粘在最近的设备上。** 已实现，见[第 1 阶段的记录](../../implemented/architecture/2026-11-10-synced-conversation-home.zh.md)。第 1、4、6 步，Aeven Cloud 是唯一始终在线的设备。最近在 Aeven Cloud 中运行的对话，在用户于另一台设备上输入时仍在那里运行。当前一回合的文件留在另一台设备上时，模型的运行时上下文会说明。没有界面。这修复了 2026-11-10 的故障。
2. **显式移动。** 第 2 步，通过选项菜单中的两个"继续……"操作，在界面确认之后实现。
3. **没有窗口也能运行的桌面设备。** 没有打开窗口时，桌面设备保持其同步连接（目前 `keepConnected` 只用于托管，见 `packages/sync/sync-yjs/src/index.ts`）。它存储一份按用户的模型凭据，例如按用户 id 存在操作系统钥匙串中的刷新令牌，因为 `llm-aeven` 只在有客户端登录时才持有用户的令牌。每台设备发布在线状态：其类型（桌面或云端）、构建和转发协议版本，以及是否允许运行回合。存活由中继看到套接字来判断，每 10–15 秒一次 ping 和 pong，让休眠的 Mac 不再算作在线，而不是靠同步文档中的心跳。
4. **默认远程。** 对没有文件夹的聊天执行第 3、5 步。本阶段只与其保护措施一同交付：
   - 收件箱条目由存放在操作系统钥匙串中的逐设备密钥签名，桌面设备只运行由同一账户的设备签名的输入。
   - 转发的输入带有其来源设备。
   - 掉线后重新成为首选的桌面设备，要先稳定连接一段时间；Aeven Cloud 接手的空闲对话会保留到该回合结束。
   - 设备在落后期间运行的回合，记录为可见的"X 上的回合已被丢弃"事件，而不是静默地重新提交。
   - 回合产生的文件成为按内容寻址的会话附件，按需同步，因为文件夹本身不会在设备之间移动。
5. **文件夹会话、多台桌面设备、自动化。** 对文件夹会话执行第 5 步，主桌面覆盖，自动化在其现有的逐自动化租约下遵循同一规则，网页上针对文件夹会话的输入转发给拥有该文件夹的桌面设备，而不是弹出"在 Aeven Desktop 中可用"对话框。设置、主桌面以及状态栏（"在 MacBook 上运行"、"电脑离线，在 Aeven Cloud 中运行"）只在本阶段交付时才显示。

## 考虑过的替代方案

现行规则（由用户输入所在的设备接手空闲对话）不需要在线状态或转发，但每当用户换设备时都会让对话离开其文件和任务，如 2026-11-10 那样。

本计划的早期草案提议对每个空闲对话都优先用户的桌面设备，它选择"最近运行它的桌面设备"，只有在没有桌面在线时才回退到 Aeven Cloud。它仍会把 2026-11-10 的消息送到 Mac，因为那个对话最近是在 Aeven Cloud 中运行的。优先最近的设备（不论其类型）保留了新对话对桌面的偏好，又不会出现那个故障。

始终在 Aeven Cloud 中运行最简单也最安全，但放弃了从网页使用用户自己的文件夹、工具和电脑操控。

像 Codex 和 ChatGPT 那样对每台桌面设备弹出一次"允许这台电脑运行网页对话"的提示，作为产品决定被否决：普通用户不能被打扰。设备签名的收件箱条目取代它，并与远程一同交付，而不是之后。

在设备之间共享对话的文件夹被否决，改为对产生的文件使用同步附件：笔记本电脑与监狱之间的双向文件同步会带来冲突和配额问题，附件则可以避免。

## 验收标准

- 桌面应用打开时，在最近于 Aeven Cloud 中运行的对话里于 Mac 上输入的消息在 Aeven Cloud 中运行，并能停止该对话的后台任务（阶段 1）。
- "在这台电脑上继续"把对话移到该桌面设备，下一回合在那里运行；"在 Aeven Cloud 中继续"把它移回去（阶段 2）。
- 所有窗口关闭、桌面应用在后台时，网页上新聊天中的消息在接手等待时间内于桌面设备上按其预设运行；桌面休眠或离线时，经过接手等待后在 Aeven Cloud 中运行，用户无需任何操作（阶段 3–4）。
- 未由该账户设备签名的收件箱条目不会在任何桌面设备上运行（阶段 4）。
- 因设备掉线而中断、并在别处得到回答的回合显示"X 上的回合已被丢弃"事件，其提示只运行一次（阶段 4）。
- 构建无法读取该日志的桌面设备永远不会被选中（阶段 3）。

## 风险

- 远程默认开启且使用桌面的常规预设时，任何接管了用户网页登录的人都可以在该桌面上运行其预设允许的任何内容。设备签名的收件箱条目把这限制在该账户的设备上，仅凭被盗的网页会话并不持有这些设备，但没有逐设备的同意。
- 回合在设备之间移动会改变工具集，每次切换都会使提示缓存失效。
- 被丢弃回合的副作用（例如桌面设备在掉线前写入的文件）会留在该桌面的磁盘上。
- 不稳定的桌面设备可能让对话来回切换；稳定连接等待以及 Aeven Cloud 保留其接手的空闲对话是防护措施。
- 桌面上存储的模型凭据是一个新的静态秘密。
- Aeven Cloud 持续从 `main` 部署，而桌面设备会落后，因此版本差异是常态；会拒绝该日志的桌面设备不能被选中。
