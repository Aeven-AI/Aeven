# Agent Note: 浅色方案是一条七级中性色阶

Status: implemented

[English](2026-10-19-light-scheme-neutral-ramp.md) | 中文

## 问题

`aeven-language.css` 逐个别名覆盖上游平台调色板，每个覆盖都写自己的十六进制值。结果是浅色方案里约有二十种不同的中性色：三个几乎相同的近黑文字色（`rgb(50, 50, 50)`、`rgb(80, 80, 80)`、`rgb(90, 90, 90)`），一个说明文字色，一个禁用色，三个相差七级以内的白（`#fff`、`rgb(242, 242, 242)`、`rgb(235, 235, 235)`、`#e6e6e6`），行内代码的底色和它自己的字面色（`#737373`），一组从冷色上游色阶原样继承的滚动条颜色，以及半打 Aeven 层从未调暖的冷灰色别名。

没有任何机制阻止下一个 token 再加一个近黑或一个偏白。若干没有任何样式表读取的别名仍然带着值，而在主题生效之前就绘制的表面——启动页、markdown 引擎、随仓库携带的登录与账户样式表——各自维护着一套自己的中性色阶。

## 决策

### 七个级差，只声明一次

[Aeven 视觉语言](../process/2026-09-03-aeven-web-visual-language.zh.md)规定由哪一层持有这些值；本文规定浅色方案可以持有多少个。`aeven-language.css` 的浅色块以七个中性级差开头：`--dsw-aeven-ink`、`--dsw-aeven-ink-muted`、`--dsw-aeven-ink-faint`、`--dsw-aeven-ink-disabled`、`--dsw-aeven-surface`、`--dsw-aeven-well`、`--dsw-aeven-raised`。浅色方案中的每个别名都解析到其中之一，没有别名写自己的中性字面值。半透明着色与状态混色保留自己的值，因为它们表示某个级差的百分比，而受支持的浏览器下限无法从 token 计算出它。

近似的颜色被合并：两个较浅的文字色成为 muted 级差，主按钮的悬停色成为 muted 级差，行内代码底色成为 raised 级差，行内代码的文字色成为 token（`--dsw-alias-markdown-inline-code-text`），读取 muted 级差而不再是字面值。消息区强制为黑的那几行现在读取色阶，不再重复写 `rgb(0, 0, 0)`。

### 滚动条要么存在，要么不存在

凡是引擎仍绘制滚动条的场合，滑块静止时停在 raised 级差，指针悬停时到达 disabled 级差，轨道保持透明。因此浅色方案自己声明滚动条别名，不再继承冷色阶的 `rgb(229, 229, 229)` 与 `rgb(212, 212, 212)`。深色方案保留上游值：它的滑块在 `rgb(60, 60, 61)`，轨道本来就是透明的。

### 主题之外的表面读取同一组级差

启动页、markdown 引擎的 `--hm-*` 调色板、语法高亮的注释与标点色、JSON 树与悬浮卡片的金属件、上传磁贴与灯箱，以及随仓库携带的登录与账户样式表，各自重复声明了灰色。现在它们都写七个级差值之一，或其中一个的 alpha：启动页的冷色 `#0f1115`、`#61666b`、`#81858c` 变成 ink、muted、faint；引擎的 `rgb(160, 160, 160)`、`rgb(105, 105, 105)`、`rgb(102, 102, 102)` 变成 faint 与 muted；登录样式表的 `#111`、`#333`、`#868e96`、`rgb(90, 90, 90)`、`rgb(100, 100, 100)`、`rgb(105, 105, 105)`、`#ddd` 变成 ink 或某个级差。

深色调色板未改动。它是一条独立的反向色阶，合并它是另一个决策。

### 色阶由检查强制，而非写在文档里

`packages/client/ui-theme/tests/aeven-language-styles.client.spec.ts` 按层叠顺序解析浅色方案——两个样式表按挂载顺序、只看浅色 `body` 块、沿 `var()` 链追到字面值——一旦某个 `--dsw-alias-*` 或 `--dsw-specific-*` 值是七个级差之外的不透明中性色，检查即失败。新别名挑一级通过，自己发明一个灰色则不能通过。

## 考虑过的替代方案

- **保留平台别名、直接写入字面值。** 否决：别名列表很长且随上游增长，散落在各处的字面值无法审计；一条色阶把词汇集中在一处，让每个别名成为七选一。
- **从 `design-platform.css` 删掉上游静态色阶。** 否决：超出范围，许多别名和第三方主题覆盖都读那条色阶；由于 Aeven 层覆盖了使用冷色级差的别名，浅色方案已不再暴露它们。
- **同时合并深色调色板。** 此处否决：深色是独立的反向色阶，其级差并非浅色方案的级差；同样的色阶约束可以基于它自己的证据另行处理。
- **删掉消息区强制为黑的那一段，而不是让它读取色阶。** 否决：它承载一个先于色阶存在的产品决定——浅色消息区只使用一种墨色——与那个墨色取自哪一级差无关。

## 影响

- 浅色方案持有的中性色从约二十种降到七种，而且全部集中显示在 `aeven-language.css` 的一个块里；评审者读这份调色板，而不必到处寻找覆盖。
- 原先使用两个较浅文字色的界面元素现在统一深一级；主按钮的悬停落到 muted 级差而不是自己的级差，比过去跳得更明显。
- 静止的滚动条滑块停在 raised 级差，与它所在表面的差别很小；指针悬停时到达 disabled 级差才是它变得可读的原因。需要更明显滚动条的表面自行重绑。
- toast 与 tooltip 表面改用 ink，而不是原来的两种深色块，因此它们与背景的区分只来自层级阴影。
- 行内代码在消息区内保留自己的文字色——那里的正文被强制为 ink。
- 启动页、markdown 引擎、语法配色、随仓库携带的登录与账户样式表，以及原先各自写着灰色的组件局部字面值，现在与它们所处的主题一致。
- 深色调色板保留自己的色阶，因此明暗两套方案不再共用同一组级差数。
