# Agent Note: No scrollbars on the model list or the sidebar session list

Status: implemented

[English](2026-09-12-no-scrollbars-on-the-model-list-and-sidebar.md) | 中文

## Problem

有两个表面绘制着内容始终不配拥有的滚动条：模型选择器的列表——它在搜索框之后排布动辄数百行目录——以及侧栏的会话列表——它在加载少量会话后就会溢出。侧栏的滚动条是[指针揭示式侧栏滚动条](../../archived/feature/2026-08-04-pointer-revealed-sidebar-scrollbars.md)所确立的交互暗示：指针位于该列之上时绘制，离开后隐藏。即便如此，它读起来仍像固定家具：无论滚动条是否绘制，预留的条带都在；行比它们所在的窄一个条带；并且在列内任何位置移动指针都会把它带回来。

## Decision

`ui-theme` 的滚动条样式表拥有一个全局 `.no-scrollbar` 退出类，以类名施加于滚动元素本身。它同时声明两条渲染路径：`::-webkit-scrollbar` 上的 `display: none`（位于该表的闸门之外），以及标准属性一半的 `scrollbar-width: none`（位于闸门之内）——该表内所有 `scrollbar-width` 都由同一个闸门承载，于是每个引擎都通过它实际实现的那条路径隐藏滚动条，而不是让另一条失效。

目前有两个表面退出：popupSelect 外壳的视口（`ui-commands`），即模型列表以及建立在该外壳之上的其他命令选择器；以及工作区浏览器的 `.list`（`ui-workspace`），即侧栏端到端测试所称的该列中唯一的滚动区域。

内嵌的 Aeven 样式表（`ui-auth-aeven/src/vendor/aeven-auth.css`）为它自己的消费方声明了同一个类，并带有 `body` 前缀，且由于认证挂载位于主模块图中而恰好全局加载。主题样式表也声明了它，使该行为由本仓库拥有并受测试，而不是继承自那个导入图；两处写法必须保持一致，而 Markdown 引擎既有的 `no-scrollbar` 调用点如今同样依赖这个类。

这反转了指针揭示式交互暗示，而且这次反转是彻底的：侧栏的会话列表在任何指针状态下都不绘制滚动条，也不预留条带，因此溢出出现时没有可增可减的预留——[预留槽位修复](../bug-fix/2026-07-28-themed-scrollbars-and-reserved-gutter.zh.md)所保护的不变式依然成立，而且如今无需为无人看见的滚动条在每一行上花掉 8px 也能成立。曾经决定该状态的外壳不再跟踪指针：延迟、它的计时器、几何离开监听，以及 `quietBars` 重绑都已移除，留下的是一个自己拥有滚动条处理方式的区域，和一个不再仲裁滚动条的列。

## Alternatives considered

**保留揭示，仅在指针离开时隐藏滚动条**——即已发布的行为。之所以拒绝：它为一个绝大多数时间不可见的滚动条持续预留条带、持续压缩行宽，而揭示式笔记之所以接受这一代价，仅仅因为滚动条会回来。

**把滑块永久重绑为 `transparent`**，即把侧栏自己的机制变为无条件生效。之所以拒绝：它保留了条带——可见效果与隐藏滚动条一致，但那条 8px 的空带仍留在那里，而不是还给行。当必须隐藏滚动条却又不能放弃其占位时，该重绑仍是正确的工具；它不是移除滚动条的工具。

**只依赖内嵌样式表里的类。** 它已全局加载、已被 Markdown 引擎的代码块与表格使用，且不需要任何新 CSS。之所以拒绝将其作为唯一定义：那样该行为就取决于认证分块是否仍在主图中，而 AVN 之内没有任何东西声明或测试它。声明两次是更小的风险，且该重复已在样式表中标注。

**只在模型列表隐藏滚动条**，侧栏保持原设计。之所以拒绝：同样的固定家具在两个表面引发了同样的抱怨，给出不同答案会让侧栏的滚动条再次成为特例。

**在应用内绘制覆盖式滑块**，而不是移除滚动条。按前一篇笔记已给出的理由拒绝：它换来任意样式，代价是命中测试、拖拽、滚轮、惯性以及两套调色板的悬停状态——为一项纯外观收益而拥有大片自有表面。

## Consequences

两份列表滚动时都没有滚动条、也没有条带。侧栏的行宽增加一个条带并抵达面板边缘；模型列表的行在其卡片内同样如此。滚动不受影响——滚轮、触控板、拖选以及外壳的方向键仍能移动两份列表，端到端测试对此加以固定而非假设。

不再有任何读数取决于指针，也没有任何东西在跟踪它：侧栏外壳的指针延迟、其 `quietBars` 状态类以及驱动它们的那两个测试，都随它们所服务的交互暗示一并退役，因此没有留下任何监听、计时器或 DOM 状态类。

其他所有表面的滚动条皮肤保持不变：`--dsw-alias-scrollbar-*` 令牌、`--avn-scrollbar-*` 重绑约定，以及悬浮表面用的成对取值，仍决定谁绘制滑块。只有这两个退出的区域位于其外。

让出的能力是悬停暗示本身：指针位于侧栏之上不再揭示会话列表的终点与可滚动距离。要重新引入它，需从该列表移除退出类，并重建本次改动删除的指针机制及其 `transparent` 重绑。

## Testing

`ui-theme` 的滚动条测试固定该工具类在两条路径上的声明，并保持该表单一闸门的规则完整：该表内每一个 `scrollbar-width`（包括退出类中的那一个）都位于 `@supports` 闸门之内，而伪元素规则位于其外。

`apps/web/tests/sidebar-scrollbar.e2e.ts` 测量真实引擎而非相信声明：列表确实溢出（防空洞断言）、`scrollbar-width` 解析为 `none`、预留条带为 0、首行抵达侧栏边缘且内容区终止于边框盒、列表仍可程序化滚动、无论列表是否溢出这些行的几何都保持不变，并且在指针位于列表之上与远离列表两种情况下读数完全一致。其提交的 golden 记录了两套调色板下的几何与解析样式。

`apps/web/tests/default-model.e2e.ts` 从 composer 的模型按钮出发，在 popupSelect 列表上固定同一退出行为，从打开的 listbox 读取计算后的 `scrollbar-width`。

`ui-sidebar` 的外壳快照固定展开与折叠两态下根元素的类名，退役的状态类正是借此被挡在外面：两处都不出现 `quietBars`。
