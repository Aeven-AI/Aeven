# Agent Note: Generators own both locales of a catalog, and checks scope to the changed packages

Status: implemented

English | [中文](2026-10-26-generated-catalog-locales.zh.md)

## Problem

Two costs dominated documentation work and neither one produced a document.

The first was the bilingual pair for generated catalogs. `gen-config-catalog` and `gen-persistence-catalog` wrote the English file; the Chinese file was a hand-maintained counterpart, translated section by section, then re-recorded with `verify-translation-pairing --write`. Every regeneration re-opened the same work: `来源：` lines, `需要：` lines, a line-number shift in a `Source:` link. The prose in those files is a fixed vocabulary — a title, three intro paragraphs, five labels, two headings — and everything else is identifiers, paths, or verbatim declaration text. Hand-translating a fixed vocabulary once per regeneration, and paying a fail-and-retry cycle when a stale section drifted, was most of the documentation time in a change that touched one plugin.

The second was the check loop. `tsc -b` over the whole solution rebuilds every project whenever its incremental state is gone, and a `pnpm install` that links a new workspace package discards it; a one-line edit cost a cold multi-minute rebuild. The gates and the test suite are corpus-wide for good reasons, but the inner loop does not need the corpus.

## Decision

### The renderer takes a locale, and emits both sides itself

`gen-config-catalog` and `gen-persistence-catalog` now render each side from one `render(entries, locale)` call. `Locale` names exactly the prose a side contributes: banner, language switcher, title, intro paragraphs, label prefixes, section headings, and the two path projections a translated page needs — `.md` page links and the external-type reference form. `LOCALES` is `[EN, ZH]`, both are written in one run, and `--check` fails naming whichever side is stale.

This follows the contract the Cordis subsystem-region generator already had: a generator that owns both sides projects paired document paths to each output locale while keeping every other generated byte equal. Nothing about the pairing contract weakens — both files are still recorded by `verify-translation-pairing`, and the structure signature still catches a side that drifts. What changes is who writes the prose: the generator holds it, once, and a reviewer reads a diff of a fixed vocabulary instead of translating it again.

The generated banners say so on both sides: the file is generated, do not edit it by hand, run the generator again.

### The inner loop maps changed files to their owning packages

`scripts/check-changed.ts` (`pnpm run check:changed`, or `typecheck:changed` / `test:changed` / `docs:changed`) reads the working tree — staged, unstaged, and untracked — maps each path to the nearest enclosing `package.json`, and hands `tsc -b` those packages' project files, vitest those packages' `tests/` directories, and `verify-translation-pairing` the documentation pairs it touched. A change outside every package (`scripts/`, root configs, `docs/`) falls back to the corpus-wide command for that step, because that is where the change's blast radius actually is.

It is a driver, not a gate. `typecheck`, `test`, and `doc-sync` keep their corpus-wide meaning, and CI still runs them.

### Documentation checks cache successful inputs

The aggregate always schedules its gates. A leaf may skip only when its recorded successful fingerprint matches its current inputs, verifier code, and discovered dependencies. `verify-md-links` includes local file and directory targets, so deleting a linked source file invalidates its cache. See [execution efficiency](../bug-fix/2026-10-26-agent-execution-efficiency.md).

## Alternatives considered

**Keep translating by hand and accept the cost.** Rejected: the recurring work is a fixed vocabulary, so it buys nothing, and the failure mode is worse than the cost — a stale Chinese section (a service key the English side had dropped, a `systemPrompt` it had gained) sat in the file because nothing compared the two beyond structure.

**Generate the Chinese side by machine-translating the English at build time.** Rejected: `docs/i18n/README.md` gives both languages equal authority, and a translator model in the build path puts unreviewed prose in a document that a reader is entitled to trust. Holding the prose in the generator is a fixed, reviewable vocabulary; a model call is not.

**Keep one locale and drop the pairing for generated catalogs.** Rejected: generated catalogs are exactly where a reader who cannot read the intro paragraph is worst served, and the paired-path projection is cheap once the renderer takes a locale.

**Make `typecheck` itself scoped.** Rejected: it would quietly weaken the command CI and every reader treats as exhaustive. A separate `check:changed` names what it does.

**A path filter on each gate.** Rejected for now: only the pairing check accepts named pairs, and the other gates answer corpus-level questions (does every package README meet the skeleton; is the module graph current) that a filter would answer only partly. Scoping typecheck, tests, and pairing covers where the time actually went.

## Consequences

- A catalog regeneration is now a one-command, one-diff operation with no translation step. The cost that remains is reading a diff of Chinese prose the generator already held.
- The Chinese catalogs now carry content the hand translation had drifted from; the diff that landed with this note corrects a dropped service key, a stale `subprocess` entry, and shifted source links.
- A generator that owns two locales must place the language switcher after the H1 heading, because the pairing check reads the switcher there. Both generators do, and a locale array makes the next one do it by construction.
- `check:changed` is a convenience with no spec and no CI role; a defect in the mapping surfaces as a fallback to the corpus-wide command, not as a false pass.
- `check:changed` reads the working tree only. A commit already made on another branch is not its input; `check:all` and CI remain the authority for a pushed diff.
