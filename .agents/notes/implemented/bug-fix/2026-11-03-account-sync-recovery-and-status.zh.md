# Agent Note: 账户同步恢复与准确状态

Status: implemented

[English](2026-11-03-account-sync-recovery-and-status.md) | 中文

## Problem

中转服务器的拒绝可能使持久化上传留在队列中，连接仍然打开，却没有再次发布的机会。新设备也可能在应用中转历史之前显示已是最新，因为发出计数无法衡量下载。每个连接周期只读取一次设备列表，会遗漏后来加入的设备。

## Decision

保险库保留未确认的上传。暂时的 `server-error` 或连接关闭会结束发布连接，让提供方已配置的重连循环恢复发布。其他拒绝保留在队列中并暴露上传失败；用户可通过现有的启用操作重试，该操作会重新连接失败的保险库。追赶失败会关闭连接，并从持久化游标恢复。

`catchingUp` 同时涵盖中转追赶和正在应用的接收帧。传输失败会一直可见，直到该传输成功。设置使用低调的图标和现有 Menu 组件显示详情与重试；下载追赶使状态保持同步中，空闲状态省略空计数。“忘记设备”明确说明移除列表条目仍保留访问权限。

`sync/devices` 报告本地设备列表编辑和该文档的远程变化。Remote 仅向所属账户转发设备和状态通知。设置将设备通知合并为一个正在进行的读取和一个待处理的刷新，独立于上传进度。存储复用预编译的上传语句，接收批次向各文档数组追加更新，避免反复复制已累计的更新。

## Alternatives considered

**立即重试所有拒绝：** 永久拒绝的帧会导致密集请求循环。现有重连延迟限制暂时失败的恢复频率，其他拒绝则保留数据并等待另一次尝试。

**每次状态通知都刷新设备：** 上传进度可每秒通知数次，而设备列表并无变化。独立通知避免反复读取文档，同时仍能观察设置页面打开期间加入的设备。

**把在线视为已是最新：** 连接可用并不代表传入历史已应用。下载工作保持为独立的状态事实。

## Consequences

提供方不需要额外的重试计时器或配置。永久拒绝的帧仍留在队列中，可能阻塞后续发布；弹出菜单暴露失败而不删除数据。设备移除仍属于列表管理，而非撤销访问权限，详见[账户同步设计](../../proposed/architecture/2026-10-27-account-sync-network.zh.md#what-ships-today)。

聚焦的提供方、保险库、Remote 和客户端测试覆盖无需再次编辑的已保存上传恢复、追赶被拒绝、下载状态、账户范围通知、设备刷新合并和失败弹出菜单。所有者本地的客户端快照固定英文、中文和西班牙文的下载及空闲文案；设置没有录制会话输入。真实双设备和已部署中转服务器的验证与这些本地夹具分开。
