# Agent Note: 刻度导轨的稳定化恢复了被丢弃的行为

Status: implemented

[English](2026-09-16-tick-rail-stabilization-restores-dropped-behavior.md) | 中文

## 问题

`refactor/simplify-conversation-scroll-ui` 分支用一次「进行中的工作」提交（`ba27d25d4c` 检查点，其提交信息写明：测试、卫生门禁与快照都尚未对其中任何内容运行过）重写了对话滚动区，随后又在它之上重建了轮次导航（`0714950757`、`258477130b`、`ed1eceeab6`）。`packages/client/ui-chat` 与 `packages/api/session-controller` 中共有 29 个 spec 失败，并且回到底部控件抛出三处未处理的 `TypeError: el.scrollTo is not a function`。

这些失败并非同一个缺陷。大多数描述的是该分支有意替换掉的组件的行为：导轨的内部滚动器与渐变淡出、它按标记生成的 `--turn-natural-position` 包装元素、ChatView 自带跳转分页器的 `aria-busy` 标记生命周期、带手动重试控件的停滞闩锁、四屏预取跑道，以及 `loadThrough` 的向后遍历。但其中四项描述的是该分支从未打算丢弃的行为，另有一处 `color-mix()` 取值违反了客户端的 iOS/Safari 14.5 CSS 底线。

## 决策

每个失败都在持有过时陈述的那一侧解决：当有文档记载的重新设计替换了 spec 所断言的机制时改 spec；当重写悄悄丢掉了 spec 仍然陈述的契约时改源码。导轨是以 outline 为输入的刻度阶梯；跳转走事件导航路径；一次失败的跳转仍然落在最近的已渲染行上并标记它。

恢复了四项源码行为，它们各自都被该分支更早的测试所固定：

- **首帧就存在底部标记。** `publishMark` 从挂载时已经存在的行中取得它的「最后一个轮次」取值，因此一个打开后就钉在尾部、并按下尾部的会话会立刻标记最后一个轮次，而不必等待某次行变更。`b10f873d41` 声称做了这项修复；没有这次播种，它自己的测试就是失败的。
- **轮次跳转落在它最早渲染的那一行，或落在对话起点。** `006cf095d9` 让导轨跳转落在该轮次最早的行上，并在该行就是流的第一行时落到滚动原点，使开头的 System prompt 留在视野内。重写后的 `navigateToTurn` 无条件地写入阅读线算式，丢掉了原点这一情形。
- **分页从未到达的跳转仍然让读者落位。** 重写后的兜底完全跳过了轮次目的地，于是导轨标记的是一个流无法显示的轮次。现在兜底对每一种目的地都落在最近的持久行上，标记也跟随实际落位的那一行。
- **挂载到已打开会话的视图只测试一次分页。** 布局效果的打开分支与「已提交窗口」效果都会在挂载提交上运行；现在该效果只负责挂载之后的每一次提交，从而在这个视图首次贴上的那一帧上省下一次布局读取。会话侧的「请求进行中」保护本来就已经把这次重复调用收敛为一次请求；这次改动去掉了重复调用本身。

`Session.loadThrough` 保留它声明的「被取代」契约。在一次锚定读取进行中到达的请求，会以两个目标中更低者加入那一趟；这一趟用再一次锚定读取来服务它，而不是用双侧窗口已经取代的那种遍历——锚定读取在任何距离上代价相同，因此快速连点两次导轨，第二次更深的目的地仍然会落地，而不是无人服务。

`StatsLine` 重新测量自己的行以判断省略号，并且**只在行被裁剪时**在延迟提示气泡中显示整行。那次进行中的提交把它换成了一个裸 `title` 属性，丢掉了裁剪判断和喂给它的观察者；而该提交自述的范围里没有任何一处提到统计行。

导轨未加载刻度的变暗改用 `rgba(10, 10, 10, 0.35)` 陈述其 35% 的静止色。`color-mix()` 是底线会丢弃的值级函数，那会让每个未加载刻度以全强度绘制。

## 备选方案

**恢复被替换掉的组件。** 导轨自带的滚动器、淡出、标记包装元素，以及 ChatView 侧的跳转分页器，都可以重建，从而让旧 spec 原封不动地通过。否决：该分支移除它们各有明确理由——采样到固定条带的阶梯不需要内部滚动器、活动标记跟踪通过 `IntersectionObserver` 不需布局读取、而一条分页器（事件导航路径）已经会为跳转让路——每条理由都在其提交中带有度量，并在一个 35 轮次会话上实机验证过。

**把 `loadThrough` 退回向后遍历。** 否决：一次锚定读取即可到达任意 seq 是该分支的首要成果（在 2 万事件的会话上，遍历是 37 次往返 / 67ms，锚定是 1 次往返 / 5ms），而双侧窗口的 `detached`/`returnToLive` 契约正建立在它之上。

**保留挂载时重复的分页测试，并把两个调用次数 spec 重新基线化。** 否决：有三个 spec 陈述「打开只拉取一次」，这次重复调用是挂载帧上对滚动口的第二次布局读取，而会话侧的保护已经让第二次调用成为空操作——也就是说这个瑕疵毫无支撑价值。

**按同级客户端套件的做法装一个空操作 `scrollTo` stub。** 仅对这个 spec 否决：那些套件断言的是「`scrollTo` 被调用过」，而这些用例断言的是跳转最终落到了哪里。因此这个 stub 执行视图唯一要求的那件事——把请求的偏移量放到元素上——而两个断言位置的用例则点出控件计算出的底部，因为 jsdom 不做夹取。

**让生产代码里的 `scrollTo` 调用变成防御式（`typeof el.scrollTo === 'function'` 加一次 `scrollTop` 写入）。** 否决：`Element.scrollTo` 在所有浏览器中都存在，而只服务于 jsdom 的兜底会掩盖下一个环境缺口，而不是把它陈述在它该在的地方。

**把这些丢失的行为也当作过时的 spec 处理。** 否决：原点落位、最近行兜底、首帧底部标记与被裁剪行的提示气泡都是有自己更早提交与测试的用户可见契约。丢掉它们的重写是需要修复的回归，而不是需要记录的设计。

## 后果

范围内的套件为绿——`packages/client/ui-chat` 359 通过，`packages/api/session-controller` 433 通过——三处未处理的 `scrollTo` 错误消失，因为 jsdom 现在具备了视图所需要的能力，而不是让处理函数抛进 React 的错误路径。`verify-css-baseline` 报告全部 121 个受治理样式表都守住底线。

在持有过时陈述的那一侧修复，代价是这些 spec 失去了它们的旧机制。`chat-view.client.spec.tsx` 中有七个用例被改名，因为它们的标题命名的是该分支已移除的机制（内部滚动器及其淡出、`aria-busy` 生命周期、停滞闩锁、以「屏」计的预取跑道），现在每个用例都以不更少的断言固定替代行为。另有两个 spec 各自新增了一个用例，覆盖超出标记上限后的采样以及始终保留最新轮次。

渲染导轨的 spec 现在会安装 `turnOutline` 投影，因为导轨的输入是宿主的全日志 outline，而不再是已加载窗口。这是该分支的设计，也意味着一个没有 `session-turn-outline` 单元的部署完全不渲染导轨——这是部署事实，不是测试缺口。

当重定向读取在读取过程中到达时，`loadThrough` 现在可能发出第二次锚定读取。其代价是每次重定向一次往返，上限是读者能发出的目标数量；它补上了一个洞：快速的第二次点击此前会被静默地无人服务。

## 测试

`packages/client/ui-chat/tests/chat-view.client.spec.tsx` 固定了：来自 outline 的导轨阶梯、指针到标记的映射、采样步长及其「最新轮次」追加、固定间距样式、跳转的事件导航生命周期（意图已投递、一次分页请求、确认、最近行兜底）、作为标记来源的阅读带、底部规则、轮次跳转的原点落位、挂载时的填空拉取，以及八屏预取跑道。`packages/api/session-controller/tests/session.client.spec.ts` 固定了：针对建模宿主日志的「每个跳转目标一次锚定读取」、重定向的第二次读取、被拒绝且不留下任何目标的跳转，以及在毫无进展的页面上有限的这一趟。`packages/client/ui-chat/tests/chat-stats.client.spec.tsx` 固定了尺寸观察者与被裁剪行的提示气泡。
