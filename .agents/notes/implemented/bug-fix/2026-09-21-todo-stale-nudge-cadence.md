# Agent Note: Cadence and evidence for the todo staleness nudge

Status: implemented

English | [中文](2026-09-21-todo-stale-nudge-cadence.zh.md)

## Problem

A live session's todo dock read `#17 in_progress` for seven minutes after the work that item described had shipped. Between the plan's write at 22:15:47 and its replacement at 22:22:49 the agent finished issue #17 (PR #22 merged, issue closed) and issue #18 (PR #23 merged, issue closed) — 29 tool calls across both — while the dock still showed `#17 in_progress`, `#18 pending`, `#14 pending`. The reader asked twice whether the list was being kept in sync.

The dock was faithful to its input. It renders the `todos` projection, that fold takes the session's last `todo/write`, and the log's last write really did say `#17 in_progress`; the plan was simply no longer true. The mechanism that exists to catch that — the staleness nudge — fired three times inside the window and was believed only on the third. The model's own reasoning records why. The first notice arrived 11 seconds after the model had written the plan, and its first tokens read "The todos are synced — the nudge is automated; #17 IS in_progress which is accurate". The second, at 15 tool calls, drew "Todos are accurate (#17 in progress)" — and at that moment it was: the PR that finished #17 came three calls later. The third, at 27 tool calls, was the first true one, and it was answered immediately ("The todos are stale: #17 is done (PR #22 merged, issue CLOSED), and #18 is in progress …") with a corrected plan written 46 seconds later.

Two properties of the notice produced those two dismissals. Its cadence reset on every write and started at 3 tool calls — about two steps at that session's 1.35 calls per step — so the first challenge landed on a plan the model had just written: 21 of the session's 40 notices came within 4 tool calls of one of its 26 writes, and every write drew one. And the notice text carried no age: `Your todo list still shows 3 of its 9 tasks open.` describes a plan three calls old and a plan forty calls old identically, so the model could not check the premise — only re-derive its own history from the transcript, which it did not do until the third notice. The design that introduced the nudge had both halves: it challenged after 8 steps and every 32 after that, and its text stated the drift (`Your todo list has not changed for <N> steps while …`). A later catch-all commit (`Land the in-flight workspace, layout and provider work`) moved the measure to tool calls with thresholds 3 and 12 and dropped the age clause, tightening the first challenge roughly four-fold while removing the evidence a reader needs to tell a true notice from a false one.

## Decision

One interval governs the notice: `STALE_WORK` = 12 tool calls other than `todo_write` since the last write, applied to the first notice and to every repeat after it (`remindedAt` is null until the first, so the interval runs from the write). The reminder names why it was raised — `Your todo list has not changed for 12 tool calls, while 3 of its 9 tasks are still open.` — and the settlement path, which has no count to quote, states its own reason instead: `Your todo list has not been updated since the background work you started settled, …`.

12 sits inside that session's own write-to-write spacing. Consecutive writes there sat 5 to 19 tool calls apart (median 9) across 26 stretches, so the first challenge lands while the plan is still plausibly the one being worked to, and a stretch as long as the reported window draws a second. It also halves the notice volume for the same session: 50 notices simulated against the 40 logged, with none of them raised on the plan's own write.

The reason clause is what makes a notice checkable, and it is the same information/salience split the package already draws between the read-back and the notice. `has not changed for 24 tool calls` is a claim the model can weigh against the work it has done since it last wrote; the open-count sentence alone is true of a fresh plan and a stale one alike.

## What the dock renders

The stale strip was a stale write, not a stale render, and the reload and navigation paths are why. The browser holds finished per-key values in `ProjectionValueStore` (`packages/api/session-controller/src/client/sessions/projection-store.ts`): a follow-opening baseline seeds each row at the baseline's cut, `{type: 'projection'}` frames update one row each, and a lower-or-equal seq loses. There is no client-side folding of session events and no persisted projection row, so `TodoDock`'s `useProjection('todos')` renders exactly the host value for the cut the client was given — after a reload or a session switch alike.

That baseline is one consistent cut. `observeSession(…, { projectionMode: 'all' })` (`packages/session-query/session-query/src/observation.ts`) answers from the registry snapshot for an attached session — `{ asOfSeq: cursorBefore(session.seq), values }`, every value folded to the same log position — and from cache-seeded hydration over the whole log for a cold one, and the follow path ships it with the opening snapshot (`packages/api/session-controller/src/history.ts`). Frames are change-only: `drive()` notifies only when the folded state and the rendered view both change (`packages/session/session-projection/src/index.ts`), and each notification becomes one frame (`packages/api/session-controller/src/control.ts`). Both folds take the session's last `todo/write` and neither clears at a turn boundary ([standing-plan lifetime](2026-09-16-todo-plan-survives-the-turn-boundary.md)), so the dock cannot be older than the log — which is exactly why the seven-minute window had to be fixed at the write, in this package, and not in the render path.

## Alternatives considered

- **Keep the 3/12 cadence and only add the reason clause.** The cheapest change, and it does make each notice checkable. Rejected because the notices it keeps firing on a plan the model has just written would still be false, and a false notice that names its own age is still a false claim about work that did not happen; the cadence that produced "the nudge is automated" survives.
- **Restore the step-based cadence (8 steps, then every 32) unchanged.** Faithful to the reviewed design, but it measures steps where work is what ages a plan, and its repeat interval is long enough that the reported 29-call stretch would have drawn one notice. The work measure stays; the threshold is recalibrated against measured stretches instead.
- **Challenge on every step while a plan is unfinished.** Maximum salience and minimum latency. Rejected: it makes the notice a constant, which is the state that taught the model to dismiss it, and it spends the plan's tokens on every step.
- **Wrap a digest of the tool calls since the write into the notice.** The model derived the drift itself at 27 calls ("PR #22 merged, issue CLOSED"), so naming that work would shorten the inference. Deferred, not rejected: rendering tool-call arguments as model-facing prose needs a per-tool rule the harness does not have, and the count plus the plan is enough to state the claim truthfully.
- **Enforce reconciliation instead of asking for it** — a `reject` pre-step decision, or holding the final answer until the plan is written. The loop offers no such point: a `reject` ends the turn as blocked, which loses work over bookkeeping, and nothing precedes a final answer that can be conditional on a tool call. Not available without an agent-loop change.
- **Mark items `completed` from tool evidence** (a merge, a closed issue, a green gate). Rejected: the mapping from tool calls to a plan item's truth is exactly the judgment the model holds and the harness does not, and a wrong automatic completion is worse than a late manual one.

## Consequences

A plan now goes unchallenged for at least 12 tool calls, so a model that stops writing is reminded later than before — the trade this note makes deliberately, since the earlier reminder was not being read. The window can still be long: at 27 calls the model believed the notice but deferred the write behind one more PR ("Let me create the PR for #18, merge it, and update todos"), which is the residual behavior no cadence fixes, and the reason the notice states its age rather than only its urgency.

The notice text grew by one clause on both paths, and the settlement path now reads a sentence where it previously read the same words as a cadence notice. Notice volume halves for a long session. The fold's shape is unchanged (`workSinceWrite`, `remindedAt`, `stateVersion` 2), so a persisted `todoStale` row restores across this change; the reminder interval left no state to migrate.

## Deferred

Two carriers can still leave the dock holding less than the log's tail; both were traced while diagnosing this incident, neither is fixed here, and both are pinned by existing tests. The opening baseline of a session that is not yet attached is computed before its agent preset composes, so after a host restart the first session opened in the Web GUI receives a `todos`-less block, `ProjectionValueStore.seed` clears the row for an omitted key, and nothing re-publishes the key until the next `todo/write` — the strip is missing rather than stale (`packages/api/session-controller/src/history.ts`, `packages/api/session-controller/src/client/sessions/projection-store.ts`). And the Host-wide control stream, the only carrier of projection *frames*, can fail terminally and silently: the consume loop ends after `console.error` while `restart()` has no production caller, which freezes every client projection until a page reload (`packages/api/gateway/src/client/snapshot-stream.ts`, `packages/api/session-controller/src/client/index.ts`). Neither was reachable in the session this note measures as far as its evidence goes: the session stayed attached through the window, and its strip followed the write that closed the window.

## Testing

`packages/todo/tool-todo/tests/stale-nudge.spec.ts` drives the real agent loop and pins: silence at 11 tool calls and a notice at 12 that carries the count; silence while the plan is complete or never written; no repeat before 24 and a repeat at 24 that carries the new age; the settlement reason text and summary. The fold specs keep their existing expectations, which the cadence does not move. The session evidence above is from one reader-reported run and is not a fixture.
