# Agent Note: 高效执行与有证据的进度

Status: implemented

[English](2026-10-26-agent-execution-efficiency.md) | 中文

## 问题

一次漫长的本地会话在文件工具内部耗时很少，却反复每次模型回复只请求一个工具、在没有记录读取的情况下重试受保护编辑，并留下未完成的工作。没有修改文件的承诺绕过了轮次复核。文档检查也会在没有当前输入已通过的证据时跳过。

## 决策

内置角色提示要求合并独立的原生工具调用、先读取再执行受保护编辑、对完整补丁只检查一次，并继续授权工作直到完成或遇到具体阻碍。进度描述已派发的行动和已观察的结果。

轮次复核也筛选最终回复中的部分英文第一人称行动承诺。辅助复核模型检查行动是否实际发生以及请求是否仍未完成；普通对话不会仅因包含文字而被复核。现有复核配额和失败处理保持有效。

文档聚合始终调度叶门禁。链接门禁记录带版本的成功指纹，覆盖 Markdown、验证器脚本、包元数据、锁文件、缓存实现和发现的本地目标。缺失目标和旧缓存记录使复用失效。

## 考虑过的替代方案

复核每条回复会增加普通对话延迟。降低模型质量、绕过文件守卫以及信任干净的 Git 状态都无法安全解决执行开销。启用代码执行需要单独评估。

## 后果

模型和推理设置不变。批量调用取决于模型决策；英文承诺筛选可能漏掉其他措辞或语言，有限复核是建议而非完成保证。缓存复用要求此前对一致输入执行过成功检查。
