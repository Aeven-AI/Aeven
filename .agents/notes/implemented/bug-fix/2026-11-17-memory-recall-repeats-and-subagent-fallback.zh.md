# Agent Note：召回跳过重复记忆与子代理未判定的记忆

Status: implemented

[English](2026-11-17-memory-recall-repeats-and-subagent-fallback.md) | 中文

## 问题

`memory-context` 为每个用户轮次追加一个召回块，并把每个块保留在会话历史中，但它渲染每个块时不考虑较早的块已经交付了什么。在最近六个最大的本地会话中，约一半的召回行重复了历史中已有的记忆；最大的会话带有 92 个块、210,570 个字符，却只有 120 条不同的记忆。

子代理的任务提示是一条 `user` 消息，且子代理继承父代理的所有者，因此子代理也会召回。当相关性判定失败或超时时，提供方的机械回退会交付排名最高的两条记忆；在最近 87 个子代理会话中，约 30 个研究型子代理各收到两条与任务无关的关于此人的记忆（出生日期、家庭、账户）。

## 决定

- **会话中较早的块已交付的记忆不会出现在之后的块中。** `deliveredMemoryIds` 从会话较早的 `memory-context` 召回块中读取 id；最近一次 `compaction/summary` 或 `compaction/prune` 之前的块不计入，因此被压缩移除的记忆可以再次交付。召回只找到重复记忆的轮次会带有一条通知，说明先前给出的记忆仍然适用；当个人轮次中关于此人的记忆来自较早的块时，该轮仍会收到个人提示。
- **子代理会话不会从降级的召回中收到任何记忆。** 该轮会带有一条通知，说明召回无法判定哪些记忆适合该任务。经过判定的召回和画像块保持不变，因为日志显示，当任务与此人有关时，经过判定的个人记忆对子代理有帮助，而画像块没有造成可观察到的泄露。

## 考虑过的替代方案

**为每个子代理去掉 person 领域的记忆和画像块。** 挖掘此人自己的存档以构建画像的子代理，从正常运行的判定中收到了相关的个人记忆；去掉它们会丢失任务所需的上下文。

**只以 id 引用重复交付已交付的记忆。** 完整的行已经在请求历史中，引用只会增加 token，不会增加信息。

## 后果

长会话不再累积重复的记忆行，之后轮次的召回块只包含会话尚未见过的记忆。当判定失败时，主会话仍保留两条记忆的回退。
