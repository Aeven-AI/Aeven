# Agent Note: 保留桌面开发项目的工作目录

Status: implemented

[English](2026-10-14-desktop-development-project-working-directory.md) | 中文

## 问题

Desktop Host 在 Electron 退出后继续运行，并将生成的开发项目作为工作目录。Host 占用该目录时，Windows 拒绝删除它，因此重新准备开发项目可能在 Electron 启动前因 EPERM 失败。

## 决策

开发准备刷新已有真实项目目录的内容，不删除目录本身。如果项目路径是符号链接或非目录，则通过已有的自有路径清理逻辑删除。依赖链接和项目元数据根据当前工作区重新创建。

## 考虑过的替代方案

**每次启动前停止 Host。** 这会中断浏览器客户端和正在运行的工作，与共享 Host 的生命周期相冲突。

**重试删除目录。** 工作目录的占用进程仍在运行，重试无法消除原因。

**每次启动创建新的项目目录。** 这会留下多个依赖视图，并需要跟踪每个持久运行的 Host 占用哪个视图。

## 影响

开发启动之间的项目路径保持稳定。刷新链接不会重启正在运行的 Host，也不会替换它已加载的模块；后端改动仍需重启 Host。

回归测试在子进程占用项目作为工作目录时准备项目，检查陈旧内容被删除且依赖目标保留，并在清理临时目录前等待子进程退出。现有 Windows 开发项目在 Desktop Host 运行期间也能成功刷新。
