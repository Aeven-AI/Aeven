# Agent Note: 启动保留认证就绪条件

Status: implemented

[English](2026-10-25-startup-keeps-authentication-readiness.md) | 中文

## 问题

可选 MCP 握手和预先生成的调试产物拖慢桌面启动。使用持久化验证密钥跳过认证就绪条件，可能在当前签名密钥到达前接收请求。

## 决策

认证保留等待首次密钥获取的行为。可选桌面 MCP 条目不等待连接即可激活；发现完成后，现有监督器注册工具，并继续负责重连和清理。启动失败需要等待发现才能作为致命错误处理。客户端源码映射和单插件响应根据不可变快照按需生成；预处理源码缓存区分共享同一缓冲区的插件标识。

## 考虑过的替代方案

**持久化验证密钥并在就绪后刷新。** 密钥轮换可能导致恢复的会话被拒绝，同时已撤销的密钥仍被信任。**推迟所有启动工作。** 必需的身份和应用依赖必须在接收请求前就绪。

## 影响

启动从关键路径移除可选工具和调试工作，不改变令牌验证或登录传输。工具可能在首页加载后才可用。针对性生命周期测试覆盖延迟发现、清理和无效配置；客户端测试覆盖加载器、不可变响应和源码映射。构建与已安装应用检查仍需验证产物交付；启动计时本身不能证明登录成功。
