# Agent Note: 表格修复要求行以管道符开头

Status: implemented

[English](2026-09-28-table-repair-leading-pipe.md) | 中文

## 问题

GFM 要求存在分隔行，一串管道符行才构成表格，而模型常常漏写分隔行。引擎原先的修复方式是：把任意两行及以上、包含管道符的连续行重建为带合成表头与分隔行的表格。管道符并不能证明这是表格：推理与回答中的管道符来自项目符号列表里的 shell 管道（`` - `ls -R | head -50` ``）、正则交替（`` `\b(?:I|we)\s+` ``）、TypeScript 联合类型（`'redirect' | 'window'`），以及代码片段中的 `||`。

这样的两行会被改写成两列三行的表格，既在整体渲染时发生，也在流式渲染中发生。在某次已记录的会话推理中，`` - `\b(?:I|we)\s+` … `` 与 `- Other branches: …` 这一对就被渲染成了表头空白的表格。在 80 个已存会话里，22 处管道符行组中有 14 处其实是散文；而数据中每一处真正的无表头表格，其每一行都以自己的管道符开头。

流式块类型判定也存在同一规则：缓冲区里出现两个管道符就把整块判为表格，因此一句带两个管道符的散文会被渲染成只有一行的表格；而同一增量里“表格后接散文”的较大分片会把散文并入表格——表格块的边界取自缓冲区**最后一个**空行，随后无表头转换又把散文重建成了行。

## 决定

当一行在最多三个空格缩进和任意引用标记之后以管道符开头时，它就是表格行。该规则由 `src/engine/table/rows.ts` 拥有；`patterns.tableRowRegex` 与 `patterns.tableRowScanRegex` 描述同一种行形态，前者锚定单行，后者用于在整段文本中查找。

- 整体渲染只在行组中每一行都是表格行时才转换（`findTableRuns`），因此项目符号列表、正则交替或代码片段仍保持散文。
- 流式判定只在该块将要提交的内容——缓冲区到第一个空行为止的部分——全部由表格行组成时才判为表格，并统计这段内容中的管道符，而不是整个缓冲区中的。
- 当缓冲区并非由表格行组成时，`convertTable` 原样返回。由首行判定为表格的块仍可能是散文，重建它会凭空造出行。
- 表格块在第一个空行处结束。表格本身不可能包含空行，而取最后一个空行会把同一增量中表格之后的散文吞进表格。
- 已闭合的文本块执行与整篇文档渲染相同的行组修复，因此散文中的无表头表格在流式过程与从日志重新渲染后看起来一致。
- `convertTableHeadless` 把该行组的缩进加到它输出的每一行上，而不只是第一行。列表项内缩进的行组现在仍会是表格，而不再把合成表头与分隔行当作字面文本留在页面上。

不以管道符开头的行为散文。`a | b` 与 `c | d` 两行，以及列表项下缩进的无表头行组，仍是它们本来的表格；带分隔行的表格不受影响：remark-gfm 无需任何修复即可解析它。

## 考虑过的替代方案

**保留管道符计数规则，只要求单元格数一致。** 两行散文通常管道符数量相同——同一个项目符号里的不同管道、两条语句里的同一个 `||`——因此产生该缺陷的规则依然会保留。观察到的误判与真实表格之间，唯一区别正是该行是否以管道符开头。

**只修复位于顶层的行组。** 缩进同样不是判别依据：列表项下的表格是合法的，散文也会缩进。

**把行组切分成最大的表格行子段，使嵌在散文中的表格仍被重建。** 已存会话中没有任何场景需要它——每处散文行组通篇是散文，每处表格行组通篇是行——而它会把没人验证过的混合内容也转换掉。严格解读才是有证据支撑的解读。

**仅凭首行就把缓冲区判为表格。** 这样“一行表格行后接一句普通句子”会在某一帧被重建为表格，并在该块闭合时变回散文。要求整段内容都符合，才能让流式帧与最终渲染完全一致。

## 后果

带管道符的散文按文本渲染，在聊天记录、推理与流式过程中都是如此；管道符保持可见，而不会变成列。每一行都不以管道符开头的无表头表格不再被重建——它按 GFM 的规则渲染为段落中的字面管道符。单独一行表格行在流式时仍渲染为表格、稳定后渲染为段落：`findTableRuns` 要求两行，该限制在本记录中未作改动。

决策落在 `src/engine/table/**`、`src/engine/repair/tables.ts`、`src/engine/stream/detect-block-type.ts`、`src/engine/stream/find-block-boundary.ts`，以及 `src/engine/renderer.tsx` 中处理已闭合文本块的路径。`tests/correctness/pipe-prose.client.spec.ts` 固定了整体渲染在 1、3、200 三种分片大小下散文与表格的区别；`tests/unit/table/rows.client.spec.ts` 固定了行规则；`tests/unit/stream/block-detection.client.spec.ts` 固定了块类型。
