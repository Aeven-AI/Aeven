# Agent Note: 命名步骤不因 MFA 状态接口缺失而失败

Status: implemented

[English](2026-10-15-naming-step-outlives-a-missing-mfa-status-route.md) | 中文

## 问题

命名步骤保存读者姓名后，曾请求 `GET /mfa/status`，以决定是否提供身份验证器设置。该第二次调用的任何失败都会置位该步骤的失败状态，因此对于不提供 `/mfa` 路由的 Aeven API——即尚未上线身份验证器工作的部署——已保存的姓名会得到「我无法保存这个名字。请重试」，并让读者停留在该步骤，因为命名关卡在步骤报告姓名之前不会启动应用。该失败还以按钮下方一行文字呈现，而此界面上的其他失败都以弹窗呈现。

## 决策

该步骤只报告姓名的结果。`/set-display-name` 被拒绝时抛出此界面的弹窗——携带 `modal.oops` 与 `name.saveFailed` 的 `show:modal` 事件——并让读者留在该步骤。该步骤不发出第二次调用，因此已保存的姓名与启动应用之间既没有 `/mfa/status` 请求，也没有设置引导（[注册不再提供身份验证器设置](2026-10-23-signup-stops-offering-authenticator-setup.zh.md)）；注册入口位于账户设置中。

命名关卡只在姓名保存之后启动应用，因此读者绝不会在姓名之前进入产品。

## 考虑过的替代方案

**保留按钮下方那行文字，只是不再由状态调用置位。** 这行文字与该界面不一致：登录与注册的失败都以弹窗报告，而按钮下方的一行会被读作字段错误。

**状态无法回应时提供设置引导。** 设置引导界面自身的设置调用会以同样方式失败，读者会被带到一个无法完成的界面；而引导文案已经承诺之后可在设置中开启该保护。

**要求状态接口必须可用，否则不启动。** 双重验证是可选功能，因此一次无法回应的状态调用不应成为应用的关卡。

## 后果

早于身份验证器工作的 API 可以正常为读者命名，因为该步骤不从它读取其他内容。该步骤不区分「未开启保护」与「无法判断」：账号已开启保护时，读者会进入应用，并在下次登录时被要求提供第二个因素，这与开启保护之前就已存在的会话一致。

## 验证

`packages/client/ui-auth-aeven/tests/name-check.client.spec.tsx` 覆盖两条路径：姓名被拒绝时抛出弹窗并让读者留在该步骤；姓名保存后启动应用。该界面另外在浏览器中以 1728x997 渲染，并用这两种回应驱动，提示语经测量居中于姓名输入框之上。
