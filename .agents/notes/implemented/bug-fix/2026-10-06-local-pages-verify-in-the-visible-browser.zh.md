# Agent Note：本机页面在可见浏览器中验证

Status: implemented

[English](2026-10-06-local-pages-verify-in-the-visible-browser.md) | 中文

## 问题

[浏览器界面状态报告](2026-10-01-browser-surface-status-report.zh.md) 按对用户的代价为浏览器界面排序：先用无头 Playwright，只有在被拒绝或页面需要登录会话时才使用附加的 Chrome。该顺序针对会话无法控制的页面的读取，不涵盖工作区自身提供的页面。2026-10-06，一个调整 Aeven 设置页样式的会话在 `127.0.0.1:3080` 上用无头 Playwright 验证了每一处修改。它的测量描述的是用户看不到的浏览器，其中一项与用户在可见窗口中看到的结果不一致。

## 当前范围

[所选侧边栏操作决定](../feature/2026-10-09-fast-sidebar-browser-actions.zh.md)取代了远程页面优先无头的顺序。本机页面仍然先在可见浏览器中验证。

## 决定

由页面地址而不是任务类型决定。本机提供的页面（`localhost` 或 `127.0.0.1`）是开发中的应用，先在用户能看到的浏览器中验证：会话旁的面板，或由 `mcp__chrome_devtools__*` 工具驱动的 Host Chromium。两者都不可用时无头浏览器仍是其后备，模型随后说明检查是在无头副本中运行的。远程页面保持先无头的升级顺序。首步浏览器上下文、`preview_status` 的下一步、`web_fetch` 的提示段落与 `in-app-browser` 技能都陈述这条规则。

## 考虑过的替代方案

**按任务分类（“开发工作使用 DevTools”）。** 模型必须推断任务类型，而这里它推断错了。地址则是模型从即将打开的 URL 上读出的事实。

**在仓库 `AGENTS.md` 中加一条规则。** 它只覆盖本仓库，而 harness 指引覆盖每个工作区的开发服务器；同一规则的两份副本会逐渐不一致。

**在 Playwright 中阻止本机来源（`--blocked-origins`）。** 它强制了顺序，但也让可见浏览器宕机或无法启动时，本机页面失去无头浏览器这一后备，而会话正是为这种情况保留无头浏览器。用 hook 拒绝这类导航有同样的代价。

## 后果

- 本机提供的页面先在用户能看到的浏览器中验证——会话旁的面板，或 Host Chromium——两者都不可用时无头浏览器仍是后备，模型随后会说明检查是在无头副本中运行的。
- 该规则经由四个拥有者到达模型：首步浏览器上下文、`preview_status` 的下一步、`web_fetch` 的提示段落与 `in-app-browser` 技能。
- 由地址而不是任务类型决定，因此该规则覆盖每个工作区的开发服务器，而不只是本仓库；用户看不到的检查也不再能作为工作区所提供页面的证据。
