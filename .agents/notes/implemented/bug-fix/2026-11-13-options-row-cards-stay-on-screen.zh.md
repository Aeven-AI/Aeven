# Agent Note：输入框选项弹窗的行卡片保持在屏幕内

Status: implemented

[English](2026-11-13-options-row-cards-stay-on-screen.md) | 中文

## 问题

在手机上，从输入框选项弹窗的行打开的卡片（朗读声音、权限模式、上下文操作与详情）会越过屏幕右边缘（[#643](https://github.com/Aeven-AI/Aeven/issues/643)）。它们的样式表把每张卡片放在距行 `left: calc(100% + 10px)` 处，即弹窗旁边；`max-width: min(360px, calc(100vw - 32px))` 只限制卡片宽度，不限制其左边缘落在哪里。弹窗至少 232px 宽并从圆形按钮处开始，因此在 390px 宽的屏幕上，卡片从约 x 314 开始、到约 x 557 结束；而文档是 `overflow: hidden`，无法滚动查看。

## 决定

`@aeven/client-ui-primitives` 新增 `useBesidePlacement`，为在行旁打开的卡片提供定位步骤。它测量行容器与卡片：卡片在后侧放得下时保留样式表的后侧位置；前侧有空间时移到行的前侧；否则叠放在所属行的上方，并横向平移，直到两侧边缘都落在 16px 边距内（与样式表 `100vw - 32px` 上限隐含的边距一致）。它在窗口缩放、捕获阶段滚动以及卡片自身尺寸变化时重新计算，因此卡片打开后才到达的声音目录也会被重新定位。叠放的卡片会盖住所属行上方的弹窗行，但所属行仍可见，再次点按该行仍可关闭卡片。同一模块的 `useViewportClamp` 在圆形按钮的位置会把左对齐的弹窗卡片推出边缘时将其向内平移；按钮目前位于左侧，因此现在不产生位移。

`ComposerOptions` 通过本地的 `RowPane` 为三张卡片应用该钩子；`SystemVoice` 为声音卡片应用它，并在叠放时从行的上边缘而不是下边缘计算高度上限。

## 考虑过的替代方案

**仅用 CSS 的手机分支。** `@media (max-width: 640px)` 规则可以移动卡片，但无法知道圆形按钮的位置，也无法知道目录加载后卡片有多宽；641px 宽的平板配上较宽的目录仍会被裁切。

**通过 Menu 原语的 portal 路径渲染卡片。** `Menu` 已经做了钳制，但它的卡片是条目列表；声音卡片的粘性语言分组与上下文明细是任意内容，移入 portal 还会把它们移出弹窗的外部点按关闭根节点。

**在手机上用卡片替换弹窗。** 一次只显示一张卡片属于设计变更，issue 中仍未定论；叠放在弹窗上方保留了桌面行为和点按行的切换，无需新增导航。

## 影响

`conversation.input.options` 中任何复制 `.pane` 几何的插件行都应以相同的间距、上移量和边距应用 `useBesidePlacement`，否则仍会溢出。该钩子只按宽度做决定：叠放的卡片不做纵向钳制，当前卡片不需要，因为弹窗位于屏幕下部。

## 验证

三个客户端包通过类型检查，`pnpm run build` 通过。在源码 Web 客户端的移动端模拟下，测量了每张卡片的边界框与视口的关系：390×844 时，声音卡片叠放在所属行上方，位于 x 88–331，权限卡片位于 x 88–276；320×568 时，弹窗向内平移 8px 至 x 72–304，声音与权限卡片分别位于 x 61–304 与 x 80–268；在声音卡片打开时旋转到 844×390，它回到弹窗旁边，位于 x 314–557。修改前，390px 下声音卡片位于 x 314–557。上下文行未验证，因为新会话没有上下文读数。
