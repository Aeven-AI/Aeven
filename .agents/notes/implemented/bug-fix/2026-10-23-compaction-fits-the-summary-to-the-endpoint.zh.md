# Agent Note: 让摘要请求适配端点的上限

Status: implemented

[English](2026-10-23-compaction-fits-the-summary-to-the-endpoint.md) | 中文

## 问题

摘要调用会重放它所压缩的区间，因此它自身的请求就带着该区间。端点若因体积拒绝该区间——token 预算对应 `CONTEXT_WINDOW_EXCEEDED`，可接受的消息条数对应 `MESSAGE_COUNT_EXCEEDED`——每次重试都会原样拒绝同一个请求。溢出恢复当时只有一个最大平衡头可选，因此被拒绝的摘要让该轮无法继续：本可适配的缩减比端点刚刚拒绝的区间更小，却没有任何代码去选取它。

## 决策

`packages/compaction/compaction-basic/src/region.ts` 中的 `halveRange` 选取所选区间中最多持有该区间按路由计价 token 一半的最大头部：它累加该区间的 token 计量节点，取前面的节点直到下一个节点会超过一半，再向前回退结束位置直到 `toolPairingBalancedAfter` 成立；当头部少于两个节点时返回 `null`。两个或更多节点组成的头部总能缩短表层，因为一个检查点替换了它们。计量节点与会话表层不匹配时抛出错误，而不是去折半一个计量器并未计价的区间。

`compactFitting` 恰好在这两个错误码上带着更小的头部重试摘要。信号已中止，或失败带有其他错误码时，它直接重新抛出而不重试；`halveRange` 找不到头部时，它重新抛出原始错误，因此单个工具对造成的不可分割区间仍然报告提供方的失败。

溢出恢复持续压缩，直到抵达它最初选中的区间末尾。每一轮在当前表层上选取可压缩区间，调用 `compactFitting`；当提交结果的 `shadowedRange.end` 未到达所选区间的末尾时，它重新计量，并把剩余部分与替换头部的那个检查点一起压缩。压力压缩在自身的尝试循环中调用 `compactFitting`，并在每次尝试之后按路由模型的阈值重新计量，因此被折半的头部算作该次尝试的进展。

## 考虑过的替代方案

**原样重试被拒绝的区间并报告提供方错误。**区间大小不变，端点会再次拒绝它，于是溢出的轮次以错误结束，尽管更小的头部本可以被摘要。折半只多花一次摘要尝试，却让该轮继续下去。

**每次溢出都预先选取更小的头部。**多数端点接受完整的可压缩区间，而在常见路径上压缩得比端点接受的更少，会丢弃本不必丢弃的历史；因此第一次尝试使用完整区间，只在尺寸被拒绝之后才折半。

## 后果

- 尺寸被拒绝时，同一轮内每次折半多花一次摘要尝试，而不是结束该轮；折半受区间限制，因为每一步都从头部去掉至少一个节点。
- 一次溢出恢复可能落地多个检查点：循环一直运行到被遮蔽的区间抵达原始末尾，因此一次恢复中会话会记录不止一个 `compaction/summary` 事件。
- 被折半的头部让区间其余部分原样保留，剩余部分随后与该检查点一起压缩，而不是在一个请求里重写；恢复后的表层每一轮持有一个检查点。
- 没有平衡头部可缩小的区间——过大的工具对、区间中不存在低于一半的两节点头部——仍然抛出原始的提供方错误，该轮把它报告出去。
- `packages/compaction/compaction-basic/tests/compaction-basic.spec.ts` 固定了一半 token 预算、回退到平衡工具调用边界、不匹配时抛出、两种 `null` 情形、两个错误码各自触发的一次重试、其他错误码与已中止信号以及无更小头部时的重新抛出，以及重新计量剩余部分直到被遮蔽区间抵达原始末尾的循环。
