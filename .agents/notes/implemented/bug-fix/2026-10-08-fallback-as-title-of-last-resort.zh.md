# Agent Note: 回退是最后手段标题

Status: implemented

[English](2026-10-08-fallback-as-title-of-last-resort.md) | 中文

## Problem

一个全新的 Web 会话在约一秒半内被命名了两次。首条符合条件的用户消息落地时，`onUserMessage` 立即创建了确定性回退；主请求的路由写入日志后，已注册的首消息提供方又在它之上追加了模型标题。于是侧边栏行、其搜索结果行与浏览器标签页都先显示截断的首条提示词，随后显示另一个名称。每个会话只发生一次辅助模型调用——被重复的是标题本身，而读者无法分辨哪个是临时名称、哪个是定稿名称。

同一个窗口里还提供重命名。行菜单仅在会话仍为 `blank` 时隐藏，因此从首个轮次开始，该行就带着 New Session 标签、可用的 Rename 操作，以及一个把该临时标签预填为会话当前标题的对话框。

## Decision

由提供方负责的修订只由该提供方命名。确定性回退是最后手段标题：它命名任何没有提供方负责的会话、填补未产生标题的修订，并为恢复时没有标题的会话命名。[纯日志会话标题](../feature/2026-07-21-log-backed-session-titles.zh.md)负责周边设计；本记录只改变一次已安排的自动调用所产生的那次修订。

### 每个已安排的修订只接受一次修订

`onUserMessage` 只安排提供方修订，不再安排其他内容，因此由提供方负责的新会话在模型答复到达前一直显示本地化的 New Session 标签。`fillFallback` 会为一个没有任何修订排队或进行中的活跃会话安排确定性标题：

- 失败或返回无效结果的提供方调用——在失败修订释放其活跃槽位后填补；
- 在调用前被丢弃的修订，原因来自 `startPending` 的各项守卫或提供方 dispose；
- 没有提供方负责的提示词，因为没有注册提供方、节奏不安排它，或会话已持有已接受的标题。

被较新修订取代的修订不作填补——由那次较新的调用报告结果——会话已消失或服务正在卸载的工作同样不作填补。`runProvider` 在填补前先清空自身的活跃槽位，因此这次填补不会被误认为进行中的工作；`ensureFallback` 仍会返回已接受的标题，而不会追加第二个标题。

### 标题创建期间的重命名

当会话尚无持久化标题且正在工作时，侧边栏行不提供其 Rename 操作：该行显示为本地化的 New Session 标签，因此没有可预填的名称，而一个名称已经在路上。该事实就是行自身的 `untitled` 与 `running` 位，列表本就携带它们，因此不需要新的线上字段或 host 事实。处于静止状态的无标题会话——即提示词未产生任何合格标题输入，因而不会安排任何工作的会话——保留该操作，因为没有什么会来替换读者赋予它的名称。

## Alternatives considered

- **保留即时回退，改为依据实时标题工作事实来限制重命名**：不予采纳，因为这会新增一个经会话列表状态通道推送的 host 事实、一个线上字段及其客户端接线，却仍留下触发该报告的重复命名：读者依旧看到该行与浏览器标签页改名。
- **对所有无标题行都不提供重命名**：不予采纳，因为一个永远无法被命名的会话——例如只用不合格内容提示过的会话——将因此失去唯一的重命名路径。正是「正在工作」这一合取项为静止的行保留了该操作。
- **用定时器延迟回退，而不是在修订结束时填补**：不予采纳，因为定时器是与其所等待的提供方相互竞争的第二套状态机，而修订结束正是已知标题缺失的确切时点。
- **只要注册了提供方就抑制回退**：不予采纳，因为提供方可能让会话永远无标题：一次失败、被丢弃或被 dispose 的调用会让会话停留在临时标签上而无持久名称，而恢复的、没有安排提供方的会话则完全不会被命名。

## Testing

`packages/session/session-title/tests/provider.spec.ts` 覆盖已接受修订的计数（由提供方负责的修订只产生一个 `session/title` 事件）、失败填补、被取代而不作填补的修订，以及在填补前已消失的会话。`service-contracts.spec.ts` 覆盖 dispose 与被丢弃修订的填补。`packages/client/ui-workspace/tests/rows.client.spec.tsx` 覆盖行无标题且正在工作时 Rename 被收起、标题落地后恢复。无密钥的录制会话场景 `snapshots/sdk/session-title-after-turn` 回放结果不变，因为已恢复且有标题的会话不会再安排修订。`apps/cli/tests/profiles/headless/tests/expected/` 下由 owner 本地运行的过程预期已刷新为新的事件顺序：回退现在跟在它所填补的失败调用之后。

## Consequences

- 会话只被命名一次。侧边栏行、搜索结果行与浏览器标签页保持本地化的 New Session 标签，随后显示定稿标题，而不再出现中间那段截断的提示词片段。
- 由提供方负责的新会话会在模型调用的延迟期间保持可见的无标题状态；基础 profile 将该延迟上限定为六十秒，而对随附路由实测约为 1.5 秒。失败或因 dispose 而结束的调用仍会留下持久标题，因为回退会填补它。
- 对于提供方一直失败的部署，回退而非提示词成为其唯一保留的标题，因此已配置的 `fallbackMaxWords` 与 `fallbackMaxBytes` 决定该名称的质量。
- 在该窗口期间，尚无标题的行不可重命名；该行始终保留 Fork 与 Archive。
