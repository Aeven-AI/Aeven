# Agent Note: todo 计划跨轮次边界存续

Status: implemented

[English](2026-09-16-todo-plan-survives-the-turn-boundary.md) | 中文

## Problem

dock 的计划条在每个轮次边界都会清空，读者将其报告为已完成工作被删除。[下一轮次清空规则](../feature/2026-07-28-todo-plan-clears-on-next-turn.zh.md)让 `todos` 投影在每个 `turn/start` 返回 `null`，其前提是读者把该条视为「本轮的进行内容」。这个前提只在 agent 于每轮早期重写列表时才成立。此后的两项改动消除了这份压力：让模型在每一步以运行时上下文读回自己的计划（`fix(todo): let the model read its own plan back`），以及陈旧计划提醒——其提交信息本身记录了一个 agent 连续 96 步持有同一份计划而从未重写（`feat(todo): nudge a plan that has gone stale`）。没有理由重写未变化列表的 agent 就不会重写它，于是这次清空不再只让 dock 空白几秒，而是让它整轮空白。

故障的本质是分歧，而不只是一个空盒子：`todoPlan` 保留着计划，而 dock 什么都不渲染，因此模型以为计划就在屏幕上，读者看到的却是空 dock。在暴露该问题的会话中，三次读者反馈（「check todos」「why did the todo get removed?」「again the todos are gone」）都落在折叠已清空 dock 的时间窗内，而仅宿主的回读仍持有读者此前一直在看的同样 13、21 和 23 个条目。此前对同一反馈的调查只检验了条目数量上限，便得出「没有任何东西删除 todo」的结论——而这恰恰是折叠出现分歧时从模型一侧看到的样子。

## Decision

计划的生命周期属于会话，而不属于轮次。`todos` 折叠从每次 `todo/write` 取整份列表，仅在首次写入之前为 `null`，对其余每个事件（包括 `turn/start` 与 `turn/end`）返回同一个状态引用（`stateVersion` 3）。两个投影单元现在折叠完全相同的输入——面向客户端的 `todos` 与模型回读的 `todoPlan`——因此 dock 与 agent 对有效计划不可能出现分歧。由于注册表的变更流仅在原始结果发生 `Object.is` 变化时通知，轮次边界不再推送任何 `todos` 帧，计划离开 dock 的方式只剩一种：被下一次写入替换。

## Supersedes

[下一轮次清空 todo 计划条](../feature/2026-07-28-todo-plan-clears-on-next-turn.zh.md)的决策被反转：其 `turn/start` 清空行为已移除，它在此之上划分的「dock 按轮次的 `todos`」与「模型跨轮次的 `todoPlan`」之间的区别也随之取消。它的其余内容依然成立——投影单元及其 `wire` 契约、整表替换的末次写入生效、`turn/end` 从不清空，以及对「用空写入改动日志」方案的否决。

## Alternatives considered

- **保留清空，并让 dock 从仅宿主的回读恢复** — 需要让 `todoPlan` 抵达客户端，这要么意味着再接一个客户端可见的键，要么让 dock 去读一个被 `wire` 契约有意排除的键。两者都会重新制造本次改动所消除的双数据源问题，并且都让 dock 在每个轮次边界短暂空白。
- **仅当所有条目都为 `completed` 时清空** — 范围更窄，且确实能修复所报告的在途计划消失问题。否决原因是：部分完成的计划仍会跨越边界进入后续不相关的工作，而这正是原规则想要防止的陈旧性；同时这会让 dock 的取值依赖于模型在任意时刻改动的状态。
- **在 `turn/end` 清空** — 原笔记的首个备选，依然更差：它会在读者正阅读那份由清单解释的答复时把已完成的清单藏起来。
- **由读者手动关闭该条** — 这是一个真实的产品选项，但需要新增按会话持久化的 UI 状态以及 dock 中的控件；投影改动是更小的完整修复，关闭控件日后可以叠加其上。

## Consequences

dock 会持续显示 agent 实际正在推进的计划，包括计划未发生变化而跨过轮次边界的情形；已完成的清单现在也会保留到下一次写入替换它为止。代价是陈旧性，而它由别处负责：陈旧计划提醒存在的意义正是在计划长期未变时把 agent 推回 `todo_write`，运行时上下文回读则让模型持有的同一份列表保持显式，而非靠重建。读者可见状态现在只有一种含义而非两种，而会话证据表明这一性质比自动退场更有价值。

`stateVersion` 提升到 3 会丢弃已持久化的 v2 检查点，这是必需的而非附带效果：v2 行可能持有清空折叠在 `turn/start` 之后产生的 `null`，而当前折叠永不返回该值，因此恢复它会从投影缓存中重新引入空 dock。覆盖：投影规格固定了计划跨过下一次 `turn/start` 而存续，以及两个折叠在同一读取切点上一致；客户端 fixture 镜像把 `turn/start` 从该键的折叠中移除，并不再为它推送帧；tool-todo README 与本笔记承载该生命周期规则。
