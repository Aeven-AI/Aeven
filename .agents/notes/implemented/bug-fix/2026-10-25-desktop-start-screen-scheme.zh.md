# Agent Note: 桌面启动画面按“外观”偏好绘制

Status: implemented

[English](2026-10-25-desktop-start-screen-scheme.md) | 中文

## 问题

启动画面带有 `color-scheme: light dark` 与 `prefers-color-scheme: dark` 媒体查询，因此总是按操作系统报告的配色绘制。在产品的“外观”设置里选了“深色”、而操作系统仍是浅色的用户，会先看到浅色的启动画面，再在客户端预加载界面接管时变色。启动状态行那三条安装步骤文案都是带版本号的整句，13px 字号、宽达 440px，文字的份量盖过了这块画面本来要展示的标记。

## 决策

`readStartScreenScheme(file)` 读取 Host 的设置文档——Aeven 主目录下 `resolveAvnHome()` 指向的 `settings.yaml`——并返回其中的 `ui-theme.preference`，也就是“外观”一行写入的字段：`light`、`dark` 或 `system`。启动画面在任何 Host 运行之前就要绘制，因此由桌面壳自己读文件，而不是去询问设置服务。文档不存在（只有改过设置才会有）、无法解析（Host 在启动时拒绝并报告）、或其中没有内置偏好时，返回 Host 自己的默认值 `system`。`startPageDocument(platform, scheme = 'system')` 对内置配色写 `color-scheme: <scheme>` 与该配色的调色板、且不带媒体查询；`system` 则保留媒体查询。`brandDocumentHead` 的 meta 标签接受单一配色值。

启动状态行只带一句短语，不再有版本号与步骤名：排入更新检查的启动显示“正在检查更新”，每个安装步骤都显示“正在安装更新”。该行 11px，宽 `min(80vw, 260px)`，不透明度 0.55，仍脱离加载画面的排布流，因此文字出现时既不动标记也不动加载圈。

## 考虑过的替代方案

**通过 Host 的设置服务读取偏好**要等 Host，而 Host 在这页画完之后才启动。**只保留媒体查询**正是旧画面的做法，且与用户在产品里选定的配色相矛盾。**在这一页里渲染客户端的预加载界面**为了画两个颜色就要加载一份客户端包，而这两个颜色桌面壳本就有了。

## 影响

启动画面与客户端预加载界面的配色一致，交接时不再变色。桌面壳以 CSS 自定义属性携带两套调色板，而偏好本身只有一个来源，即设置文档；在设置中改过的内置配色要到下次启动才体现在这页上，因为每次启动页请求都会重新读取该文档。状态行不再说明正在安装的版本，也不再说明安装进行到哪一步。
