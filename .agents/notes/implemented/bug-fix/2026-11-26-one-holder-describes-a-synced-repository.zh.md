# Agent Note：仓库的两个持有者无休止地相互覆盖对方的描述

Status: implemented

[English](2026-11-26-one-holder-describes-a-synced-repository.md) | 中文

## 问题

2026-11-26，桌面 Host 在空闲时占用一个 CPU 核心的 10–11%，托管 Host 占用 23%。两者都持有工作区 `808f70b3…`：桌面上是一个 725 MB 的仓库，托管 Host 上是一份受管副本。`workspace-git-sync` 在账户的 `workspace-git/repositories` 文档中为每个仓库保存一份描述，每个持有者在每轮处理中都写入自己的描述。描述包含位置提示和大小，它们在每台设备上都不同，因此每个持有者都发现对方的描述不同并将其替换，而这次替换又触发对方的下一轮处理。由此产生三个故障。

- 桌面上的每轮处理为每个仓库运行约 11 条 Git 命令，并写入再删除一个检查点暂存目录，大约每秒一次。
- 两台设备轮流替换的 `Y.Map` 条目每次写入都会留下一个任何合并都无法合并的已删除项。该文档增长到 4.7 MB，每台设备每 `snapshotAfter` 帧就为它排队一次快照，账户的 `sync.db` 增长到 1.1 GB，其中 73% 是空闲页。
- 托管 Host 把 `http://127.0.0.1:3128/git/github.com/…` 发布为远程。`git remote get-url` 会应用 `url.<base>.insteadOf`，而该 Host 通过本地代理转发 Git；仓库配置中保存的是真实 URL。

## 决策

- 描述记录写入它的设备。持有者只在仓库没有描述、当前描述由它自己写入，或描述它的设备不再是持有者时才描述该仓库。
- 远程通过 `git config --get remote.<name>.url` 读取，它不应用任何改写。
- 文档改为 `workspace-git/repository-holders`，每台设备停用 `workspace-git/repositories`。Yjs 文档无法丢弃已删除项，而早于本说明的构建会继续向第一个文档写入不带设备的描述，采用新规则的构建只能把它们视为可替换的。
- 当空闲页超过存储文件的 `reclaimFreeRatio`（默认 0.5）时，`SyncStore.reclaim` 在打开时重写该文件以去掉空闲页。

## 考虑过的替代方案

- **只按远程比较描述。** 否决：对同一工作区持有不同远程（例如 fork）的两个持有者会以同样的方式相互覆盖。
- **每台设备一份描述。** 否决：读取方需要一个远程、分支、提示和大小来放置仓库，那样就必须在多份描述中挑选。
- **在 `publicRemote` 中拒绝环回主机。** 不作为修复方案：改写后的 URL 对任何代理地址都是错的，而配置中的 URL 对所有情况都是对的。

## 影响

分支、提示和大小来自描述仓库的设备，只在该设备运行一轮处理时变化；当另一个持有者描述仓库时，更改了远程的持有者不会发布它。运行较早构建的设备与运行本构建的设备在都升级到本构建之前各自保留独立的仓库列表。中转服务器保留第一个文档。
