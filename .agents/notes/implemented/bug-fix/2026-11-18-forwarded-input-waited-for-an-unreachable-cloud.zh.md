# Agent Note：桌面设备的输入在等待一个无法访问账户的 Æven Cloud

Status: implemented

[English](2026-11-18-forwarded-input-waited-for-an-unreachable-cloud.md) | 中文

## 问题

2026-11-18，一位桌面用户在某个对话中的消息显示“Ævening…”，没有停止按钮，刷新后消失。中转服务器显示，桌面设备在 07:38:26 和 07:51:45 把它们写入同步收件箱，发给托管 Host。该 Host 自 2026-11-16 起就没有同步过这个账户（账户密钥受通行密钥保护，而 Host 没有授权），因此从未看到它们。它在 07:53:31 取走了所有排队的输入，此时距用户打开 Aeven Web、Host 获得授权仅 1.6 秒。

两条规则造成了这次等待。`homeOf` 只要始终在线设备运行了对话的最近一回合，就把对话留在它上面，而不检查它能否访问该账户。`consumePass` 在账户有始终在线设备时，从不让打字的桌面设备运行它转发出去的输入，既没有超时也没有过期。

## 决定

- 始终在线设备也每隔 `presenceMs` 在其设备条目上打 `seenAt` 标记，而只有在持有账户密钥和中转连接时它才能这样做。
- 只有当该标记在 `presenceWindowMs` 之内时，`homeOf` 才把对话留在始终在线的编写方；否则由桌面设备自己运行该对话。
- 当输入被发往的设备没有接手时，输入所在的设备在 `remoteFallbackMs`（10 秒）之后自己运行它，无论账户是否有始终在线设备。由运行方租约来仲裁目标设备迟到的接手。

## 考虑过的替代方案

- **让转发的输入过期。** 已否决：消息仍然不会运行，只是之后再消失。
- **在本地运行每个桌面输入。** 已否决：由云端运行的对话把其文件和后台任务留在云端。

## 影响

始终在线设备每隔 `presenceMs` 为每个账户写入一次存在更新。此改动之前构建的桌面设备仍会不检查标记就转发给始终在线设备。转发的输入仍只保存在同步收件箱中，因此客户端刷新后无法显示它；显示等待中的输入是另一项工作。
