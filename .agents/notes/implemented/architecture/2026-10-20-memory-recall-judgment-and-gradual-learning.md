# Agent Note: Memory recall judgment and gradual learning

Status: implemented

English | [中文](2026-10-20-memory-recall-judgment-and-gradual-learning.zh.md)

## Problem

Automatic recall delivered whatever shared words or embedding direction with the turn. A person who wrote that they felt down while asking for the weather got CSS notes, account-page edit logs, and coding procedures, while the memories about what they were going through were dropped: MemOS's relevance filter was skipped for latency, and when it ran it judged task fit only, from the first 500 characters of a query that put the current message last. Learning had the opposite problem. A procedure was written and recalled the moment one turn ended, before the person could react, from personal conversations as well as work, so a crisis conversation became a standing rule to recite a hotline and a rejected answer became the procedure for the next one. The English-only MiniLM embedder ranked Dutch and Spanish memories near noise, and an archive import through the model reworded and silently dropped facts.

## Decision

Recall has three stages. Retrieval embeds the person's earlier messages in the session followed by the turn's text with `Xenova/multilingual-e5-small` (`query: ` / `passage: ` prefixes, 512-token pieces, q8 on CPU). On a session's first turn the person's own memories from the last 48 hours join the candidates. A relevance judgment owned by `@aeven/memory-memos` then reads the request whole, the earlier conversation apart, and each candidate's kind, domain, age, and procedure status, decides whether the person or the task leads, may keep nothing, and reports whether the person is sharing their life; on failure at most two mechanical hits are delivered and the recall is marked degraded. When the person asks what is known about a subject, the judgment keeps every distinct fact about it. `@aeven/memory-context` keeps the judged order, drops only exact repeats, caps a judged block only by `judgedMaxItems` (14) rather than per domain, and, when the person is sharing their life, follows the block with a notice outside it, because the block's content is data, never instructions.

Learning is gradual. The learner waits for the person's next message and reads it as feedback; a turn memory filed as `person` is never learned from; a new or rewritten procedure is a `candidate`, recalled only when the judgment finds an exact fit and marked unproven; it becomes `active` when a turn it informed called a tool and the next message did not correct it, returns to `candidate` on a correction or negative rating, and is archived after `candidateTtlDays` unconfirmed. MemOS induces a policy only from two episodes, recalls only `active` policies, delivers one Skill per turn, and leaves remembered facts and personal conversations out of policy induction and episode summaries. Its cosine cutoffs are re-mapped to the e5 scale by quantile matching (`packages/memory/memory-memos/scripts/embedding-eval.ts calibrate`), a model change re-embeds every stored vector before recall resumes, and `memory_remember_bulk` imports a fact file verbatim, skipping text already stored and tagging imports so their age is not read as today. A remembered or imported fact ranks with a learned value of at least `rememberedFactValue` (0.5), because it never takes part in a rewarded task and would otherwise lose to rewarded conversation traces that are further from the query.

## Alternatives considered

Keeping MemOS's filter and improving its prompt: it has no domain, age, or procedure status for a candidate, so it cannot tell a log from a fact or an old import from today's event. Excluding coding memories from chats by session type: a person can need personal support in the middle of a coding session, so the judgment decides per turn. Promoting a procedure when the same kind of task recurs in another session: recurrence shows demand, not that the written steps worked. A larger multilingual embedder or a cross-encoder reranker: deferred until the eval script shows the e5 retrieval stage is the bottleneck; with the cleaned store e5 scored 58/80 against 49 and 50 for the MiniLM variants on the owner's labeled cases.

## Consequences

Every direct-user turn spends one more model call, about 1.0-1.5 s, before the reply starts, and a judgment failure delivers less memory rather than unjudged memory. Procedures take longer to start helping, and a candidate that is never recalled into a confirming turn is archived. The e5 cutoffs are provisional: they preserve the share of pairs MiniLM kept, not proven relevance, so the eval script and live checks are the evidence for retuning. Existing untagged procedures read as candidates. Personal eval cases stay beside the owner's memory, never in the repository.
