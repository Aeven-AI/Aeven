# Agent Note: 记忆召回评判与渐进学习

Status: implemented

[English](2026-10-20-memory-recall-judgment-and-gradual-learning.md) | 中文

## 问题

自动召回交付的只是与本轮共享词汇或嵌入方向的内容。用户在询问天气时写下自己心情低落，得到的却是 CSS 笔记、账户页面的编辑日志和编码流程，而关于他正在经历什么的记忆被丢弃了：MemOS 的相关性过滤为降低延迟而被跳过，而它运行时也只判断任务契合度，依据是查询的前 500 个字符，而这个查询把当前消息放在最后。学习的问题正好相反。一个流程在一轮结束的瞬间就被写入并召回，用户还来不及反应，而且这些流程既出自工作对话，也出自私人对话，于是一场危机对话变成了一条背诵热线的常设规则，一个被否决的回答则成了下一次的流程。仅支持英文的 MiniLM 嵌入模型把荷兰语和西班牙语的记忆排到接近噪声的位置，而经由模型执行的归档导入会改写事实并静默丢弃事实。

## 决策

召回分为三个阶段。检索用 `Xenova/multilingual-e5-small` 依次嵌入用户在本次会话中更早的消息和本轮文本（`query: ` / `passage: ` 前缀，512 个 token 的分片，在 CPU 上使用 q8）。在会话的第一轮，该用户最近 48 小时的记忆也加入候选。随后由 `@aeven/memory-memos` 拥有的相关性评判完整读取请求、单独读取此前的对话，以及每个候选的类型、领域、新旧程度和流程状态，判断以用户为主还是以任务为主，可以什么都不保留，并报告用户是否在分享自己的生活；评判失败时最多交付两条机械命中，并把该次召回标记为 degraded。当用户询问某个主题上已知哪些内容时，评判会保留关于该主题的每一条不同事实。`@aeven/memory-context` 保留评判后的顺序，只丢弃完全重复的内容，对评判后的块只按 `judgedMaxItems`（14）设上限而不按领域设限，并在用户分享自己的生活时，于该块之后、块外附上一条提示，因为块内的内容是数据，永远不是指令。

学习是渐进的。学习器等待用户的下一条消息，并把它当作反馈来读；以 `person` 归档的轮次记忆永远不作为学习来源；新增或重写的流程是 `candidate`，只有在评判认定完全契合时才被召回，并被标记为未经验证；当它影响过的一轮调用了工具、且下一条消息没有纠正它时，它才成为 `active`，遇到纠正或负面评分时回到 `candidate`，在 `candidateTtlDays` 内未获确认则被归档。MemOS 只从两个 episode 归纳策略，只召回 `active` 的策略，每轮交付一个 Skill，并把记住的事实与私人对话排除在策略归纳和 episode 摘要之外。它的余弦阈值经由分位数匹配重新映射到 e5 尺度（`packages/memory/memory-memos/scripts/embedding-eval.ts calibrate`），更换模型时会在召回恢复之前重新嵌入每个已存储的向量，而 `memory_remember_bulk` 逐字导入事实文件，跳过已存储的文本，并为导入内容打上标签，使其新旧程度不会被读作今天。被记住或导入的事实参与排序时带有至少 `rememberedFactValue`（0.5）的学习值，因为它从不参与有奖励的任务，否则会输给距离查询更远、却获得奖励的对话轨迹。

## 备选方案

保留 MemOS 的过滤并改进它的提示词：它没有候选的领域、新旧程度或流程状态，因此分不清日志与事实，也分不清旧导入与今天的事件。按会话类型把编码记忆排除在聊天之外：用户可能在编码会话中途需要个人方面的支持，因此由评判逐轮决定。当同类任务在另一个会话中反复出现时提升某个流程：反复出现说明有需求，并不说明写下的步骤奏效。更大的多语言嵌入模型或交叉编码器重排序器：推迟到评估脚本表明 e5 检索阶段就是瓶颈之后；在清理过的存储上，e5 在所有者标注的用例中得 58/80，而 MiniLM 各变体为 49 和 50。

## 后果

每个直接用户轮次都在回复开始前多花一次模型调用，约 1.0-1.5 秒，而评判失败时交付的记忆更少，而不是未经评判的记忆。流程要更久才开始起作用，一个始终没有被召回进确认轮次的候选会被归档。e5 的阈值是暂定的：它们保留的是 MiniLM 曾经保留的配对比例，而不是已被证明的相关性，因此重新调参的依据是评估脚本与实机检查。已有的未打标签流程会被读作候选。个人评估用例与所有者的记忆放在一起，永不进入仓库。
