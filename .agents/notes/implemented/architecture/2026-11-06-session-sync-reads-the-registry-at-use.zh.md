# Agent Note: 会话同步在每次使用时读取工作区注册表，并归档每个未归档的对话

Status: implemented

[English](2026-11-06-session-sync-reads-the-registry-at-use.md) | 中文

## 问题

在托管 Host 上，一个桌面端对话不在任何工作区中，而在网页上开始的对话发布时没有工作区，因此桌面端也无法归档它。`SessionMirror` 只在账户的镜像启动时接收一次 `ctx.get('workspaceRegistry')` 和 `ctx.get('attachments')`。在注册表提供之前启动的镜像（如让每个账户保持连接的 Host 上的镜像）在整个运行期间都不归档任何对话，也不发布任何工作区；之后被替换的注册表则让它继续依据旧实例作答。

归档也只针对本地副本落后于索引且没有设备在运行的对话。一个在另一台设备上运行、而本地副本一直跟上的对话之后永远不会落后，因此永远不会被归档。

## 决定

- `SessionMirror` 以读取函数（`() => ctx.get(...)`）的形式接收注册表和附件存储，并在每次使用时读取；延迟归档的观察在每次导入时转移到当前注册表。
- 每次导入都会归档账户拥有的每个未归档对话，无论本地副本是否落后，也无论是否有另一台设备在运行它。

## 考虑过的替代方案

只在注册表存在后才启动每个镜像。已否决：注册表是可选的，而且镜像运行期间被替换的注册表仍会留下过期的实例。

## 后果

桌面应用走相同的路径；一个在别处运行、而本设备一直跟上的对话现在也会在本设备上被归档。
