# Agent Note：桌面 Host 的生命周期取决于客户端租约

Status: implemented

[English](2026-10-15-desktop-host-lifetime-follows-leases.md) | 中文

## 问题

[每个 Aeven 主目录共享一个 GUI Host](../bug-fix/2026-10-07-desktop-waits-for-booting-host.zh.md) 使桌面启动的 Host 可以比桌面壳活得更久：退出 Electron 会分离子进程，而子进程在无人拥有的状态下继续提供服务。2026-10-15，一个这样的 Host 在 Aeven.app 已关闭的情况下以父进程 PID 1 运行了一个多小时。该 Host 运行的是应用包内的上游 Node.js 可执行文件，因此更新会在运行中的进程下方替换应用包；Windows 则根本拒绝替换正在运行的可执行文件。下一次启动会接入旧 Host，跳过只在启动自身 Host 之前执行的发布版本协调，并呈现旧后端。发现记录既未记录 Host 的版本，也未记录其所有者，因此桌面壳无从判断。持续运行的 Host 应当可见，就像菜单栏中的应用那样，而不是 3080 端口上的隐形服务器。

固定端口还带来相关故障：当另一个程序占用 3080 时，桌面 Host 无法启动，桌面壳显示启动失败窗口。

## 决策

`runtime/host.json` 中的发现记录写明 `lifetime` 与 `avnVersion`。桌面启动的 Host 为 `leased`；`avn web` 启动的 Host 为 `foreground`，属于其终端，只在该进程关闭时停止。读取时这两个字段可选，记录版本保持为 1，因此旧构建仍能读取新记录；没有 `lifetime` 的记录按 `leased` 处理。

`leased` Host 在不再有任何租约时停止。启动它的桌面壳以其 Node IPC 通道作为租约，退出或崩溃都会关闭该通道。呈现该 Host 的其他进程（例如同一主目录上的第二个桌面构建）持有客户端租约：`runtime/host-clients/` 下的内核文件锁，进程死亡时释放。Host 在其桌面壳离开时统计客户端租约，并在仍有租约期间每两秒统计一次。浏览器标签页不持有租约：它们会无人看管地保持打开并自动重连，把它们计入会重新带回无人拥有的 Host。销毁之前，Host 会从发现记录中撤回其 URL，因此在销毁期间启动的进程会等待该进程退出，而不是接入正在关闭的服务器。桌面壳连接期间，Host 代表该桌面壳持有一个客户端租约，使其他启动器能看到它正在被使用。自行停止的 Host 没有其他进程可以终止它，因此在销毁持续 15 秒后直接退出，该时限与桌面壳原先 SIGTERM 后 SIGKILL 的预算相同。`shutdown` 命令仍会无视租约停止 Host；更新与预备健康检查使用该命令。

当 Host 报告有 Agent 轮次正在运行且没有其他客户端租约时，退出会请求确认；取消后应用继续运行，并在 Windows 与 Linux 上重新打开窗口。打包后的桌面壳发现服务于其他 avn 版本且没有客户端租约的桌面启动 Host 时，会向其发送 SIGTERM，等待该进程退出，协调发布版本后再启动自己的 Host。仍有租约的 Host 与 `foreground` Host 无论版本都会被接入，开发模式的桌面壳会接入任何 Host。

通用设置中的「后台运行」默认关闭；开启后，最后一个窗口关闭时桌面壳以菜单栏或系统托盘图标的形式继续运行，macOS 上的 Dock 图标会隐藏，直到再次打开窗口。运行中的桌面壳保留其租约，因此轮次与自动化会一直执行，直到用户从图标或应用菜单退出。该选项保存在 Electron 的用户数据目录中，因为它描述的是这一安装，而不是某个账户。

webserver 新增 `portInUse`。取默认值 `fail` 时，端口被占用会以指明该端口的错误拒绝激活。取 `os-assigned` 时，服务器监听操作系统选定的端口。桌面 Host 使用 `os-assigned`，并在 `runtime/desktop-port.json` 中记录 `{ configured, bound }`；只要配置的端口不变，之后的启动就请求已绑定的端口，因此与来源绑定的浏览器存储（包括登录状态）在回退后得以保留。`avn web` 只在调用未指定 `--port` 时回退。

## 考虑过的替代方案

**保留分离的 Host，只增加版本检查。** 该检查能修复更新后的旧后端问题，但仍会留下无人拥有的进程，macOS 更新时仍会替换正在运行的可执行文件，在 Windows 上仍会失败。

**Electron 每次退出都停止 Host。** 这忽略了呈现同一 Host 的其他进程，它们会在轮次进行中失去后端。

**通过已认证的 HTTP 连接持有租约。** 持有的连接会在进程死亡时立即释放租约，且无需轮询。在启用 Aeven 登录的组合中，Host 的 API 认证的是账户 bearer 而不是启动令牌，因此非浏览器持有者没有可出示的凭据。Aeven 主目录中的文件锁依赖的权限与已经保护 `host.json`（其中带有启动令牌）的权限相同。

**把已连接的浏览器标签页计为租约。** 被遗忘的标签页会让 Host 无限期存活，而这正是要修复的缺陷。

**回退到固定的端口列表。** 列表中的任何端口同样可能被占用；记住已绑定的端口才能保留与来源绑定的存储。

## 后果

在后台运行关闭时关闭 Aeven，3080 上不会再有监听者，除非另一个进程持有客户端租约，或该 Host 属于 `avn web` 终端。更新会在替换应用包之前停止 Host，之后的启动会替换任何来自其他发布版本的桌面启动 Host。在 Windows 上，SIGTERM 会直接终止该进程而不执行销毁流程。呈现其他进程所启动 Host 的桌面壳无法查询运行中的轮次，退出时不会请求确认。持有者崩溃且其 PID 被复用时，对应记录会按租约计算，直到该进程退出。第一次从 3080 回退会让浏览器客户端登出一次。按用户要求，验证仅包含 TypeScript、仓库构建与 macOS 上的实际运行检查：在另一个 Host 占用 3080 时，于单独的 Aeven 主目录上运行开发模式桌面壳，Host 回退到操作系统分配的端口并在重新启动时复用该端口；桌面壳退出后，在另一个进程持有客户端租约期间继续提供服务；该租约释放约两秒后停止；在没有租约时退出，Host 在一秒内停止，并移除其记录与 MCP 服务器子进程。Windows 与 Linux 的托盘行为、运行中任务的退出确认、过期 Host 的替换、崩溃释放以及并发启动顺序尚未验证。
