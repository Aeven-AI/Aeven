# Agent Note: Aeven Cloud 加入工作区同步

Status: implemented

[English](2026-11-23-cloud-joins-workspace-sync.md) | 中文

## 问题

归入账户某个项目工作区的云端会话，在托管 Host 自己的项目副本中工作，位于账户的 `.aeven-projects/<workspace id>` 下；文件同步不携带它，以免同一项目被同步两次（[聊天文件存放在 Aeven 文件夹中](2026-11-23-chat-files-live-in-the-aeven-folder.zh.md)）。云端会话在那里所做、但未通过 Git 推送的修改只存在于该 Host 上：账户的桌面设备看不到它们，丢失该 Host 就会丢失它们。桌面设备之间已经通过工作区同步交换这类工作：文件夹工作区作为文件同步文件夹，仓库则通过 Git 加工作状态检查点。托管 Host 两者都不运行，因为两者都以 Host 自己的用户身份运行 Git 和文件操作，在服务多个账户的 Host 上，这会让一个账户的仓库配置、钩子或链接触及其他所有账户。

## 决定

托管 Host 成为每个账户的文件夹工作区与仓库工作区的一台设备，两个 Consumer 都从新的 `managedRoot` 设置进入托管模式（托管 bundle 中为 `avnHomePath('sandbox', 'accounts')`，需同时设置 `AVN_SYNCTHING` 与 `AVN_HOSTED_SANDBOX=1`）：

- **放置。** 工作区只在其会话于该 Host 上运行一个轮次时才到达，落在 `<managedRoot>/<owner>/.aeven-projects/<workspace id>`（`@aeven/workspace` 的 `placeManagedWorkspace`，名称下已有其他文件时加编号）。不会搜索已有副本。仓库的轮次会等待其克隆或复制；文件夹的读取会像在任何设备上一样等待所需文件。在工作区到达之前记录了占位目录的会话，随后在绑定的目录中工作：在没有自己文件夹的 Host 上，`working-directory` 优先使用已绑定工作区的目录，而不是其外部的已记录目录或没有目录。
- **Git 在监狱中运行。** `workspace-git-sync` 的 Git 运行器接受一个 `confine` 钩子，托管模式基于沙箱能力构建它：每条 Git 命令都在账户的监狱中运行，以工作树为根、以它使用的那一个传输文件夹为唯一的其他根；其环境通过 `env` 传入；使用 `safe.directory=*`，因为监狱用户既不拥有 Host 创建的目录也不拥有工作树；并使用远程的 HTTPS 形式，这是出口代理唯一承载的形式。
- **Host 不访问工作树内的文件。** 进出工作树的复制以受限的 `cp` 命令运行：检查点的未跟踪文件、收到的检查点的未跟踪文件，以及环境文件，Host 会先把环境文件写入一个从未被任何监狱挂载过的暂存文件夹。检查点文件夹通过一次重命名就位，而不是递归复制，其描述以独占方式创建。传输文件夹位于账户的 `.aeven-projects/.transfer`，没有任何会话的监狱挂载它。该 Host 不发布环境文件、不显示冲突文本、也不解决冲突，因为这些都要读取或重命名账户命令可以写入的文件。
- **所有设备。** 作为符号链接的未跟踪文件不再随检查点传输；收到的环境文件路径中含有空、`.`、`..` 或 `.git` 分量时会被跳过。检查点会记录它是否带有工作。设备自己不带工作的检查点（在那里拉取或提交时写入）不再压过另一台设备的工作，收到这样的检查点只会快进干净的工作树；分支领先于收到的检查点的设备会在其上应用该检查点的更改和文件，而不是跳过它；重启后重写未变化的工作会保留其时间。在此之前，云端轮次之后在桌面上拉取会遮住云端未提交的工作，落后于桌面的云端克隆的工作也会被跳过。

## 考虑过的替代方案

**把 `.aeven-projects` 作为 Aeven 文件夹的一部分同步。** 这样每个项目会被发送两次，一次通过 Git，一次作为不带 `.git` 的文件，#763 已将其移除。

**只把云端副本备份到加密文件云。** 丢失 Host 时不会丢失任何东西，但工作仍然到达不了桌面设备，恢复它需要手动解密文件云副本。

**以 Host 自己的用户身份运行 Git 和复制，并做路径检查。** Node 没有 `openat`，因此对路径的检查与经由它的写入之间，可能被把目录换成链接的命令抢先；看不到其他账户的监狱则不需要这种检查。

## 后果

云端会话在项目中完成的工作，会通过桌面设备之间交换的同一种检查点到达账户的桌面设备，桌面设备的工作也以同样方式到达云端，因此不再有只存在于 Host 上的项目工作。云端在某个项目中的第一个轮次会等待其克隆。克隆计入账户的监狱配额，并且只通过出口代理、使用账户自己的 Git 凭据访问 Git 主机。此次变更之前创建的云端副本留在 `.aeven-projects/<workspace id>` 中，同步的副本使用旁边带编号的目录。云端的环境文件不会传回，纯文件夹中的冲突在桌面设备上解决。

## 验证

`pnpm run typecheck` 与 `pnpm run build` 通过。在线检查在一个仓库工作区中运行一个云端轮次：仓库到达账户的 `.aeven-projects`，在那里做出的修改会在桌面设备下一次轮次之前出现在同一个检出中，监狱的进程列表显示 Git 以受限方式运行。
