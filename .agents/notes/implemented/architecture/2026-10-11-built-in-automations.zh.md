# Agent Note: 内置本地自动任务

Status: implemented

[English](2026-10-11-built-in-automations.md) | 中文

## 问题

用户需要重复执行智能体工作，而无需管理插件、cron 表达式或保持源对话运行。计划必须在重启后保留，且不能悄然重放可能已经修改外部账户的工作。

## 决策

自动任务是 Web 组合中的默认产品能力。`/automations` 是位于普通输入框上方、可直接访问的宽版管理页面。创建及扩大任务使用对话批准；页面不增加独立创建表单。注册起始地址按键分派页面，因此自动任务和 Imagine 保持独立内容。管理 RPC 使用 `/automation-control`，与页面 URL 分开，桌面传输将该自有通道转发至运行中的 Host。操作控件高 30px，采用全圆角。

## 理由

会话内的 Schedule 将提醒送入运行中的对话，不拥有独立工作。这一职责保持不变。自动任务通过存储域持久保存任务定义和不可变的执行记录，并创建普通的新根会话执行工作。日期计算代码改编自 titanwings/dsh-automation 的提交 0d73a4e03639d4f63d0771ae4490e2718b7e7aa0，并保留 MIT 署名；其仅面向编码的执行器、仅面向工作区的界面及上游 API 假设未被复制。

## 考虑过的替代方案

现有的会话 Schedule 在运行中的对话内提供提醒，不拥有独立执行。复制上游执行器会将任务限制在编码工具，并绕过 Aeven 当前的账户和连接器集成。独立调度进程会重复现有 Host 和存储生命周期。

## 影响

确定性的执行身份和持久接纳水位防止清理历史后重放。重启先将已接纳执行记录同步至水位，再清理历史。版本 2 的存储域记录本地执行器身份，按账户限制已结束记录数量，始终保留活跃工作，并拒绝版本 1 数据。重启将未完成的工作标记为失败，因为外部操作可能已经发生。重叠和迟到的执行以已跳过记录显示。模型请求创建或扩大任务时需要普通批准。执行不继承会话批准授权，连接器写入防护仍然有效。管理工具从服务声明的依赖获取身份权限，不通过智能体上下文解析。工具注册同时属于服务和智能体生命周期。失败执行支持明确确认或关联重试；活跃工作期间禁止重试。正常结束的轮次显示为执行结束，而不是已验证成功。

## 验证

验证遵循用户要求：运行 TypeScript 和构建，不运行测试套件。浏览器检查验证 `/automations` 的直接访问与刷新、独立 Imagine 内容、宽版布局和 30px 圆角控件。用户批准的 Europe/Amsterdam 时区 13:00 新闻任务通过真实对话工具创建，并在管理页面读回。这验证管理与持久保存，不证明次日定时执行或每项外部操作。托管执行、外部通知投递、持久批准续执行及操作系统启动管理仍未实现。
