# Agent Note: 设置界面以色块构成，验证器挑战是认证界面的一步

Status: implemented

[English](2026-10-16-settings-surfaces-are-fills-and-the-challenge-is-an-auth-screen.md) | 中文

## Problem

Account、Voice 与 Personalization 三个设置页彼此渐行渐远，也偏离了产品其他界面的语言：它们用描边表达边界。Account 页把双重验证行放在一个带边框的卡片里，方案卡片中"推荐"的那张带 1px 黑色描边，Personalization 的语音选项是带单选圆圈的卡片、输入框也带边框。这些页面打开的双重验证设置步骤更糟：`MfaForm` 渲染的是一张居中卡片——410px 宽、24px 圆角、自带徽标方块、23px 标题压在 208px 二维码上——而它所在的设置页其他行都是发丝线单元格。表单样式表还引用了本主题未定义的旧 token（`--dsw-alias-background-primary`、`--dsw-alias-border-primary`、`--dsw-alias-status-danger`），因此它一直画的是自己带下来的回退色值。

登录时的挑战步骤则是另一个方向上的同一个问题：`MfaForm` 的 login 模式在认证界面上画的还是那张卡片，所以第二因素步骤与上一屏的邮箱验证码步骤毫无相似之处——宽度不同、标题字号不同、只有一个文本框而不是六格验证码输入、失败信息写在行内而不是像认证界面那样弹出提示框。

## Decision

设置界面用色块而非线条表达边界。调色板是本主题的 `--dsw-alias-bg-module-platform`（安静的底）、白色（位于其上的内容）与 `--dsw-alias-button-primary-fill`（一组里唯一的行动召唤）。Account 页的保护行与身份行一样是普通单元格；方案卡片是填充方块，靠色调承担重点（推荐方案即填充的那张，内容反白），其操作按钮是白色胶囊；额度金额选择器保留模块色轨道上抬起的白色分段。Personalization 的语音选择器是一叠填充选项，被选中的那张是黑色，没有单选圈，输入框坐在模块色底上、没有边框。Voice 页是每个识别器一张填充卡片，标题用该识别器自己的名字，取分组标题的字号。

`MfaForm` 保留一套流程、两种呈现。`layout: 'cells'`（设置）不画自己的外框——宿主行已经写明功能并携带状态——步骤文案左对齐，注册二维码与输入区并排。`layout: 'card'`（默认）是注册、登录与命名界面显示的形式。样式表不再带回退色值，改用本主题定义的别名，两种呈现因而使用同一批 token。

登录挑战不再由 `MfaForm` 渲染。`Authenticate.tsx` 把它作为邮箱验证码步骤旁边的一步来渲染：同一个面板、同一套标题字号、验证码输入、说明行与按钮行，以及同一个"验证码被拒"提示框。六个格子来自 `Input` 的 `inputNumbers` 分支，步骤的标签指向第一格。挑战只在说明行位置报告一种失败：服务端已接受的验证码已被消费，因此其后的资料读取失败由同一个按钮重试，绝不会被要求再提交一次验证码。因此 `MfaForm` 去掉了 `login` 模式及其文案联合类型中仅供挑战使用的键。

各设置界面的行分隔线均已移除——General、Appearance、Memory、Language、Permissions、Skills、Search engine 与 Integrations 的行只靠节奏分隔。标签页下划线、输入框边缘与焦点环保留：它们是控件，不是分隔线。

## Consequences

Account 页读起来是一页，而不是在单元格列表里塞进两张卡片；双重验证设置步骤延续页面本身，而不是在界面里再开一层界面。推荐方案无需描边就一目了然，登录挑战在形态上与邮箱验证码步骤已无差别，第二因素因此不需要用户重新学习。

代价：方案网格无法再用描边标出当前方案，只能靠色调与禁用的"当前方案"按钮来表达；比较四列价格时，读者读到的是填充而非轮廓。Account 页自身的发丝线消失后，各分组依赖该区段本就使用的 28px 分组间距。把挑战从 `MfaForm` 移出，意味着它的覆盖率转到认证界面的挂载测试——资料重试行为本就属于那里；`MfaForm` 剩下的模式由 Account 区段的测试覆盖。

## Alternatives considered

- **保留描边、只重做表单。** 否决：所有者的方向是设置界面使用这三种色调，而"卡片套卡片"的结构正是被指出的问题。
- **给 `MfaForm` 增加第三种 `layout`，用自身的 CSS 模仿认证界面的结构。** 否决："与邮箱验证码步骤完全一致"只有在两步由同一张样式表与同一批控件绘制时才成立；在第二张样式表里复制这套几何，任一侧移动就会走样。
- **让设置区段在 `MfaForm` 的逻辑旁边自行渲染注册界面。** 否决：挑战逻辑很微妙（已消费的验证码、拒绝映射、恢复码展示），第二份实现需要同样的测试。
- **把发丝线从菜单与标签页下划线一起去掉。** 否决：标签页下划线标示当前页，菜单分隔线对条目分组；两者都不是行分隔线。
