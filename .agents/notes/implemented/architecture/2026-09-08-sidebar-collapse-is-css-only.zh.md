# Agent Note: 侧栏折叠只用 CSS

Status: implemented

[English](2026-09-08-sidebar-collapse-is-css-only.md) | 中文

## 问题

侧栏折叠已经从 JavaScript 重建为 CSS 五次。每次重建都会删掉测量逻辑，而随后的每次改动又会放回去一部分——一个列求解器、一个 `ResizeObserver`、一个从 React 写到祖先元素上的宽度——因为仓库里没有任何东西陈述这条规则，也没有任何东西会在规则被破坏时失败。这个回归对现有的每一道门禁都不可见：单元车道 stub 了 `ResizeObserver` 与 `matchMedia`，浏览器车道断言的是 ARIA 与几何，而不是动画期间运行了什么，而且滑动变慢时它*仍然能用*。只有盯着侧栏移动的人才看得见，这就是它反复交付出去的原因。

本 harness 所对标的 Aeven 客户端，整件事只用一条声明完成：

```css
.sidebar { transition: width 0.4s cubic-bezier(0.23, 1, 0.32, 1); }
```

一个 class 变化，该列做动画，没有 JavaScript 运行。这就是目标，本 harness 被要求与它完全一致。

## 决策

**侧栏做动画期间，不运行任何 JavaScript。** 折叠是侧栏列上的一次 class 变化加一次 CSS `width` 过渡。在滑动持续期间，不测量任何盒子、不发布任何宽度、不调度任何帧、不响应任何 resize。

由此得出三条规则，每一条约束的都是不得存在的代码，而不是必须存在的代码：

**任何宽度随侧栏变化的元素都不得被观察。** `ResizeObserver` 没有轴过滤：观察一个会被滑动改变尺寸的盒子，就会在每个动画帧被调用一次，无论其回调随后决定跳过什么。在回调内部忽略宽度不算达标——回调被调用本身就是违规，因为那正是下一次改动会在里面重新长出工作的地方。需要高度的观察者，应当观察一个宽度不会被滑动改变的盒子。

**toggle 不得触发 React 渲染。** 折叠状态以 class 或 data 属性的形式抵达 DOM。一次会重渲染框架的存储更新，会连带重渲染它下方的会话，那是一次挡在点击与第一个动画帧之间的同步 transcript（文本记录）渲染。

**不得从 JavaScript 发布宽度。** 列宽由需要它的元素在 CSS 中读取（框架中间列上的 `100cqi`）。在 transcript 的祖先元素上写一个可继承的自定义属性，会让其下每一个元素的样式失效，每帧一次。

窄视口断点仍留在 `matchMedia`，那不是测量：它在越过边界时投递一个事件，在列做动画期间保持沉默。

## 撰写本 note 时的实测状态

滑动本身是流畅的，帧中位数 8ms，但存在两处违规：

一次折叠在 376ms 内触发了 135 次 `ResizeObserver` 回调——`composerSeat` 上 90 次，`scrollBody` 上 45 次，两者都被 `ConversationRoot` 的 seat 观察者观察。被观察的 seat 高度全程恒为 165px，而它的宽度从 1440 变到 1695。这些回调没有做布局，因为该观察者与 `ChatView` 的观察者都带有仅高度保护，会在读取几何之前返回，而滑动期间实测的样式写入次数为零。保护是生效的，观察者依然在运行：上面那条规则针对的是调用本身，不是回调内部的工作量。

toggle 点击在过渡的第一帧之前花掉一次 56ms 长任务，因此动画以一次掉帧开始，之后运行干净。

## 落实

这里已经失效过的东西正是 note 本身，四次。这条规则需要一个测试：在折叠期间只要 `ResizeObserver` 被调用就失败——在启动前装一个计数包装层，触发折叠，把过渡驱动到结束，断言调用次数为零。它属于浏览器车道，因为这个违规只存在于真实的布局引擎中——jsdom 既不实现 `ResizeObserver` 也不实现过渡，这恰恰是现有的每一个测试对它视而不见的原因。

## 备选方案

**保护回调，而不是保护观察行为。** 这正是代码现在的做法，上面的实测就是它换来的结果：135 次正确地什么都不做的调用。它并不稳定，因为该保护的正确性会被每一次想从回调里多取一项事实的改动重新讨论一遍，而弄错的代价在有人盯着动画看之前都是不可见的。

**保留列求解器，把它做得更便宜。** 反复否决。任何用 JavaScript 响应 resize 的做法都按动画节奏运行，因此代价是逐帧的，并随 transcript 规模增长；CSS 引擎本来就不需要帮助即可为宽度做动画。

**把列宽发布为自定义属性供会话读取。** 否决，因为该属性必须位于 transcript 的祖先元素上，于是每次写入都会让整棵子树的样式失效——这正是 `100cqi` 容器查询所取代的那个具体错误。

## 影响

任何想要实时测量某个会被侧栏改变尺寸的盒子的需求都无法得到满足，只能在 CSS 中推导，或接受一个在滑动结束后才更新的值。这就是代价，也正是要点：这条约束正是让动画留在 CSS 引擎帧预算内、而不是落入 transcript 帧预算的原因。

composer seat 目前处于被观察状态，且它的宽度确实随滑动变化，因此满足第一条规则意味着要么把 seat 移入一个宽度稳定的盒子，要么在不观察它的前提下取得它的高度。在那之前，本 note 描述的是一条代码尚未满足的规则，而上面那个落实测试正是把这个缺口从记忆变成失败的手段。
