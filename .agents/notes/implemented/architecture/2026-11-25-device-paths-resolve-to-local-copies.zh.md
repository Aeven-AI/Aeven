# Agent Note：另一台设备记录的路径解析到本机副本

Status: implemented

[English](2026-11-25-device-paths-resolve-to-local-copies.md) | 中文

## 问题

会话以运行它的设备上的绝对路径指称其文件：产出文件、回复图片、正文链接，以及客户端要求资源管理器打开的文件。2026-11-25，桌面会话 `session-45df5e4a…` 创建了 `~/Documents/Aeven/vase-reassembly`，在 chat.aeven.io 上点击其中的 `index.html` 却毫无反应，尽管 pink 上存有包含所有文件的同步文件夹。每个 Host 入口各自解析客户端路径：只有 `/api/workspace-file` 字节路由会把另一台设备 Aeven 文件夹内的路径映射到本机副本；资源管理器在打开文件前调用的 `workspaceFiles.read` 在 pink 上解析 `/Users/Mac/...`，什么也没找到。位于桌面上会话项目根之下的路径在任何地方都没有映射，尽管工作区同步在 pink 的 `.aeven-projects/<id>` 中保留着该项目的副本。而在设置了托管根的 Host 上，项目文件只在其会话于该处运行轮次时才到达，因此只在桌面运行过的项目根本不在 pink 上。每个症状都在出现的地方被单独修补。

## 决定

- `@aeven/api-workspace-files` 按会话通过同一处解析每个客户端路径：其在本机的工作区根、其账户，以及其日志记录过的每个根。`toLocal` 把另一台设备记录的根替换为本机的根；读取与文件路由随后对位于任一设备 Aeven 文件夹内的路径使用账户的 Aeven 文件夹副本。列表、预览、文件路由、`sidebar_files` 与资源管理器写入都经过它。
- `workingDirectory` 投影保留 `roots`：`session/cwd` 事件记录过的每个根。连同头部的 `cwd`，它为在设备间移动过的会话指出每台设备的根。
- `WorkspaceRegistry.wantSessionFiles` 发出 `workspace/session-files-wanted`。打开资源管理器以及任何未找到内容的读取都会调用它，受 `arrivalWaitMs` 限制。工作区文件同步像为轮次那样响应；工作区 Git 同步获取仓库并应用另一台设备检查点记录的较新工作，除非该仓库的某个轮次正在此处运行。对仍在到达的文件的读取通过现有的 `fs/pre-read` 队列等待它们。

## 考虑过的替代方案

- **症状出现在哪个入口就修补哪个。** 否决：字节路由与文本读取正是这样变得不一致的。
- **向运行该会话的设备逐个请求文件。** 暂时否决：会话交接只通过账户收件箱单向转发输入，没有请求-响应通道，而且该设备关机时文件仍不可用，这正是文件同步要避免的。
- **只映射最新记录的根。** 否决：先在一台桌面、再在云端、再在另一台桌面运行的会话会在三个根之下指称文件。

## 影响

无论哪台设备写下文件，会话的文件都能在任何持有副本的设备上打开。在托管 Host 上首次打开某项目的资源管理器会开始传输该项目，传输可能很大；读取最多等待 `arrivalWaitMs`，传输会继续。位于所有记录的根与 Aeven 文件夹之外的路径仍按原样解析，因此不在任何同步副本上的文件报告为缺失。
