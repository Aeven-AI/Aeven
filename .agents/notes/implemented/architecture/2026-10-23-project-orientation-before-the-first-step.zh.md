# Agent Note: 第一步之前的项目概览

Status: implemented

[English](2026-10-23-project-orientation-before-the-first-step.md) | 中文

## 问题

归档在某个项目文件夹中的会话开始时，模型只知道该文件夹的路径，别的什么都不知道。`agent-instructions` 说明如何在项目中工作——读它的文件、跟随引用——但没有说明这个项目是什么，因此「这个该怎么部署」这类问题会从网上回答，而不是依据工作目录里的部署文件。用户必须在第一个有用的回答之前先说明会话位于哪个文件夹。

## 决策

`@aeven/project-context` 预先挂载一个 `agent/pre-step` 监听器：它先委派，再向进入的步骤追加一条 `UserMessage`，因此模型可见的概览与记录下来的日志是同一个事件，回放、恢复或重新推导请求时读到的都是模型当时读到的文本。当该步骤自身的决定已经带有本插件的消息时不追加；当会话的可见表层已经持有一条时不追加；表层扫描读取的是持久事件，因此恢复的会话与被压缩过的会话都只保留一个注入点。

该消息把会话工作目录指明为此人自己的项目，并要求在搜索网络之前先读它的 README、文档与代码来回答关于该项目的问题。随后它携带项目 README 的摘要——去掉前言块、围栏代码、标题、图片、HTML、表格以及语言切换行之类的纯链接行之后的开头正文，截断到 `maxSummaryLength` 个码点——以及顶层列表，目录以结尾的 `/` 标出，点开头的条目与 `ignoredEntries` 中的条目被略去。挂载了 `ctx.workspaceRegistry` 时，它还会列出会话所有者其他的文件夹工作区，筛选条件为 `kind: 'folder'`、路径已定义、路径不是当前工作目录，且属于本会话的所有者。仓库控制的文本会被转义，因此 README 无法关闭 `<project_context>` 框架。

读取经由可选的 `ctx.fs` 提供方：`resolve`、`stat`、`readBytes` 与 `listDir` 组成该消息，而没有该提供方的组合会把本插件挂载为空操作。没有工作目录的会话不产生消息；工作目录 `stat` 结果不是目录的会话同样不产生消息。

## 考虑过的替代方案

**扩展 `agent-instructions` 而不新增包。**该包说明如何在该文件夹中工作，这是任何组合都需要的，与具体项目无关；概览说明项目是什么，并需要文件系统、README 与工作区注册表，因此它拥有独立的监听器与独立的挂载点。

**把概览作为系统提示词段落投递。**提示词段落会在每次请求时重新计算，并且需要自己「模型可见且被记录」的规则；一条带显式来源的持久用户消息只记录一次，由回放与恢复复用，并携带模型当时读到的同一文本。

**等提问需要时再让模型读取该文件夹。**只凭会话路径作答的模型会用通用知识描述托管与部署，而不是依据与之并存的部署文件；只有明确点名某个文件的问题才会把它们带到该文件夹。

## 后果

- 每个会话只有一条消息，采用追加而不是替换此前的 token，因此请求前缀只增长一次，后续步骤复用它；它留在 transcript（文本记录）中，直到压缩将其遮蔽。
- 摘要只取 README 正文，因此 README 以标题、徽章与代码开头的项目只能得到很短的摘要甚至没有摘要，而没有 README 的项目只会得到列表与那条指令。
- 列表只有一层：嵌套的 package、服务器或网站会被点名，但不会被描述。
- 没有 `ctx.fs` 的组合不产生任何内容，这也是让无提供方的产品不受影响的挂载方式；没有工作目录的会话（例如个人聊天）同样什么都收不到。
- 只有在挂载了 `ctx.workspaceRegistry` 时才会列出其他项目文件夹，且只有会话所有者自己的文件夹工作区符合条件。
- `packages/context/project-context/tests` 固定了第一步之前带来源归属的注入、表层与步骤已持有时不产生第二条消息的规则、被拒绝与已中止的 pre-step 路径、README 摘要提取、顶层列表、相关项目筛选以及配置默认值。
