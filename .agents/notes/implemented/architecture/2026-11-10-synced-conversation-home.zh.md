# Agent Note：同步对话留在运行其最近一回合的始终在线设备上

Status: implemented

[English](2026-11-10-synced-conversation-home.md) | 中文

## 问题

同步账户的对话没有归属设备。回合运行期间，其他设备把输入转发给正在运行它的设备；对话一旦空闲，用户在哪台设备上输入，哪台设备就认领它并运行下一回合。2026-11-10，一个托管对话在 Aeven Cloud 的账户文件夹中启动了 `pnpm install`，用户在 Mac 桌面应用中输入的下一条消息在 Mac 上运行，而那里既没有克隆的仓库也没有该后台任务。文件、后台任务和沙箱状态都留在创建它们的设备上。

这是[由哪台设备运行同步对话的提议计划](../../proposed/architecture/2026-11-10-synced-conversation-runner.zh.md)的第 1 阶段。

## 决策

最近一回合在始终在线设备（例如 Aeven Cloud）上运行的对话，在该设备有响应时留在它上面。

- `avn-sync-yjs` 在账户的同步设备列表中把设置了 `keepConnected` 的设备标记为 `alwaysOn`。只有托管 Aeven 设置 `keepConnected`。
- `avn-session-sync` 在会话索引条目中记录运行最近一回合的设备（`writer`）：包含 `turn/start` 的已发布后缀把它设为发布设备，其他发布（例如重命名或选择模型）保留原值。
- 当该设备始终在线且不是发出询问的设备时，`ctx.sessionHandoff.homeOf(owner, sessionId)` 指出它。
- `avn-session-controller` 对这样的对话，把开启回合的输入（提示、编辑、重试）通过同步收件箱转发，而不是认领该对话。
- 收件箱把转发输入的优先处理权交给始终在线的编写设备，否则交给输入所在的设备。第一台设备在 `inputGraceMs`（3 秒）内没有接手时，任何设备都可以认领并运行它，因此输入从不阻塞；运行它的设备成为该对话的编写设备。
- 设备从收件箱应用的输入在该设备上运行；控制器不会再次转发它。
- 为重命名或选择模型而取得的认领持有中继的运行者租约，而以前只有回合结束才会释放它。`ctx.sessionHandoff.endChange` 在变更应用完毕且没有回合运行时交还租约，让始终在线的归属设备能立即接手下一回合。

### 兼容性

会话事件类型、会话日志格式、流批次格式和 `SESSION_FORMAT_VERSION` 都没有变化，因此本变更前后的构建读取相同的历史。两个新字段是同步映射中的可选成员：不认识它们的构建会忽略它们，缺少 `writer` 的对话行为如前；旧构建发布对话时会在不含 `writer` 的情况下重建其索引条目，使该对话回到以前的行为，直到更新后的设备运行一个回合。旧桌面设备不知道这条规则，因此会继续认领在其上输入的对话。

## 考虑过的替代方案

记录最近发布任何事件的设备被否决：在 Mac 上重命名会把云端对话移到 Mac 上。

修改 `holdRunner(false)` 以释放没有回合的认领所持的租约被否决：会话同步插件在每次智能体状态变化时都会调用它，因此可能在认领与该认领所为的回合之间丢掉租约。`endChange` 只在变更之后调用。

在任何认领没有回合运行时释放运行者租约，因同样的原因被否决；租约仍然守护认领与其回合之间的窗口。

## 影响

托管对话在用户于另一台设备上输入时保留其文件、后台任务和沙箱，这修复了 2026-11-10 的故障。

云端对话目前还不能被有意移到桌面设备上；"在这台电脑上继续"操作是计划的第 2 阶段。当 Aeven Cloud 没有响应时（例如部署期间），在桌面设备上输入的内容会在输入宽限时间后在那里运行，之后对话留在该桌面设备上。

由于还没有设备发布存活状态，该规则只把始终在线设备视为无需在线状态即可连接；桌面设备在第 3 阶段获得存活状态。

## 验证

在本地环境上（Aeven API 和同步中继分别在 9000 和 9010 端口，两台从本分支启动的 Host 登录同一账户，其中一台设置了 `keepConnected`）：
- 在普通 Host 上、于始终在线 Host 最近运行过的对话中输入的消息，在始终在线 Host 上运行；
- 始终在线 Host 停止时，在普通 Host 上输入的消息在输入宽限时间后在普通 Host 上运行；
- 在普通 Host 上重命名之后，其下一条消息仍在始终在线 Host 上运行，索引仍把该 Host 记为编写设备；
- 之后在始终在线 Host 停止时发送的新消息，约三秒后在普通 Host 上运行。

停止 Host 和重命名两种情况第一次运行时失败，由此发现了上文修复的重复转发循环和被持有的租约。两个镜像的内存运行也确认了：没有 `writer` 的索引条目以及不始终在线的编写设备都不会产生归属设备。类型检查和构建通过。未在同一中继上运行旧桌面设备。
