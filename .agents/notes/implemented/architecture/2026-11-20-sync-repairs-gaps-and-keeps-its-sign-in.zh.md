# Agent Note：同步会修复卡在丢失更新之后的副本，并保持登录直到退出登录

Status: implemented

[English](2026-11-20-sync-repairs-gaps-and-keeps-its-sign-in.md) | 中文

## 问题

一台桌面设备始终看不到云端 Host 创建的一个 Bot，也看不到云端 Host 在 11 月 11 日和 19 日做的三次删除，而桌面设备自己的更改却能到达云端 Host。桌面设备上账户 `automations` 文档的副本把云端 Host 之后的更新作为 Yjs 待处理结构保存：它们依赖一条桌面设备从未收到的更新。有两个机制让这种状态无法恢复：

- `SyncStore.isNewCounter` 是一个高水位标记。发送方计数器不高于该发送方已见过最高计数器的帧会被当作重放丢弃，即使它只是晚到（经由本地网络连接或在中转积压中排在更晚的帧之后），其内容也从未被应用。
- 快照的 `covers` 会让中转服务器删除该文档在该序号之前的所有帧，包括其他设备的帧。有缺口的副本照样生成快照，于是中转服务器删除了携带缺失更新的帧，只有它的写入方还持有它。

另外，同步使用客户端最后一次向 Host 出示的访问令牌进行认证，这是一个内存中的会话值。访问令牌寿命很短，而登录依赖一年期的刷新 Cookie，因此应用一直显示已登录，中转服务器却每五秒拒绝一次该令牌，只在调试级别记录。设置了 `keepConnected` 的 Host 为此持有同步授权，但一个可解析却被拒绝的令牌总是优先于授权。

## 决策

- 计数器不高于高水位标记的帧，只要其更新超出已存储副本的状态向量（`addsTo`）就会被应用；最近计数器的记忆会跳过真正的重复帧而无需检查。分片的晚到帧仍被丢弃，依靠修复补齐。
- 维护会报告每个写入方第一个缺失的时钟（`compactWithMissing`），存在缺失时不排队快照。
- 有缺失时钟的副本向账户的 `sync/repair` 文档写入 `{ doc, device, missing, at }`，副本完整后删除。存储该文档的每台设备对每个请求只回应一次：执行 `reconcileOnce` 每个存储执行一次的 `docs.get` 比较，发布中转服务器副本缺少的内容。丢失更新的写入方总是持有它，因此无需修改中转服务器副本就能恢复。
- 中转服务器（servers/node `fix/sync-grant-bound-to-session`）把授权绑定到请求它的访问令牌背后的登录会话，并且只在该会话存在时兑现。退出登录会删除会话，因此退出登录会结束授权，其他情况都不会。
- 每个 Host 都取得授权，而不只是设置了 `keepConnected` 的 Host；`keepConnected` 现在只标记常开 Host。被拒绝的访问令牌不会再次出示；授权作为后备；没有可用凭据时状态带有 `error: 'sign-in'`，并在“设置 → 同步”中显示。

## 考虑过的替代方案

- **用已见计数器集合取代高水位标记。** 不采用：该集合会按发送方和文档无限增长，而内容比较正好回答真正的问题。
- **让卡住的设备重新获取文档的帧。** 单独不够：它需要的帧可能已从中转服务器删除；只有持有该更新的设备能够提供。
- **在 Host 上用镜像的刷新 Cookie 刷新访问令牌。** 暂缓：授权已经给了 Host 一个只有退出登录才会结束的凭据。

## 影响

- 卡住的设备和一台持有缺失更新的设备都运行此版本后，缺口即可恢复；中转服务器的修改必须在 Host 取得授权之前部署，否则旧中转服务器签发的授权不会绑定会话。
- 本次修改之前签发的授权不带会话，在过期或被撤销之前仍会被接受。
- 从未打开或维护的副本，在发生其中之一之前不会发现自己的缺口。
