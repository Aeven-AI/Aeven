# Agent Note：Web 界面陈述自己渲染什么，并提供回复所引用的文件

Status: implemented

[English](2026-08-28-web-surface-render-capabilities-and-workspace-files.md) | 中文

## 问题

Web GUI 中的助手回复经由 `MarkdownText` 渲染：它把 ` ```mermaid ` 围栏画成图表，渲染 KaTeX 数学公式，并从绝对 `http`/`https` URL 显示 `![alt](url)` 图片。然而没有任何面向模型的文本说明这一点。`app:web-surface` 提示词分节描述的是服务器、HMR 与重新构建，且开篇即为「浏览器不提供隐式的 DOM、路由或截图上下文」—— 读起来就像一个完全不具备渲染能力的界面。

一个没有得到输出界面说明的模型只能猜测，且每次运行的猜测都不相同。已记录的会话显示了两个方向的失败。被要求画图时，某次会话转而调用 `cordis_define` 去构建 Client 插件，因为 Cordis 分节的路由规则会认领「所请求结果是视觉性的」工作，而没有任何文本指出更省事的路径。被要求显示图片时，某次会话下载了文件、报出文件系统路径，并声称「我无法把图片内联进聊天文本本身 —— GUI 的消息渲染器不会嵌入回复中的图片内容」。在同一次会话的后续，它读过渲染器后自我纠正，输出了 `![dog](https://…)`，并成功渲染。能力从未改变，改变的只是模型对能力的判断。

图片这一例还有真实存在的另一半。Agent 生成的文件没有 URL，而渲染器拒绝文件系统路径与 `data:` URI，因此仅靠正确的指令无法让生成的文件可见。一次已记录的会话通过在 8787 端口启动一个用完即弃的静态服务器、并引用 `http://127.0.0.1:8787/weather.png` 解决了它。

## 决策

**界面提示词陈述该界面渲染什么。** `webSurfacePrompt` 现在说明：回复以 GFM 渲染，mermaid 围栏成为图表，数学公式经 KaTeX 渲染，图片从绝对 `http`/`https` URL 显示而文件系统路径与 `data:` URI 会被拒绝，并且模型绝不可声称自己无法内联显示图片或图表。`WEB_SURFACE` 分节是正确的归属地，因为这是界面的属性而非 Agent 的属性：它仅在 `avn web` 下挂载，因此该陈述在 CLI 上不存在 —— 那里这些都不会渲染。

这刻意不采用 Agent 预设的 persona 规则。persona 会随 Agent 进入该陈述不成立的界面；而为承载一句话去 fork 一个随发行的预设，会使此后每一次上游预设变更都变成手工合并。

**`avn-host-workspace-files` 为生成的文件提供 URL。** 一条经过认证的前缀路由从工作区的规范目录提供 `<mount>/<workspaceId>/<相对路径>`。`ctx.connection.requestRejection` 在任何路径处理之前运行，因此未认证的调用方无法区分真实工作区 id 与编造的 id。越出目录的穿越返回 403，未知 id 与文件缺失都返回空的 404，非 GET/HEAD 返回 405。

**整目录暴露是有意为之。** 持有浏览器会话者可读取工作区下的每个文件。更窄的发布子树曾被考虑并暂时否决：它要求 Agent 把产物复制进发布目录，而这正是模型会遗忘的步骤，且失败是静默的 —— 得到的是坏掉的图片而非报错。无法接受该暴露面的部署应移除该行，并同时移除提示词中关于工作区 URL 的那句话。

## 验证

该包的真实编排测试通过 Loader 启动 webserver、Connection、桩注册表与该行，随后针对所提供的 HTTP 界面断言：对真实 id 与编造 id 都在任何路径处理之前返回 401、内容类型与安全响应头、被重写的文件重新提供、未知 id／文件缺失／目录一律 404、POST 返回 405，以及条目销毁时释放路由。

穿越覆盖记录了两阶段规范化。朴素的 `../` 永远到不了该路由 —— `new URL()` 会折叠它，留下一个指向未注册 id 的路径 —— 因此针对它的断言是 404。经过编码的斜杠（`..%2f`、`%2e%2e%2f`）能越过 URL 解析，并且只有在处理器解码 pathname 之后才成为 `..` 片段；这些正是解析前缀检查以 403 拒绝的请求，也正是它们证明该围栏确实在承担作用。

界面提示词的完整文本在 `web-app.spec.ts` 中按字节固定，比对的固件与 Web e2e 冒烟测试所用的是同一份，因此绕过该固件的措辞改动会在 `pnpm run test` 中失败，而不只在需要密钥的 e2e 中失败。

## 影响

Web 界面提示词增加了一个段落，因此每个 Web 会话的系统提示词都会改变，其前缀缓存在升级时会失效一次。

`avn web` 现在会向已认证的浏览器会话暴露工作区内容。这确实扩大了泄漏的会话 cookie 所能触及的范围，也正因如此，暴露面那一段写在包 README 中，而不只写在本 Note 里。

提示词中的工作区 URL 语句与 `workspace-files` 行是一个整体：移除该行却保留该语句，会让模型构造出返回 404 的 URL。两者都位于 `packages/bundle/web-app`，README 中陈述了这一配对关系。

若模型仍为生成的图片报出文件系统路径，或拒绝绘制图表，现在这属于提示词遵循失败，且有按字节固定的期望文本可供比对，而不再是模型只能靠推断的未言明能力。

## 考虑过的替代方案

**persona 或用户预设规则。** 作为永久修复被否决：作用域错误（它会跟随 Agent 进入该陈述不成立的界面），且为承载一项部署事实而 fork 随发行的预设。它仍是合理的本地权宜之计，前提是措辞点明绝对 `http`/`https` URL —— 只说「以 markdown 图片链接回复」的指令会产出自信的 `![dog](/Users/…/dog.jpg)`，而它静默地不渲染。

**在 `LINK_SAFETY` 中启用 `data:` 图片 URI。** 一行即可，无需服务端工作，但被否决：回复中的 base64 属于模型可见内容，而「模型可见即入日志」的规则会把每一张显示过的图片持久化进会话日志。

**保留临时静态服务器。** 被否决：如已记录的会话所示它确实可行，但它耗费一个回合、泄漏一个进程、占用未受管理的端口，且不带认证地对外提供文件。

**改为收窄 Cordis 分节的视觉触发条件。** 单独做不够。它能阻止画图时的绕路，却没有告诉模型改做什么，而且完全触及不到图片那一例。
