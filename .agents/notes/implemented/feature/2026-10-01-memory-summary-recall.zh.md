# Agent Note: 自动召回使用轨迹摘要

Status: implemented

[English](2026-10-01-memory-summary-recall.md) | 中文

## Problem

复制的助手回答和工具记录占用自动召回空间。历史细节使记住的偏好或经验更难辨认。

## Decision

MemOS 提供方在所有轨迹领域的 `turn-start` 召回中使用已存储的轨迹摘要。摘要中已有的结果标签仍然可见。显式搜索对所有领域都返回展开的轨迹，包括摘要所提炼的原始消息（[细节](../bug-fix/2026-10-01-recall-returns-the-captured-message.zh.md)），轨迹读取保留存储的细节。缺少摘要时保留候选片段；非轨迹候选保持现有表示。不引入新的摘要生成器、存储格式、限制或工具约束。

这部分取代了[记忆路线图](../../proposed/feature/2026-09-28-long-term-memory-roadmap.zh.md)中的自动工件投递，其其他决策仍然有效。[提供方基础](2026-09-28-long-term-memory-memos.zh.md)保留其独立范围。召回块每轮投递一次：在每个后续请求前再次附加该块的做法被否决，且没有测量对两者进行比较。

## Alternatives considered

- 展开的自动片段保留即时细节，但会在每个召回块中重复历史回答。
- 在每个后续请求前附加该块可使文本靠近动作，代价是每请求多一份副本并随步骤数增长，且没有测量显示它改变代理的行为。
- 新生成的经验需要额外模型调用和持久化表示；现有摘要支持最小改动。

## Consequences

自动轨迹召回突出记住的摘要，而技术细节需要显式检索。现有工具输出限制可能截断这些细节；此改动不提供分页。存储的摘要可能遗漏有用事实，更清晰的投递也不保证遵循。

## Verification

TypeScript 检查和完整构建通过。针对重新构建的服务器进行的 Chrome 实机测试覆盖两个已完成轮次，每轮投递一个召回块。两个相同轨迹条目分别为 148 和 166 个字符，而较早轨迹中为 1,015 和 1,024 个字符。自动块包含摘要和结果标签，没有附加助手回答或工具记录。代理识别了仅解释的偏好，并执行两次请求的读取。`memory_get` 返回原始回答标题和摘录，由其现有输出限制截断。这些观察确认了投递和观察到的偏好应用，并未证明总 token 节省或普遍遵循。没有运行自动化行为测试套件。
