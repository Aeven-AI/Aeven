# Agent Note: 通行密钥登录并同时解锁同步数据

Status: implemented

[English](2026-11-17-passkey-sign-in.md) | 中文

## 问题

保护账户同步数据的通行密钥无法用于登录账户。通行密钥页面只保留 PRF 输出和凭据 ID，它的挑战值在浏览器中生成，Aeven 服务器也不保存任何公钥，因此没有可用来验证断言的依据。受保护账户的读者先用邮箱或提供方登录，然后还要再触碰一次通行密钥来解锁设备。

## 决定

- **持有同步密钥的通行密钥同时用于登录。** 创建通行密钥的步骤（`protect`、`add`）会让页面描述新的通行密钥（`meta=1`）。页面返回 PRF 输出，后接 `{ id, publicKey, alg, aaguid, device }`；设备随 `key.protect` 或 `passkey.add` 发送 `signIn: { publicKey, alg }`。中转服务器把它保存在 `passkey_credentials` 中，以凭据 ID 和账户为键。通行密钥只在持有账户密钥期间可以登录：`passkey.remove` 和 `key.unprotect` 也会删除它的登录公钥。页面把账户已有的通行密钥列入 `excludeCredentials`，因此已持有其中一个的提供方会拒绝再创建一个，而不是替换它；密码管理器以账户邮箱命名新通行密钥，邮箱由账户 → 安全传入，因为 Host 身份只带有账户 ID。
- **先填邮箱。** “使用通行密钥登录”位于“使用邮箱登录”下方。读者输入邮箱，`/passkey/lookup` 告知该账户是否有可登录的通行密钥，之后才打开通行密钥页面；`/oauth/passkey/check` 以 `other-account` 拒绝其他账户的通行密钥。桌面外壳在匹配登录地址时把各个 loopback 主机名视为同一个，因为 Host 按页面到达时使用的名称向页面给出 loopback URL。
- **登录像提供方一样在 Aeven 网站上进行。** `/oauth/passkey` 提供一个带有服务器签发、一次性挑战值的页面。页面在要求用户验证的前提下请求该网站的任意通行密钥，把断言提交到 `/oauth/passkey/check`，并跟随响应给出的 URL。服务器用 Node 的 crypto 根据保存的 SubjectPublicKeyInfo 公钥验证签名，因此不引入 WebAuthn 或 CBOR 依赖。验证通过的断言会创建会话和一次性的 `strong` 挑战，客户端像处理提供方登录一样通过 `/oauth-result` 兑换它。用户验证同时代表两个因素，因此 `strong` 兑换跳过身份验证器代码。桌面端和等待中的网页通过与提供方登录相同的交接方式收到结果（`finishedSignInUrl`）。
- **一次提示完成登录与解锁。** 登录界面在挂载时生成一次性的 X25519 密钥对和验证串，并传入 `#key=…&vault=…&salt=…`。页面在登录提示中计算 PRF，并把结果密封后以验证串的哈希为键存放到 `/passkey/vault/result`。登录后，设置 → 同步弹窗从读者的 `takePasskeyUnlock` 取得这对密钥并调用 `unlockFromSignIn`，只有设备仍处于锁定状态时才请求通行密钥。
- **常规登录保留。** 通行密钥按钮只是登录界面上新增的选项。此次变更之前创建的通行密钥仍可用于解锁。中转服务器为每个通行密钥标注 `signIn`，账户 → 安全在仅用于解锁的通行密钥上提供“用于登录”：`upgrade` 步骤以相同的用户句柄创建替代通行密钥，使持有旧通行密钥的提供方替换它，先添加新副本，之后才移除旧副本。账户始终不会两者皆无，本设备也始终持有账户密钥。PRF 盐值和通行密钥主机名都没有改变，因此每份已封装的密钥都仍能打开。

## 考虑过的替代方案

**通过已认证的 API 路由注册公钥。** 中转连接已经认证了账户，通行密钥的封装密钥也是从这里到达；在同一个请求中保存两者，可以避免为从未持有账户密钥的通行密钥留下登录公钥。

**使用 `@simplewebauthn/server`。** 浏览器以 SubjectPublicKeyInfo 形式提供新通行密钥的公钥（`getPublicKey()`），所以验证只需要对两个缓冲区做一次签名校验；该库会带来这里用不到的证明与 CBOR 处理。

**在登录前由 Host 发起解锁。** 同步 Remote 只为已登录的调用方执行操作。在页面中生成密钥对、登录后再交给 Host，可以让每个同步操作都留在账户自己的会话之后。

## 影响

受保护账户的读者只需触碰一次通行密钥即可登录并解锁设备，而服务器仍然从不持有未密封的 PRF 输出，只多保存了公钥。登录用的通行密钥只来自账户 → 安全，因此从不保护数据的账户没有通行密钥登录。

- 已持有账户某个通行密钥的提供方会拒绝第二个（`duplicate`）；读者把新通行密钥保存到另一个密码管理器或手机上。
- 每个通行密钥行都提供“移除”。移除多个中的一个只删除它的副本；移除唯一的通行密钥会在确认后关闭保护，由中转服务器重新保管密钥，任何设备都不会丢失数据。这些行只在已解锁的设备上显示。
- 恢复密钥是可选的、持有账户密钥的 28 个字符代码，只显示一次，并需要输入回来确认。
- 只在一个平台上可用的通行密钥（Mac 上的 iCloud 钥匙串）不会出现在另一个平台上（Android）；那台设备用常规登录，再用另一个通行密钥解锁。从另一台设备设置新设备是另外的工作。
