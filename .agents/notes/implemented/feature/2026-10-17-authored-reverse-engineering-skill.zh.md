# Agent Note: 逆向工程技能由本仓库撰写，并从设置页面安装

Status: implemented

[English](2026-10-17-authored-reverse-engineering-skill.md) | 中文

## 问题

Aeven 没有用于读取“拿不到源代码的软件”究竟如何工作的技能。面对某个已发布应用如何实现一项功能、一个二进制带着哪套工具链与哪些依赖、两次构建有何差异这类问题，会话每次都要临时重新决定路线：先判断格式，再取最省的信息清单，然后只切出能回答问题的那段代码。这项工作在每个目标上都一样，而做错的代价很高——把整份反汇编倒进上下文，并不能回答一次针对单个函数的 `rg` 就能回答的问题。

技能目录里提供的是一份第三方的指令文件。要有人在设置页面里找到它，它才会到达某个账户；它的命令面向另一套宿主环境；而重新分发它的文本，会在一个模型可见的文件里带上一条需要向读者交代的版权声明。

## 决策

技能本体是 `packages/skill/skill-catalog/authored/reverse-engineering/SKILL.md`，通过技能目录发行：设置页面把它列在 `reverse-engineering` 分类下，安装进已登录账户自己的库，也可以再次移除。[技能目录来源那条记录](../process/2026-10-17-skill-catalog-extra-sources.zh.md)负责说明本仓库的一个目录如何变成可安装的包。

技能是使用者看到的那一层，服务是它背后的引擎：一份可安装的指令文件，每条路线先点名一个 `rea` 工具，再给出服务缺席或某个提供方引擎缺失时顶上的 shell 命令。`packages/bundle/web-app/cordis.patch.yml` 通过 `@aeven/mcp-client` 把这个服务挂在两个浏览器服务旁边，因此每个 `mcp__rea__*` 工具都在 `tool_search` 之后等待，在工具索引里只占一行；正文的第一步就是为这个服务做一次 `tool_search`，而它的 shell 一列让没有 `npx` 的宿主照样能走完路线。

正文按制品类型给出路线——原生二进制、Go、Rust、.NET、Electron 与 JavaScript 目录树、APK、固件、Hermes 与 bytenode、WASM 与 EVM 字节码、SQLite、报文与网页捕获、核心转储、浏览器页面——其中只有一条路线必须由服务回答：单个函数的伪代码、调用者与被调用者。让结论可核查的规则写在路线旁边：证据标注为“已见”或“推断”，并给出文件偏移、符号或工具的 evidence id；在副本上操作；把多个探测合进一次 shell 调用；一次只读一个函数；并且读每条结果自己写明的限制，而不是替它抹平。静态阅读无法回答时，它把会话引向运行时观察；涉及屏幕或原生对话框时，引向 computer use。

另有一份同样由本仓库撰写的条目 `leanrea` 与它并列发行：那是没有挂载任何服务时的纯 shell 快速路径，规则相同，循环里没有服务。两者是不同的目录条目，因为同一个问题用了不同的工具来回答；安装其一不会带来另一个。

这个文件在本仓库中写成，面向 Aeven 自己的接口；它唯一带上的外部名字，是它所驱动的那个工具服务。

## 考虑过的替代方案

**把第三方技能文件改个名字内置进来。** MIT 允许这样复制，同时要求在副本中保留其版权声明，而这份模型可见的文件此后就要向读者交代这条声明；它的命令也假设了一套 Aeven 并不运行的宿主。在这里撰写正文的代价是要自己写，换来的是路线表只有一个负责人。

**在这里自己实现那些反编译桥接。** Hopper、Ghidra、IDA、JEB 与 Kuna 之间没有共同 API，因此一套原生分析层意味着五个适配器，以及一套要跟着五家厂商发行节奏维护的记录机制。该服务是 MIT 许可且上游仍在维护，所以本仓库把它当作依赖引入，而不是再写一个更差的版本。

**只挂服务，不发技能。** 那样，从不读取二进制的会话也要等一个子进程，而每条 shell 命令就能回答的格式都要多走一次分析服务的往返。把服务挂在技能旁边，便宜的路保持免费，昂贵的路在 `tool_search` 点名之前不可见。

**改为随预设提供的技能。** `aeven` 组合把 `presets/aeven/skills/` 挂进每个会话，因此预设技能常开，设置页面关不掉。让一个人决定某个会话是否携带逆向工程指令，正是这个技能必须保留的选择。

**把路线表拆成每种格式一份参考文件。** 按格式分文件能让单个文件更短，也让会话只读自己那种格式。可会话在知道格式之前需要的正是路线清单，拆分就要多一次调用去发现该读哪个文件，而一个没人打开第二次的技能省不下什么。

## 后果

在有人安装并加载它之前，这个技能不产生任何开销：目录把它提供给每个账户，而一次安装只把它的描述与指令带进该账户自己的会话。

挂载的服务在每个宿主上都会启动一个 Node 子进程，无论有没有会话读取二进制；无法访问 `npx` 的宿主会记下启动失败、保留它的目录条目，而技能的 shell 一列除伪代码与调用者之外仍能走完每条路线。

这些命令要由本仓库维护。工具参数会变——一个 `jadx` 模式、一个 `otool` 选项、一个 `tshark` 字段名——而上游没有任何东西会通知我们，因此过时的一行在这里修正，再由同步带进设置页面。

## 暂缓事项

没有任何东西把本仓库里的目录与它生成的包作比较。改写 `SKILL.md` 而不重新运行 `scripts/sync-skill-catalog.ts`，设置页面里留下的仍是上一次的文本，没有门禁会发现这一点，因为现有的目录检查都把包当作权威。要做这项比较就得依赖同步所用的 `zip` 工具链，而当前没有任何门禁依赖它。
