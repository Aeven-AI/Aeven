# Agent Note：列出此人早先的消息

Status: implemented

[English](2026-11-15-memory-list-messages.md) | 中文

## 问题

被问到“我问过的最蠢的 3 个问题是什么”时，Aeven 调用了四次 `memory_search`，共十六个查询，每次只得到二到四条无关结果，然后回答说记忆只保存摘要，不保存此人的问题。记忆其实保存了：每一轮的轨迹都逐字存有此人的消息，该用户的存储中约有 2,770 个对话轮次。`memory_search` 按嵌入相似度排序并设有分数下限，因此关于此人消息整体的问题（“蠢”“第一次”“每次”）匹配不到任何内容，也没有工具能按顺序遍历这些消息。

## 决策

`MemoryProvider.list` 接受 `turns: true`，按对话轮次分页，每轮一条记录，即该轮中存有此人消息的轨迹，`limit`、`offset` 和 `total` 都按轮次计数；MemOS 提供方将其映射到核心的 `groupByTurn` 列表。`MemoryRecord` 携带其 `origin`，与召回结果相同。`@aeven/tool-memory` 在其上注册 `memory_list`：来自会话可见的所有对话的此人消息，最新在前，每条带本地日期和轨迹 id，按 `offset` 分页并给出 `nextOffset`，页头写明该页的日期范围，同一天重复存储的同一条消息只列一次，可选字面文本过滤；除非设置 `includeSaved`，导入的事实和习得的流程不列出。工具描述告诉模型，关于此人长期以来问过什么的问题使用它，并在声称早先消息不可得之前先列出；`memory_search` 指向它。每页条数和消息长度是 `Config` 字段。

## 考虑过的替代方案

为“问题”调整的搜索查询仍按含义排序，无法遍历。此场景不采用挂载 `session_search`：它只搜索一个工作区，而每个托管对话都有自己的工作区。按日期范围过滤需要修改 vendored 核心；最新在前的分页满足同样的需要。

## 后果

列表遵循召回的可见性：其他工作区的项目记忆不列出。导入的事实和习得的流程仍计入 `total` 和分页边界，因此一页的消息可能少于 `limit`；页头说明省略了多少条。

## 验证

对记忆包运行 `tsc -b` 与 `pnpm run build` 通过；已重新生成 Cordis API 目录。桌面应用中的实测：在新对话中，原问题加载了 `memory_list`，逐页读取了 3,935 条中的 600 条消息，并以带日期的引用作答。同一次运行中，模型把已读范围估计为三个月，而页面日期只覆盖一周，并把重复捕获的消息列了两次；现在页头写明日期范围，重复消息被合并。
