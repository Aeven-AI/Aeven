# Agent Note: 搜索优先的 Web 指引与会话时钟

Status: implemented

[English](2026-10-01-search-first-web-guidance.md) | 中文

## 问题

随附的 `tool:web_search` 指引只陈述工具契约——参数上限、不可信数据提示、引用义务——没有说明何时必须从 Web 取得答案。于是会话用记忆回答时效性问题，并以确认工作区内事实时才使用的把握度呈现，而本可裁定这些问题的工具就闲置在 schema 里。

还有两个事实让这一缺口对模型不可见。没有任何已交付组合挂载 `@aeven/time-context`，会话因此看不到自己的知识有多旧——而这正是搜索决策所依据的唯一读数。`web_search` 的工具描述也只重复了契约文本，所以模型的工具列表里同样没有触发条件。

## 决策

`packages/web/tool-web/src/search.ts` 中的两个 `web_search` 指引变体都以同一段“搜索优先”开头：当答案可能在训练之后发生变化时先搜索——软件版本与发布、价格与可获得性、时事、日程、人物，以及文档或 API 行为——以及当模型只能猜测、含糊其辞，或断言工作区无法确认的事实时先搜索。其后是未改动的参数契约，再是该变体自身的收尾义务（用 `web_fetch` 读取页面，或使用返回的摘要片段）与引用规则。工具描述携带同一触发条件的简短形式，使该义务在读到 schema 的任何地方都可见。

该段落是包自有的模型可见文本，与它现在置于其前的契约、引用语句同属一体。它不作为 `tool-web` 的 Config 字段：这段文字是模型可见的义务，而非随部署变化的设置，而两个对它判断不同的部署在模型行为上是不同的，双方组合都无法显示这一点。

`aeven` preset 以 `refreshIntervalMs: 300000` 挂载 `@aeven/time-context`。该 preset 上的会话至少每五分钟读到一次带数字偏移与 IANA 时区的 ISO 时间戳、本次请求的浏览器时区，以及已流逝时间；该间隔抑制了快速工具循环本会逐步骤付出的注入。

两者都不是强制。会话仍可用记忆作答，工具流水线中也没有任何环节检查某条事实性陈述是否经过搜索。

本记录只负责模型可见的策略文本与时钟配置项。[已交付组合中的默认 Web 搜索](2026-07-31-web-default-search.zh.md)与[共享 base 的 Web 抓取默认值](2026-09-01-shared-base-web-fetch-default.zh.md)继续负责搜索提供方选择、凭据解析、搜索端点与超时，以及各 profile 暴露哪些工具。

## 验证

`packages/web/tool-web/tests/tool-web.spec.ts` 逐字固定“搜索优先”段落与两个收尾义务，在无限制与受限的工具 registry 上、针对可见 Web 工具的每一种组合渲染完整指引，并检查工具描述公布的数量上限。无密钥 snapshot 通道把最终指引固定在每个暴露该工具的随附 profile 的 `system-prompt.expected.md` 伴随文件中，把描述固定在 `tool-schemas.expected.json` 中。

## 考虑过的替代方案

**把策略写进部署 persona。** 拒绝，因为工具区段恰好在 `web_search` 可见时渲染：策略随之与能力同行，并在没有 Web 工具的组合中消失；而 persona 语句必须在每个 preset 中重复，且会比它所描述的工具存活更久。

**把时钟挂到 `packages/bundle/base/cordis.patch.yml`。** 拒绝，因为每次读数都是模型历史中一条持久 user 消息，而共享 base 服务于从不提出时效性问题的 profile。agent preset 才是决定单个会话承载什么的层面，因此时钟是 preset 配置项，`sdk-minimal`、ACP 与仅使用 base 的自定义 profile 的历史保持不变。

**把策略做成 `tool-web` 的 Config 字段。** 拒绝，理由见决策部分：想要不同措辞的部署想要的是不同的模型行为，字符串覆盖会把这一差异对双方组合都隐藏起来。

**用机械方式触发搜索，例如 pre-step 策略或 hook。** 拒绝，因为是否需要搜索是对问题的判断。关键词规则会漏掉不含关键词的时效性问题，而每轮都搜索会为本不需要的轮次付出一次辅助模型调用。

## 影响

每个暴露 `web_search` 的请求都要为策略段落付出成本，`aeven` preset 上的会话则为每五分钟一条简短的 user 消息付出成本。作为交换，是否搜索这一决策建立在一条明示的义务与一个可见的日期上，而不是记忆上。

自由文本指引是能解决问题的最弱机制：它要与会话中的其他指令争夺注意力，而被它忽略的会话只会静默失败，不会大声失败。更强的替代方案——关键词规则、每轮搜索，或对事实性陈述强制引用——要么在它们本该捕获的问题上失效，要么为每一轮付出模型调用。

策略文本是模型可见的提示词内容，因此修改它需要在同一变更中刷新每个随附 profile 的 system-prompt 伴随文件（`pnpm run test:snapshot:refresh`）。
