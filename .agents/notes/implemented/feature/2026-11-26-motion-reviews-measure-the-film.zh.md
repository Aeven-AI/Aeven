# Agent Note: Motion 审阅会测量影片

Status: implemented

[English](2026-11-26-motion-reviews-measure-the-film.md) | 中文

## 问题

一部关于阿姆斯特丹的 10 秒影片交到用户手上时，"light." 的下伸部和 "Brick," 的逗号被裁掉，有七个 17 到 22 px 的全大写标签，文字块的边缘彼此相差几个像素。模型审阅过它：`review_motion` 返回的静帧宽 960 px，是画面的一半，被裁掉的下伸部和 19 px 的标签在其中看起来没有问题。标题位于一个带 `overflow: hidden` 的揭示遮罩中，遮罩的盒子比字形矮 33 px。技能只给"标题"和"正文"规定了字号下限，因此标签没有下限；它告诉模型有 18 个字体族可按名称解析，却没有提到在第一个场景之前确定视觉风格、网格或字号阶梯。

## 决策

- **审阅会测量影片。** `review_motion` 随渲染传入审计时间，每隔 `auditStepSeconds`（默认 0.25 秒）一个。`ctx.motion` 返回发现：被自身盒子或遮罩裁切、溢出、重叠、被遮挡或超出画面的文字；低于画面短边 2.6% 的字号；不透明度持续低于 50% 的文字；在屏时间短于 0.5 秒加每词 0.3 秒的文字行；以回退字体渲染的字体族。工具把它们作为文本列在静帧之前。对阿姆斯特丹影片，它报告两行被裁切的标题和十五个过小的标签。
- **页面端审计是 HyperFrames 自己的。** `layout-audit.browser.js` 原样复制自 `hyperframes` CLI 包，放入 [`avn-motion`](../../../../packages/motion/motion/README.zh.md) 的 `audit/` 文件夹；我们自己的驱动脚本定位影片并收集其测量结果。上游 `check` 命令的 Node 端没有采用：它导入 CLI 的约 150 个打包分块，而 CLI 带有第二个浏览器驱动、一个 Web 服务器和 esbuild。
- **服务判定，渲染器测量。** 渲染器返回页面的原始采样；`Motion.render()` 按服务的 `audit` 阈值把它们变成发现。[`avn-motion-hyperframes`](../../../../packages/motion/motion-hyperframes/README.zh.md) 在自身浏览器的无头页面中加载打包文档；[`avn-motion-sandbox`](../../../../packages/motion/motion-sandbox/README.zh.md) 把脚本加入它通过管道传给 `render-motion` 的文档，后者新增 `--audit-times`。
- **持续性过滤瞬态。** 布局问题只有持续 0.5 秒且覆盖元素在屏时间的一半时才会报告。没有这层过滤，阿姆斯特丹影片会报告约七十个问题，几乎全是入场期间仍在遮罩后面的字母，或交叉淡化期间重叠的两个场景。
- **静帧可以只显示画面的一部分。** `review_motion` 接受 `region`；比静帧宽度更窄的区域保留自身像素，因此标签以原始尺寸呈现。
- **字体随打包文档一起传递。** 两个渲染器与回放路由在打包后用 HyperFrames 的 `injectDeterministicFontFaces` 把字体以 data URL 嵌入。Google Fonts 提供的任何字体族都可按名称解析，托管渲染器也是如此，其沙箱没有网络：文件由 Host 获取。技能不再列出 18 个字体族。
- **技能先教视觉风格与布局，再教动画。** 它在 `index.html` 中以 CSS 自定义属性确定字体、三级字号阶梯、颜色和统一的边距；先用 flex 或 grid 搭出每个场景的完成画面，再做动画；限制全大写标签；给出揭示遮罩所需的内边距；并按角色指定缓动、停留时间，以及让影片显得像生成品的模式。
- **影片在轮次的文件列表中只占一行。** `show_motion` 在其结果的 `producedFiles` 中声明合成的 `index.html`，并以存储的影片作为其副本。列表随后只显示这一行，而过去会把 `index.html` 和每个场景文件列为已编辑文件。
- **HyperFrames 的 core、engine 与 producer 从 0.9.19 升级到 0.9.99。** 渲染器调用的函数没有变化。客户端的 `@hyperframes/player` 保持在 0.9.19：0.9.99 的播放器会延迟导入 HyperFrames 800 KB 的运行时脚本，而客户端包只有一个文件；0.9.19 的播放器可以播放 0.9.99 的打包文档，后者自带运行时。

## 考虑过的替代方案

**依赖 `hyperframes` CLI 并运行 `check --json`** 被否决：解包后 24 MB，有 18 个直接依赖，每次审阅要起一个子进程，而且无法在托管沙箱内运行，那里的渲染器是一个独立脚本。**自己编写布局审计** 被否决：上游的实现有 3,500 行，已经处理了遮罩、裁剪路径、渐变和变换。**报告上游的每个代码** 被否决：盒子、视频遮片和连接线相关的代码会在照片为缓慢推进而放大到超出画面时触发，而每部照片影片都有意这样做。**自动对齐检查** 没有加入：作者会对大号展示文字做视觉对齐，让它比下方的标签偏左几个像素，而基于 DOM 矩形的检查会把这报告为缺陷。**在审阅中运行上游的 lint** 没有加入：它的字体规则要求随附 18 个字体族之外的每个字体族都有 `@font-face`，这与按名称获取相矛盾。

## 影响

在桌面渲染器上，一次审阅会启动第二个无头页面，对一部 10 秒影片的 40 个采样实测耗时 1.3 秒。托管 Host 必须在更新 Host 之前重新安装 jail 的 `render-motion`（`install-motion.sh`）：旧脚本会拒绝 `--audit-times` 与 `--still-region`。影片首次使用某个新的 Google Fonts 字体族时，打包会获取它；之后的打包读取 HyperFrames 的字体缓存。打包文档会因字体而变大，阿姆斯特丹影片的三个字体族约为 1 MB。更新 HyperFrames 现在还包括按 `audit/README.md` 的说明复制同一版本的审计脚本。
