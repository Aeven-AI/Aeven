# Agent Note: 记忆结果捕获

Status: implemented

[English](2026-09-28-memory-outcome-capture.md) | 中文

## 问题

一次被捕获的轮次（turn）包含对话与工具结果，但记忆提供方无法把可恢复的模型重试、用户纠正、已报告的验证或已完成的目标与普通行文区分开。把一次成功的工具调用或一次重试当作任务结果，会让系统学到错误的经验。

## 决策

`memory-context` 从同一轮次内已提交的事件中推导结果证据，扩展了[以 MemOS 为提供方的长期记忆](2026-09-28-long-term-memory-memos.zh.md)所建立的轮次捕获。它记录 `llm/retry` 的失败代码、直接用户明确的纠正提示、仅在该轮次存在一次成功完成的工具调用时才记录的助手验证陈述，以及 `goal/change` 完成时的目标。验证陈述始终是助手的报告，不是外部条件已通过的断言。工具调用及其实际结果仍是它背后的证据。

`memory-memos` 把这些证据存入 MemOS 的轨迹上下文提示，添加可搜索的 `outcome:` 标签，并把证据追加到召回返回的轨迹摘要中。持久完成的目标为该轨迹带来正向的隐式反馈。重试与失败的工具调用不会得到自动的负向反馈，因为该轮次仍可能成功。显式的消息评分保留自己的反馈路径。

## 考虑过的替代方案

仅凭 `turn/end`、一次成功的工具结果或模型的断言推断任务成功，会把已完成执行与已验证的工作混为一谈。把每一句看起来像纠正的话都当作对紧接其上那条轨迹的反馈，还会把指向更早工作或另一个会话的纠正归错对象。当前的捕获把纠正文本留在它自己的轮次上。

## 后果

纠正提示识别明确的英文与中文开头；其他措辞仍作为普通文本被捕获。未伴随已记录的成功工具调用的验证不会被标记。证据随被选中召回的轨迹出现，而第 6 步仍负责选择哪些轨迹进入召回上下文。
