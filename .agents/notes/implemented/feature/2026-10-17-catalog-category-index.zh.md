# Agent Note: 技能目录按分类索引分组

Status: implemented

[English](2026-10-17-catalog-category-index.md) | 中文

## 问题

目录里有七十四个技能。一整份按字母排列的列表要求读者逐行扫描才能找到想要的领域；此前的分类显示把十五个分组堆进同一段滚动，回答“哪里有值得看的内容”的数量信息夹在行与行之间，而不是摆在读者眼前。

## 决策

显示方式保留两个选项：`按分类` 与 `全部`，且目录默认打开 `按分类`。`全部` 按字母顺序列出。`按分类` 先渲染一份索引：每个分类一行，显示首字母大写的名称与它包含的技能数量。打开一行是地址为 `#!/settings/skills/category:<name>` 的页面，版式与技能自己的页面一致——分类名作标题、下方是技能数量，设置页面的返回控件回到索引——其中每一行技能仍各自打开自己的页面。搜索词会覆盖分组，跨全部分类列出匹配的技能，因为正在输入名字的读者并不是在浏览某个领域。

数量由目录实际携带的技能算出，而不是读索引里的 `categories` 字段，因此数量不会与它描述的那些行脱节。

## 考虑过的替代方案

**继续堆叠分区。** 带吸顶标题的分区能一次展示全部内容，但十五个标题与行交替出现，页面比目录本身还长，数量也留在滚动区域里而不是最前面。

**直接用 `categories` 的数量。** 索引在同步时记录数量；从 `skills` 推导只需一个事实来源，也不必再读一个可能与行不符的字段。

**把分组做进搜索语法。** `category:` 前缀能保留一份列表和一个控件，代价是为一处二级选择教一套语法，而显示菜单本来就能承载它。

## 后果

按领域两次点击即可到达任意技能，从分类回到索引一次点击。目录默认打开的就是索引，因此想找具体名字的读者改用 `全部` 或搜索框。
