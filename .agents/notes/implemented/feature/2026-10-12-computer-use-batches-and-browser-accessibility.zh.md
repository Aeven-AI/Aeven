# Agent Note: Computer-use batches and browser accessibility

Status: implemented

[English](2026-10-12-computer-use-batches-and-browser-accessibility.md) | 中文

## 问题

桌面会话支持批量配方执行和独立校验，但模型无法调用它。应用内浏览器支持批量操作，却只暴露 DOM 选择器，无法定位 shadow root 内的元素。在工具流水线外捕获浏览器画面不会产生普通的已记录图像结果。

## 决策

macOS 提供程序通过操作级 `ComputerUseSession` 注册 `computer_use_run`。每个批次包含 1 到 20 个步骤，报告已完成结果，在首个失败或未通过校验的执行处停止，并将取消信号传给宿主命令。执行需要写入权限和批准。Web bundle 通过 `register: false` 将它与 Cua Driver 并列挂载；驱动保留独占注册及现有交互工具。此批次支持语义配方，不实现层级降级或重放回执。

`preview_snapshot` 提供 Chromium 无障碍观察，采用桌面节点字段和快照级令牌。浏览器把令牌解析为后端 DOM 节点以进行点击和文本插入，包括 shadow root 内的编辑器。令牌不能与选择器或坐标组合。新的观察或浏览器操作会使令牌集失效；文档变化以及目标分离、隐藏或禁用会拒绝执行。框架定位仍属于独立工作。

`preview_screenshot` 在浏览器操作期限内将可见视口捕获为 JPEG，通过附件存储持久化，并返回普通图像块。即使 Client 忽略信号，浏览器操作也会与取消期限竞速。

## 考虑过的替代方案

**并行浏览器或外部截图命令。** 它们会离开用户选定的窗格，或绕过有期限且已记录的工具结果。现有浏览器自动化 waterfall 拥有所选 guest，并承载这两种操作。

**把第一方批次作为桌面驱动的替代品暴露。** 语义执行器没有视觉机制处理程序。保留 Cua Driver 注册可保持其已工作的无障碍和视觉机制，而不声称批次能降级调用它们。

## 影响

校验和逐期望失败在一个结果中到达模型。无障碍观察避免手工发现 shadow root 选择器。操作后令牌需要新的观察，无障碍输出会报告截断。已完成批次步骤不会回滚；重复执行可能复制应用更改。独立调用不共享观察，两种提供程序都不会在多个会话之间占用桌面。

## 验证

Host、Client 和桌面 TypeScript 编译以及仓库和桌面构建通过。按请求的验证范围，没有运行自动化测试或实际应用工作流。
