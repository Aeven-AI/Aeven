# Agent Note: 被取代的记忆不进入召回块

Status: implemented

[English](2026-10-01-memory-supersession.md) | 中文

## Problem

一次召回可能同时返回某个陈述及其替代陈述。某个区域先被记录为一个值，之后被更正为另一个值，而两段轨迹都会被检索出来，因为二者都与查询匹配；于是块中并列陈述着当前值与它已过时的前身。读到这一点的模型没有任何依据去选择，而这个失败在块本身里是看不见的：检索是成功的，只是记忆不再为真。

provider 无法解决这件事。MemOS 按相关性给候选排序，并不知道两段摘要在讲同一个对象，因此这个选择落在负责组织该块的 consumer 身上。

## Decision

`@aeven/memory-context` 会把描述同一对象的两个记忆中较早的那个退役，并在相关性打平时按时间排序。

被召回的 memory 现在会带上它被记录的时点。`MemoryHit` 新增可选的 `recordedAt`，由 `@aeven/memory-memos` 从轨迹自身的时间戳填入；provider 未报告时间的 memory 仅按分数竞争。

在渲染之前，当一个 memory 满足以下条件时会被丢弃：同一 domain 中存在更晚的 memory，二者都带有记录时间，且它们的摘要共享较短摘要中至少 `supersedeOverlap` 比例的相同词——默认 0.6。该比例按词集合度量，因此词序与表述长短不会使其失效。排序在相关性、已记录结果、片段相关性、provider 分数之后，以时间作为最后一道打平依据，使两个同等相关的 memory 即便互不取代，也先呈现较晚的那个。

该比较只作用于已经检索到的 memory。它不增加 provider 调用、不增加模型调用，也不给请求路径带来自身延迟；每段摘要的词集合只计算一次，并在排序与每一对取代判断中复用，因此这一遍在分词上是线性的，仅在受约束候选列表的集合成员判断上呈平方。

取代只约束该块。较早的陈述会从该回合的召回上下文中移除，但绝不删除，也绝不对显式检索隐藏：`memory_search` 与 `memory_get` 仍会返回它，因此历史仍可追溯，而块只陈述一个值。

指向对象在更正到达时被记录，而不是事后被推断。`@aeven/memory-memos` 在采集时把上一回合的轨迹标记为 `superseded:<替代轨迹>`，因为更正是对它紧随其后的那次交流的回应；自动召回随后在与排除 correction 标记轨迹相同的路径上排除该轨迹。该写入运行在 `turn/end` 之后的按会话采集队列上，因此不给请求路径增加任何开销；而当前一回合从未被采集时，该更正不写入任何内容。

## Alternatives considered

- 用一次模型调用来检测矛盾。它无法运行在请求路径上：召回受 `recallTimeoutMs` 约束，中位耗时已是 87ms，而一次模型调用会给每个发生召回的回合增加数秒。
- 对两段摘要做嵌入并比较向量。本地已有该嵌入器，但把它推到请求路径上，意味着为每一对被召回的 memory 付出一次推理，而词集合已经给出了这一信号。
- 仅凭词汇来解析指向对象，无论是在采集时还是在召回时。更正并不指明目标，把它的词与更早的 memory 匹配，只会退役恰好共享这些词的那个 memory；而同一会话的上一回合，才是该更正真正回应的那次交流。
- 删除被取代的轨迹。这会摧毁“某个值曾经不同”的审计线索，而结果证据与用户自己的更正经正依赖这条线索。

## Consequences

该判断是基于词汇的启发式。两个用同样措辞表达、但实际不同的 memory 可能被折叠为较晚的那个；这一风险是有界的，因为该判断从不跨越 domain 边界、要求双方都有记录时间，并且不影响显式检索；对于默认值不适配的部署，`supersedeOverlap` 是一个经过校验的配置字段。

一次更正与其对象在措辞上天然共享词汇——它们差别在于值——因此该判断存在的理由正落在它处理得最好的情形上。

召回现在依赖 provider 报告 memory 被记录的时点。省略 `recordedAt` 的 provider 会保留两个陈述，这是此前的行为，而不是新的失败。

一次更正只会退役一条轨迹：上一回合的那条。追溯到更远的更正，或到达于其前一回合从未被采集的会话之中的更正，会让较早的陈述仍留在自动召回里——在那里，渲染期的检查只要两段摘要重合，仍可将其退役。因此两种机制在所能捕获的范围上互相重叠，而单独任一都不完整。

## Verification

一个八例的 spec 覆盖了更正形态、任一时间未知时两个陈述都保留、跨 domain 边界时都保留、在最严格重合度下都保留、相关性打平时优先较晚的陈述，以及原有的完全重复去除仍然有效。另有六例覆盖更正写入的标签、同一替代被重复记录时只保留一条而更早的仍可读出、被取代的 memory 不在自动召回中但存在于显式查找中，以及被召回的 memory 会带上其记录时间。两个 spec 均通过，`pnpm run typecheck` 无错误。

未度量：两种机制在真实召回中各自多久触发一次，以及从块中退役较早陈述是否会改变 agent 的行为。前者需要 harness 尚未保留的逐回合记录。
