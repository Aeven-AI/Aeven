# Agent Note: Imagine's starter-prompt popup and its photo intake

Status: implemented

[English](2026-10-10-imagine-starter-prompt-popup.md) | 中文

## Problem

Imagine 的起始页此前提供十三条灵感提示的网格，卡片直接把文字写入输入框。卡片不带示例图，因此没有任何东西展示一条提示会产出什么；也没有任何东西让读者选择画面比例或提供精修所需的照片；更没有界面解释一条预设。该包的 README 仍在描述已被移除的 `/i/<id>` 页面及其自带输入框，并声称 Imagine 无法生成。

两个约束塑造了这次修改。Aeven 图片提供方不接受比例字段（`media-aeven` 的 `requestBody` 只接受 `WIDTHxHEIGHT` 形式的 `size`），而被生成的图片只受抵达模型的内容驱动——因此读者的画面选择与他们提供的照片都必须随之后由 agent 读取的那条消息一同传递。同时，输入框的图片入口只能经由输入框自身的 inject face 触达，而 session 作用域的 slot 组件无法使用它。

## Decision

灵感提示是目录数据。`prompts.ts` 承载每条提示的 id、随附示例（`image`，精修对另带 `before`）、它是否编辑读者提供的照片、默认比例，以及它提供的比例；标题、一行说明、提示词正文与弹窗自身的文案位于 `imagine` 字典中。Instagram 原创排在第一位，Instagram 优化与航拍视角作为两张编辑类卡片紧随其后；这三条是目前随附示例资源的提示。

航拍视角是第二张编辑类卡片，其要点就是提示词的简短：一个要求——把同一个地点与同一个主体重新拍成真正的高空航拍照片——加两条护栏，即不是插画或地图，也不是微缩模型或移轴效果，且完全没有工艺段落。它的措辞写“地面或地板”而非只写地面，因此室内照片与户外照片一样可以转换；卡片上的示例对照图就是这种简短提示词仍然交付的验证。

第二条提示 Instagram 原创不发送固定文本：它在弹窗打开时从 `scenes.ts` 的十六个场景与六种调性中各抽一个，组合进字典中固定的工艺段落；`换一个` 会逐步走过场景池，因此连续抽取不会重复同一场景。随机性在客户端决定，而不是交给模型去发挥，因为读者必须在发送前看到并修改这条消息——预览因此就是提示词本身。目录类型也随之分开：固定提示发送其 id 所命名的字典文本，自创画面的提示则承载两个池。

点击卡片会打开该提示的弹窗——共用 `Modal`，headless，双列：示例图，或原图与精修图并列，旁边是标题、带“展开更多”开关的说明、会标出像素尺寸的比例选择、照片选择区、带复制控件的完整消息，以及 `Try it`。`Try it` 把消息写入输入框，并把所选照片登记为这份草稿的图片，随后关闭；它从不发送。编辑所供照片的提示在未选择照片时也保持按钮可用：它的消息中带有一句索要照片的话，因此读者既可以在弹窗里选照片，也可以在输入框里附上。

比例以追加在消息末尾的 `WIDTHxHEIGHT` 尺寸行抵达模型，`自动` 则不追加任何内容。尺寸属 2K 档——2048x2048、1638x2048、1152x2048、2730x1536——按 Instagram 自身的导出尺寸放大。弹窗中的提示词预览由同一个函数组装，因此读者读到的就是模型收到的。

照片通过两个输入面新增的成员抵达草稿，即 `SessionInput` 与 `InputActions`：

```ts
interface ImageFileInput {
  addImageFiles(files: readonly File[]): string | null
}
```

`SessionInputShell` 依据新增的 `SessionInputDeps.draftImages` 依赖实现它——`create`、`release` 与 `busyNotice`——由 hub 接到对话服务既有的 `createDraftImages`，把 `UnsupportedImageMediaTypeError` 映射为本地化的媒体类型拒绝，把被锁定的草稿映射为忙碌提示。被锁定草稿拒绝的图片会立即释放，其预览 URL 随之消亡。hub 中草稿图片的释放现在是一个私有 helper，由命令路径、disposer 与本入口共用。该成员是必填而非可选，因为 `InputActions` 只在一个 session 存在时才存在：生产环境没有缺失的情形，且每个测试假件现在都提供它。

资源缺失或加载失败的卡片只渲染标题，而不是损坏的画框。

**让模型自行变化画面，而不是变化提示词** —— 只要求“来点原创的”并让模型选择主题，就不需要池与文案。但这样读者在花费一次生成之前没有任何可读、可改、可换的内容，而实践指南也指出，正是含糊的形容词式措辞让产出变得平庸。

## Alternatives considered

**由 Imagine 插件直接触达对话服务** —— 弹窗本可以通过 `ctx.get('conversation')` 铸造草稿描述符并把 id 交给 `inputActions.addImages`。这会拆分描述符的归属：被拒绝时的释放与预览 URL 的生命周期将离开草稿的归属者，在一个展示型包中被重新实现。

**把 `addImageFiles` 在输入面上设为可选** —— 输入框自身的 inject face 对它的各项能力使用 `| undefined`，但那些能力在没有 session 时确实不存在。`InputActions` 按构造就是 session 作用域的，因此可选性并不建模任何真实情形，只会把一条空值分支逼进弹窗。

**在选择照片前禁用 `Try it`，或为画面比例在输入框中埋一个隐藏选项** —— 禁用的按钮需要提示才能被理解，而隐藏选项永远到不了模型，因此无法改变生成。由消息承载的尺寸行与索要照片的语句让一个可用按钮保留两条自然路径。

**照搬参考产品的深色弹窗皮肤** —— Aeven 自身的 modal token 与圆角让弹窗留在产品的表面上；只借鉴了布局。

**悬停揭示式的原图/精修对比** —— 这一对图就是提示的全部卖点，而悬停手势在触屏上无法被读取。两张图并排显示并各自带标签。

## Consequences

代价是两种语言各十三条提示说明、两张约 250 KB 的示例资源，以及一个必填的输入面成员，它在一次机械改动中触及七个 client 包里的十三个测试假件。目前只有精修卡片随附示例图，其余十二条在资源到位前只显示标题。

换来的是这样一个起始页：它展示每条提示的产出、解释它，并在消息发送前捕获模型所需的两个要素——画面与照片——同时没有新增生成路径：图片仍来自一条普通首条消息上的 `generate_image`。尺寸行只在模型遵循读者文本的范围内生效，而这是产品拥有的唯一通道；没有任何机制把尺寸钉在调用本身。

自创画面的抽取不可复现，它卡片上的引导图也不是它的产出：卡片展示的是这个家族，而不是那一张画面。它的池就是文案，因此其质量是一项两种语言的写作任务——十六个场景与六种调性——而英文读起来好的场景在中文里未必同样好。

组件覆盖位于 `packages/client/ui-imagine/tests/prompt-dialog.client.spec.tsx`（弹窗的组装、比例改写、照片登记、拒绝路径，以及网格的卡片到弹窗与资源缺失行为），图片入口位于 `packages/client/ui-conversation/tests/input-image-intake.client.spec.ts`。可见的组装输出由回放 web 通道覆盖。
