# Agent Note：桌面启动画面

Status: implemented

[English](2026-10-16-desktop-start-screen.md) | 中文

## 问题

Aeven 启动时，在后端就绪之前屏幕上一片空白。桌面壳要读完打包的部署设置、向登录 shell 查询 [PATH](../bug-fix/2026-10-15-desktop-host-uses-login-shell-path.zh.md)、选定后端、安装或校正发行版、再启动 Host，之后才创建窗口，而创建出的窗口在首次绘制前一直隐藏。在已安装的 0.3.4-alpha macOS 构建上实测：普通启动时窗口在进程启动 5.7 秒后出现；需要安装发行版的启动则为 24.5 秒，其中约 19 秒的安装（含分阶段健康检查的启动）发生在任何窗口存在之前。这几秒与“永远不会绘制”的启动在屏幕上毫无区别：Electron 就绪事件后 Dock 图标的弹跳已经停止，而再次启动应用则完全没有任何反应，因为桌面壳处理后续启动的聚焦处理器要等后端就绪才安装。

## 决策

`main` 在第一次等待之前就创建主窗口，并把启动画面载入其中。画面由位于其上方的协议处理器从桌面壳自己的协议 `avn-app://shell/start.html` 提供，因此既不需要 Host，也不需要任何包状态；`start-screen.ts` 生成该文档，`brand-page.ts` 拥有它绘制的画面。后端应答后，同一个窗口载入应用自身的地址，由客户端的预加载界面接续。由于窗口与聚焦处理器都在第一次等待之前就存在，启动过程中再次启动应用会把启动画面带到前台。

画面上只有加载图形。`brand-page.ts` 绘制 50px 的 Æven 标记，其下 4px 处是加载标记，每 900ms 旋转一周，并使用客户端预加载界面接下来要绘制的配色——浅色方案为 `rgb(242,242,242)` 底配黑色墨色，深色方案为 `#111111` 配 `rgb(249,250,251)`，跟随系统方案，并遵循 `prefers-reduced-motion`——这正是[静态 Web 壳预加载界面](../bug-fix/2026-09-02-static-web-shell-preloader.zh.md)所拥有的画面。画面不含任何文案，因此交接给该预加载界面时不会发生位移。`oauth-browser.ts` 中的登录页面从同一模块绘制同一画面，使两者不会各自漂移；只有在页面别无内容可读时，它的标签才用来命名该流程。

## 考虑过的替代方案

**单独的无边框启动窗口。** 这是 Electron 常见的做法，且可以单独关闭。但代价是要在三个平台上安置、聚焦并交接第二个窗口，而桌面壳自己的窗口本就带有各平台的标题栏、[标题条](../architecture/2026-10-14-linux-desktop-caption-strip.zh.md)与标题菜单，启动画面还得重复窗口自身的尺寸与外观规则。

**在画面上写出当前阶段。** “正在准备 Aeven”“正在安装依赖包”“正在启动服务”能告诉读者漫长等待所为何事，代价是桌面壳的文案表，外加一条从 `main` 到页面的 IPC 通路，用于传递每个阶段以及后到页面的查询。第一版实现就是这样；旋转标记下方预留的那一行把标记抬到比客户端预加载界面中心高约 19px 的位置，交接时的回落清晰可见，于是文案与整条阶段通路一并删除。它所解释的那段实测等待（19 秒的安装）交由画面本身承担。

**先启动客户端，再由它重试。** 由桌面壳直接提供前端构建产物，可以让客户端自己的预加载界面与本画面同时开始，把可见等待从约 5.7 秒缩短到约 1 秒（等待主要来自 Host 启动）。但这会让客户端在没有 Host、也没有确定来源的情况下启动，触及的是连接与信任路径而非桌面壳的首帧，因此留作独立的改动。

## 后果

进程启动后数百毫秒内就会画出产品自己的画面，无论其后还要等待什么：读取部署设置、查询登录 shell、安装发行版、启动 Host。漫长等待期间读者看到的是产品本身，而不是空白；启动过程中再次启动应用会把该窗口带到前台，而不是被丢弃。

启动画面位于启动路径之中，因此无法载入页面时会退回桌面壳先前的行为：`loadURL` 记录日志，流程继续，后端就绪后应用照常打开。画面是被替换而非关闭，因此不会为显示它而创建或关闭窗口。

验证：单元测试覆盖生成的文档及其与登录页面共享的画面（`apps/desktop/tests/start-screen.spec.ts`、`apps/desktop/tests/oauth-browser.spec.ts`）。一个使用临时主目录、独立用户数据目录启动的开发版桌面壳，其渲染进程调试端点按载入顺序报告了每个页面：进程启动 0.3 秒后为 `avn-app://shell/start.html`，8.4 秒后为应用自身的来源，即该 profile 的 Host 启动耗时；期间窗口始终显示该画面。
