# Agent Note：Aeven 文件夹会同步

Status: implemented

[English](2026-11-16-synced-aeven-folder.md) | 中文

## 问题

Aeven 在用户 Mac 上的 `~/Documents/Aeven/Presentations` 中为其制作了一组演示文稿，并在回复中展示了预览图。在 chat.aeven.io 上，第二张预览显示“Image not shown”，而这些演示文稿不存在于任何其他设备上。文件同步没有携带其中任何内容：会话的工作区是 Git 仓库，通过 Git 同步，而 `~/Documents/Aeven` 不属于任何工作区。为 chat.aeven.io 提供服务的托管 Host 根本不是文件同步设备，文件云也只保存它无法读取的副本。存储的附件副本（[回复图片副本](2026-11-16-reply-image-copies.zh.md)）覆盖回复所展示的内容，而不是文件本身。

## 决定

Aeven 文件夹是 Aeven 为用户制作的文件的存放处，文件同步像对待工作区一样携带它：

- `@aeven/aeven-folder-sync` 负责它。桌面应用把它设为 `~/Documents/Aeven`。未启用 `perAccount` 时，它属于设备上的一个账户，由第一个接入的账户记录在其 `.aeven-account` 文件中，因此同步多个账户的设备绝不会把一个账户的文件随另一个账户发送。每台设备以从账户派生的文件夹 id（UUID，文件云接受的形式）共享它，因此账户的各台桌面设备与加密的文件云副本无需协调即加入同一个文件夹。每台设备把自己文件夹的绝对路径记录在 `aeven-folder/paths` 中，`localPath` 把另一台设备写下的路径映射到本机副本。
- 模型的运行时上下文把该文件夹指明为它所制作文件的存放处，演示文稿和简历技能在那里工作。沙箱策略新增的 `writableRoots` 让每个 `workspace-write` 调用无需询问即可写入它。
- `/api/workspace-file` 对位于任一设备 Aeven 文件夹内的路径，从本机的该文件夹提供文件，无论会话的工作区是否包含它。
- 设置 `AVN_SYNCTHING` 时，托管 Host 运行 Syncthing，并把每个账户的 Aeven 文件夹保存在 `aeven-folders/<account>` 下。它在账户的 `file-sync/peers` 文档中把自己列为标记 `hosted` 的设备，并与其中列出的设备共享。它只在自己持有账户密钥时这样做，即中继持有该密钥，或用户在那里解锁了受通行密钥保护的账户；持有密钥的 Host 已能读取账户同步的一切，因此桌面设备与账户列出的每个对等设备共享。托管 Host 只接受 Aeven 文件夹；向它提供的工作区和录音文件夹保持待接受状态。启用监狱时，账户的托管文件夹就是其 Aeven 文件夹，因此它的会话会写入该文件夹（[聊天文件存放在 Aeven 文件夹中](../architecture/2026-11-23-chat-files-live-in-the-aeven-folder.zh.md)取代了此前的只读副本）；受限命令只能看到其会话的子文件夹，因此 Host 不向自己的模型提及该文件夹。

## 考虑过的替代方案

**在托管 Host 上解密文件云副本。** 文件云以从账户密钥派生的密码保存 Syncthing 的加密块；读取一个文件意味着在 Syncthing 自身同步之外用 `syncthing decrypt` 解密整个文件夹，而且每次变化都要如此。受信任的对等设备通过桌面设备已在使用的传输收到同样的文件。

**把每个生成的文件复制到附件存储。** 附件随会话传输，托管 Host 可以读取，但它们按对话划分、有上限，也不是用户能在另一台 Mac 上打开的文件夹。它们继续用于对话所展示的内容；文件由该文件夹携带。

**同步智能体在任何位置写下的每个文件。** Syncthing 按文件夹同步，而智能体会在整个磁盘上写入；一个已知的文件夹让同步的内容可预测且有界。

## 影响

在一台桌面设备上制作的演示文稿、简历、影片或预览图会出现在账户其他桌面设备的 Aeven 文件夹中；在 Aeven Cloud 持有账户密钥期间，即使所有桌面设备都离线，也能在 Aeven Web 上打开。由另一台设备写入的对话（副本）不会从本设备获得存储的回复副本，因此其旧预览通过该文件夹的托管副本在 Aeven Web 上打开。部署托管部分需要 Host 机器上有 Syncthing 可执行文件、`AVN_SYNCTHING`，并且在文件云实例已占用默认端口时，需要用 `AVN_SYNCTHING_LISTEN` 指定可到达的端口。桌面应用的运行时上下文多出一行 `aeven-folder`。写在该文件夹之外的文件保持原有的可达范围：文件夹工作区的文件、Git，或回复所展示内容的存储副本。

## 验证

每个改动包的 `tsc` 均通过，`pnpm run build` 成功。线上检查方式：在桌面应用上制作一份演示文稿，它出现在 Linux 虚拟机的 `~/Documents/Aeven` 中，并且在桌面应用退出后，其预览可以在 chat.aeven.io 上打开。
