# Agent Note：分享消息的公开链接

状态：已实现

[English](2026-11-12-public-links-to-shared-messages.md) | 中文

## 问题

用户可以复制一条回复，却无法把它连同格式和图片完整地展示给 Aeven 之外的人。Session 存放在用户自己的设备上，因此任何人都能打开的链接必须由 Aeven API 提供，而且用户必须能看到并撤销自己创建的每个链接。聊天应用和社交网站还需要页面头部中的预览卡片，并且不运行脚本就能读取。

## 决定

助手消息操作条新增 order 30 的 lucide `share-2` 操作，位于反馈和朗读之后、紧挨分支之前。它打开一个 `Modal`，说明链接会公开这条回复，以一半尺寸显示该轮次已渲染收尾回复行的 inert 副本，并提供管理和黑色的创建链接按钮：创建期间按钮保持宽度，旋转图标替换链接图标，完成后复制链接并显示已复制。管理按最新在前列出账户的链接，当哨兵进入列表滚动区域时加载下一页，可逐个删除链接，也可在确认后全部删除。

Host 的 `messageShare` Remote 位于 `@aeven/host-message-share`，从持久化日志构建快照：只有收尾助手消息，标题取其第一行。提问从不发送，因此问题和注入的上下文都不会进入公开页面。图片以 `share-image:n` 的形式、经 base64 编码随 Markdown 一起发送；Markdown 图片只有在其真实路径位于 Session 工作目录或某个已注册工作区内时才会发布。每次调用都携带用户自己的 `AEVEN_TOKEN`，与连接器代理相同。

Aeven API 为每个账户、Session 和消息存储一行 `shared_links`，因此再次分享同一条消息会在同一个 `shareId` 下刷新快照，并递增用于命名其存储文件的版本号。Web 服务器在与登录页相同的页头下只渲染回复 `/s/<shareId>`：Markdown 用 `marked` 转换并用 DOMPurify 清理，带 `noindex`，并有指向 1200×630 卡片的 Open Graph 和 Twitter 标签。API 在创建链接时用 `canvas` 以品牌字体绘制卡片；字体以 TrueType 形式随附，因为 `canvas` 无法读取 WOFF2。页面唯一的脚本是一行由 CSP 哈希放行的固定内联代码：它从本地存储读取 aeven.io Web 应用的 `userId`，把 Try Æven 改为 Go to Æven，因为认证 Cookie 的作用域是 `/api`，不会到达 `/s/`。

## 验证

API 的单元测试覆盖创建、列出、删除和全部删除的按账户归属，同一链接下的快照刷新，图片重新编码和按版本清理文件，被拒绝的快照，页面的预览标签与清理，以及卡片的尺寸和换行。harness 改动通过了 Host 与 Client 的类型检查和构建。

## 考虑过的替代方案

**用 satori 和 resvg 生成卡片。** 两者都无需浏览器即可运行，但 API 已经随附 `canvas`，用它绘制卡片代码更少，也不引入新的原生依赖。

**在浏览器中渲染卡片再上传。** API 无法信任该图片，而且每个客户端绘制的结果都不同。

**从浏览器发送回复文本。** Host 已经持有日志；在那里构建快照可以避免页面发布 Session 中从未包含的文本。

## 影响

链接按账户存储在 Aeven API 上，因此会出现在该账户的每台设备上。已删除链接的页面会说明链接已不存在，但各网站已经抓取的预览卡片会留在它们的缓存中。只发布轮次的收尾步骤，与复制操作一致。
