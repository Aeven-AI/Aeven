# Agent Note: 记忆召回可靠性

Status: implemented

[English](2026-09-28-memory-recall-reliability.md) | 中文

## 问题

MemOS 的相关性 LLM（大语言模型）过滤器可能耗尽它内部的两秒上限，随后丢弃技术上相关的候选。Aeven 的召回块还把轨迹压缩为摘要，这可能漏掉让某个早先技巧变得有用的命令、设置或工具结果。

由候选数量推导出的向量扫描上限会在数据库增长后排除更晚存入的事实。重复提问还可能把自适应相似度下限抬到高于相关答案的位置，而两个字母的英文虚词会通过模式通道匹配到无关轨迹。

## 决策

MemOS 提供方通过 MemOS 的轮次开始延迟过滤提示，为自动召回与显式召回请求未经过滤的候选。MemOS 的轻量模式即使 `retrieval.llmFilterEnabled` 为 false 也会强制开启它的 LLM 过滤器，因此只改这项配置不起作用。显式搜索保留提供方按层配置的上限，除非调用方给出上限。候选仍由 MemOS 提供，而 Aeven 按查询词与已存摘要的重叠度对自动召回排序，排在较长的工具记录与助手回答之前；查询要求结果证据时优先选择结果证据；丢弃重复片段；并对每个领域应用可配置的条目上限。带纠正标签的轨迹仍可作为历史搜索，但不进入自动召回，因为它的指称对象没有被记录。技术轨迹片段除摘要与捕获结果外，还包含已存储的工具输入、输出与助手回答。`world` 分类器要求可复用的操作或事实，并排除关于 Aeven 设计的讨论。

固定的 MemOS `retrieval patch` 让存储扫描上限独立于返回的候选数量，保留高于配置最低相似度的向量候选，并从短 token 的模式匹配中排除常见英文虚词。这些修正属于现有检索实现；绑定到特定个人事实的查询改写会掩盖其他事实的失败。存储扫描上限与配置的时效窗口仍然约束向量检索。

## 考虑过的替代方案

**只改 MemOS 配置，而不修补检索。** 已否决：轻量模式即使 `retrieval.llmFilterEnabled` 为 false 也会强制开启相关性 LLM 过滤器，因此只改这项设置并不能阻止过滤器丢弃技术上相关的候选。

**围绕特定个人事实改写查询。** 已否决：绑定到某一条事实的改写会掩盖其他每条事实的失败，因此这些修正属于现有检索实现。

**由返回的候选数量推导向量扫描上限。** 已否决：该上限会在数据库增长后排除更晚存入的事实，因此存储扫描上限独立于返回多少候选。

## 后果

召回不再等待那次两秒的相关性调用，也不再受它单命中失败截断的影响。MemOS 把显式搜索记录在它轮次开始的检索理由下，因为那是接受延迟过滤提示的路径。单条默认长度为 1,000 字符，使已存储的命令与其简短输出能与结果标签一同出现；各领域上限与 `contextMaxChars` 约束整个块。一次新会话的浏览器检查召回了确切的 Node 版本命令及其 stdout，并带有 `Assistant reported verification` 标签，一次显式 `memory_search` 记录了 `DEFERRED_TO_FINAL`。候选集仍来自 MemOS 检索，可能在 Aeven 排序之前就漏掉某个条目。召回文本中的原始工具输出仍是不可信的历史数据。

## 验证

TypeScript 与完整构建通过。针对现有 545 条轨迹的数据库，年龄与生日两类查询都以默认候选数量召回了已保存的出生日期轨迹。热检索耗时 18–34 毫秒，其中 Tier 2 占 14–29 毫秒；首次查询还包含本地嵌入模型的初始化。重建后的 web 会话记录了召回的出生日期，并回答用户 48 岁，将于 2026 年 10 月 27 日满 49 岁。这些观察确立了当前数据库上的这次召回回归与延迟，而不是每个查询或每种数据库规模下的召回质量或延迟。未运行自动化测试。
