# Agent Note: 后续请求前的记忆提醒

Status: implemented

[English](2026-10-01-memory-step-reminders.md) | 中文

## Problem

相关的用户偏好和任务经验进入一个轮次后仍可能被忽略。仅在轮次开始时提供记忆，会让后续请求与记忆之间夹入工具输出，而只描述历史数据的指引并未明确要求智能体运用相关经验。

## Decision

现有的 `memory-context` Consumer 在每个被接受的直接用户轮次中仅调用一次提供方召回，并在轮次状态中保留有长度限制的提醒。每个后续被接受的 pre-step 都通过 `decision.messages` 添加该提醒，记录为插件来源、form 为 `recall` 的 `user/message`。现有会话日志记录实际提供的文本；无需新的事件类型或循环变更。系统指引要求智能体在选择行动或回答之前运用相关的记忆偏好和经验，同时以当前请求为准，记忆不得授权额外工作。

每次提醒重复轮次开始时提供的完整记忆块，保留现有的 `contextMaxChars` 和条目限制，不增加独立的截断预算。用户和项目条目先于经验和通用知识使用共享预算。`turn/end` 时清理轮次状态，防止提醒进入另一个轮次。召回失败、缺失、步骤被拒绝或取消时不添加提醒。[记忆提供方决策](2026-09-28-long-term-memory-memos.md)和[长期记忆路线图](../../proposed/feature/2026-09-28-long-term-memory-roadmap.md)各自保留独立范围。

## Alternatives considered

- 排除工具限制和执行守卫，因为用户要求所有工具保持可用。
- 在每个步骤重新召回会增加检索延迟，并在没有新用户查询时重复提供方工作。
- 更小的提醒预算可能丢弃相关记忆；实时验证使用完整的已提供记忆块。
- 将学习得到的文本提升为强制策略，会赋予历史对话和工具输出不应拥有的权限。

## Consequences

可以从轨迹重建提醒的提供情况，实时模型运行可以展示智能体是否运用了记忆偏好。提供提醒并不保证遵从。后续用户引导优先，但不触发新的召回；长轮次中的提醒会累积，直到上下文压缩。域内排序、来源元数据、存储格式和工具执行保持不变。用户要求的验证范围排除自动化行为测试；TypeScript、构建和实时浏览器观察提供所记录的证据。

## Verification

通过 Chrome 对 `127.0.0.1:3080` 上重新构建的服务器进行实时验证，覆盖三个完成的轮次，分别包含 3、4 和 6 个请求。持久化轨迹显示，同一轮次的每个请求前都有完全相同的召回块。首次运行仅执行两次被要求的读取。新会话通过记忆工具找回用户只要求解释时的偏好；随后对构建命令的普通提问仅进行读取和搜索并给出回答，没有构建、类型检查或编辑。这些观察证明了提供情况和实际偏好运用，不据此宣称减少令牌消耗或保证所有情况下遵从。
