# Agent Note：轮次导航栏为每条人类消息标记

Status: implemented

[English](2026-11-11-turn-rail-marks-every-message.md) | 中文

## 问题

聊天轮次导航栏每个 agent 轮次画一个刻度，数据来自 `turnOutline` 投影，而投影每个 `turn/start` 只保留一个条目。用户在轮次运行时发送的消息作为 steering 并入该轮，因此没有刻度。一个实测会话有 21 条人类消息，其中 17 条 steering 第 1 轮，导航栏只显示 5 个刻度，看不出用户说过什么。同一会话里还测到导航栏的两个缺陷。用滚轮滚到底部时，倒数第二个标记保持激活，因为阅读带只在有行越过它时才重新解析底部情形，而最后一次越过发生在到达底部之前。首尾两个刻度位于导航栏指针框的边缘，点击最后一个刻度的中心或外半部分会落到其后的 slot 上，没有任何效果。

## 决策

`turnOutline` 为每条人类 `user/message` 折叠一个条目。一轮的首条消息填充 `turn/start` 开启的条目，该条目仍是跳转锚点，因为向后分页越过它的窗口包含整轮。同一轮里之后的每条人类消息落定进行中条目并开启自己的条目，锚定在自身 `user/message` 的 seq 上。回复写入进行中条目，因此每个条目预览其消息之后最新的助手文本。状态用 `awaitingPrompt` 区分仍在等待提示词的开轮条目与已放置的消息，`stateVersion` 为 4。wire 值按 seq 严格递增、按 turn 不减。

导航栏按 seq 作为标记键，并按标记在大纲中的位置编号。开轮标记照旧落在该轮首行；steering 标记落在 `data-chat-anchor-seq` 等于其 seq 的行上，行未加载时经事件导航分页到达。激活标记由阅读带报告的、按流顺序最后的一行解析：同一轮里最近的前置 `user` 或 `steering` 行选出 seq 不大于它的最新标记。在底部时激活最后一轮的最新标记。`scroll` 与 `scrollend` 按底部状态重新解析标记，导航落定后只要视图停在落定偏移处，导航选定的标记就保持不变。导航栏指针框越过两端刻度各延伸 8px，带内比例在该处钳制到端点标记。

## 验证

`projection.spec.ts` 覆盖锚定在自身 seq 上并带其后回复的 steering 条目、作为条目的空文本消息、丢弃 steering 条目的回退，以及对外值与持久化值的 seq 顺序。ui-chat 测试在按消息编号的导航标签下通过。在实测会话中，重启后导航栏显示 21 个刻度，滚轮滚到底部后标记最后一条消息，点击任一端刻度的中心都能导航。

## 备选方案

**在客户端从已加载行推导 steering 标记。** 这不需要改投影，但导航栏覆盖整个会话，已加载窗口之外的 steering 消息在其页面到达前没有标记，历史分页时标记会在读者眼前出现。

**保持每轮一个刻度，并在悬停预览中列出 steering 消息。** 这能保持刻度数少，但点击无法到达 steering 消息，而这正是导航栏存在的目的。

## 影响

一个被多次 steering 的长轮次现在贡献多个刻度，会话更早达到 200 个标记的采样上限。wire 值每条 steering 消息增加一个条目。导航标签指称消息，而不是轮次。
