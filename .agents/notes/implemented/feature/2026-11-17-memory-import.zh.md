# Agent Note: 把导出文件交给 Æven 来导入记忆

Status: implemented

[English](2026-11-17-memory-import.md) | 中文

## 问题

转到 Æven 的人带着在 ChatGPT、Claude、Gemini 或 Grok 中积累多年的对话而来，而 Æven 起初对他们一无所知。这些助手的导出格式各不相同且会随时间变化，而且一个账户常被几个人共用，因此伴侣或孩子的事实不能变成用户本人的事实。此前对一个 ChatGPT 归档的手动导入效果很好，因为智能体先查看导出文件，编写自己的脚本，区分撰写者，再保存点明当事人的自足事实。

## 决定

- **由 Æven 完成导入，产品只负责把文件交给它。** Settings → Memory 顶部有一行 Import memory。它的按钮选择一个文件（`.zip` 导出或一段保存的对话），通过输入框的附件路由上传，开启一个新对话，其第一条消息附上该文件并请求导入，然后关闭 Settings。浏览器先只用文本文件重建归档，因此图片与对话的 HTML 副本留在设备上。
- **提供指引，而不是流水线。** aeven 预设附带 `memory-import` 技能：各种已知导出把对话放在哪里、阅读本人写下的内容、区分撰写者并把他人的事实作为关于此人的事实连同其关系一起保存、用对话日期标注每条事实、保留归属，以及去除重复。智能体根据文件需要编写任何脚本，并通过 `memory_remember_bulk` 以 `.jsonl` 文件保存，该工具本就接受 `about` 与 `date`。
- **`.zip` 可以作为附件。** `@aeven/document-extract-js` 把归档读作其文件列表；模型用工具在附件的只读路径处打开这些文件，每个附件本就会显示该路径。

## 考虑过的替代方案

**Host 上的固定导入流水线**（格式读取器、分批提取调用、撰写者分组、账本、撤销）。它最先被实现，随后被替换：它把四种会被提供方改动的导出格式写死在代码里，预先决定了每一项取舍，并重复了智能体本就能用 shell 与记忆工具完成的工作。

**提供方选择器，或像 Claude 与 Gemini 那样粘贴提示词。** 智能体能从文件本身识别格式，而另一个助手粘贴出的总结本就混杂了共用账户的几个人。

## 影响

导入作为普通对话运行，因此用户能看到 Æven 发现了什么，能回答谁是谁的问题，并像任何聊天一样为它付费。质量取决于智能体与技能而不是代码；改进导入就是改进指引。附件受 `attachment-local` 的 `maxFileBytes` 限制（默认 50 MiB），非常大的账户精简后的导出可能超过该限制。
