# Agent Note: 身份验证器双重验证

Status: implemented

[English](2026-10-15-authenticator-two-factor-authentication.md) | 中文

## Problem

仅凭账号密码或社交登录即可访问 Aeven。用户需要在注册时选择身份验证器保护，并在账号设置中管理它。

## Decision

Node 账号服务器负责 TOTP 设置和验证。注册流程在设置姓名后提供此选项；账号 → 安全提供开关。加密的待确认密钥十分钟后过期，有效的六位验证码才会完成启用。恢复码仅展示一次，并以哈希形式存储。关闭时需要有效的身份验证器验证码或恢复码。

密码登录、重复注册和社交令牌交换在完成第二重验证前不会向客户端提供凭据。登录挑战五分钟后过期。账号级尝试次数限制也涵盖新签发的挑战。Mongo 更新会原子地消耗 TOTP 时间步或恢复码哈希，Redis 会原子地消耗登录挑战。共享的 `MfaForm` 基础组件接收 API 操作和本地化文案，不持有启动会话状态。

## Alternatives considered

**展示二维码后立即启用。** 未成功设置应用的用户可能无法登录，因此启用需要验证码。

**仅保护密码登录。** 社交令牌交换和重复注册同样可以返回凭据，因此这些路径也要求相同的验证。

**以邮件作为第二重验证的备用方式。** 恢复码保留独立的持有因素，避免仅凭邮箱访问权限即可绕过身份验证器。

## Consequences

同时丢失身份验证器和所有恢复码后，用户无法自行恢复访问。启用保护时现有会话保持登录状态；后续登录需要身份验证器。设置资料不会进入浏览器持久存储。Node 部署需要安装 `otpauth` 和 `qrcode`，并配置现有的加密密钥。
