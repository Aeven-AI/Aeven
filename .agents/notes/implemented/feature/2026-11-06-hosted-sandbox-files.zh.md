# Agent Note: 托管命令监狱中的文件

Status: implemented

[English](2026-11-06-hosted-sandbox-files.md) | 中文

## 问题

有了[按账户监狱](2026-11-06-hosted-sandbox-jail.zh.md)，托管命令会在账户文件夹中生成图表、文档和表格，但没有任何途径把它们交给读者：Files 侧栏、生成文件行和工作区文件路由都已关闭，因为它们读取的是 Host 自己的磁盘。监狱周围还有四个缺口。`output_files` 路径在 Host 上查找，因此模型可以探测其他账户或 Host 的文件是否存在或是否变化。账户文件夹没有磁盘限额，一个账户就能占满 API 和数据库共用的磁盘。Host 对账户文件的读取跟随先前解析的路径，因此监狱中的命令可以在检查与读取之间把路径分量换成符号链接。模型也不知道监狱没有网络，或提供哪些库。

## 决策

`avn-tool-bash` 新增 `shareOutputFiles`。会话工作区之外的声明输出路径在任何查找之前即被拒绝。工作区内生成的每个文件都通过 `ctx.attachments` 存储，这是生成媒体已在使用的按账户通道：图片作为内联显示的图片块，其他文件作为供下载的文件块，结果文本告知模型读者已能看到它们。

`avn-fs-sandbox` 新增 `verifyReads`：每次读取都以不跟随末端符号链接的方式打开文件，通过 `/proc/self/fd` 检查打开的文件就是解析出的文件，并通过该描述符读取。`avn-api-workspace-files` 新增 `confineReads`，让预览像列表一样保持在工作区内，其 Remote 本已只为调用者自己的会话应答。在 `avn-ui-sidebar-select` 中，已注册的面板优先于同一种类的启动器，因此在两者都被组合时，Files 面板取代桌面版引导提示。

`avn-sandbox-jail` 新增 `quotaCommand` 和 `modelNote`。托管账户根目录是带项目配额的独立 ext4 文件系统，即以 `nosuid,nodev` 挂载的稀疏 loop 镜像。通过 `sudo -n` 调用的 root 所有的辅助程序在每个账户文件夹的第一条命令之前为其分配项目 id 以及 5 GiB、200,000 个文件的限额，并拒绝任何不是单个账户文件夹的路径。监狱中的进程无法更改项目 id，因为内核只允许在初始 user 命名空间中这样做。提示说明命令没有网络、无法安装任何东西、有哪些 Python 和 Node 库，以及要把交付文件列入 `output_files`。

托管补丁在 `AVN_HOSTED_SANDBOX=1` 时启用以上全部内容；每个新设置在其他地方默认保持以前的行为。

## 备选方案

拒绝通过现有的工作区 HTTP 路由提供账户文件：它向任何已登录的浏览器提供任何已注册的工作区，而托管文件夹不是已注册的工作区。新增按账户的下载路由会重复附件通道已为工具结果提供的授权、存储和展示。

拒绝每个账户一个 loop 镜像：每个新账户的挂载都需要 root，并且每个账户都留下一个挂载；一个项目配额文件系统只需一次挂载，每个账户设置一次配额。

把读取竞态修复放进 `avn-fs-local` 供所有组合使用被推迟：该检查依赖 Linux `/proc`，只有其受限进程与读者所读目录共享的 Host 才需要它。

## 影响

托管读者能看到命令列为输出的图表和文件，并能在 Files 侧栏中只读浏览自己的文件夹。文件工具保持关闭，因此模型仍通过命令读写文件；为它们提供账户受限的文件后端、把附件复制到账户文件夹，以及在监狱中运行 `ffprobe`，都是单独的工作。共享的文件会再作为附件存储一次，计入附件存储而非账户文件夹的配额。

## 验证

在托管机器上，账户文件系统以 `prjquota` 挂载；辅助程序为测试文件夹设置 10 MiB 限额后，20 MiB 的写入在限额处停止；辅助程序拒绝 `/etc`；bubblewrap user 命名空间中的进程无法更改文件的项目 id。类型检查和构建通过。
