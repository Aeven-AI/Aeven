# Agent Note：Bots 页面拆分为总览和每个 Bot 的独立页面

Status: implemented

[English](2026-11-20-bot-pages-split-overview-and-bot-page.md) | 中文

## 问题

Bot 的“调整”按钮会把一段预设提示词连同 Bot 的原始 ID 写入输入框，而输入框仍提示“描述一个新Bot”。同一页面同时承担总览、创建和单个 Bot 的管理，Bot 的操作位于折叠面板中整段任务的下方。点击想法会立即发送，于是代理的第一个问题在读者来得及修改之前就弹出在输入框上方。

## 决定

Bots 页面由三个起始地址组成：`/bots`（带输入框的总览）、`/bots/<id>`（单个 Bot）和 `/bots/runs`（执行记录，无输入框）。起始地址声明现在可以以 `/:id` 结尾，匹配一个 UUID 路径段，且精确声明优先于该模式，因此 `/bots/runs` 仍是独立页面。声明新增 `composer: false`，它让输入框保持挂载但隐藏，使草稿在页面间切换时得以保留；以及 `frameMessage`，它把输入的文字变成会话实际发送的消息。`UiWorkspace.startPage()` 取代 `composerPlaceholder()`，返回页面的注册键、是否显示输入框以及占位文字；`frameMessage()` 只处理当前起始页面所显示的空白会话发出的消息。

Bot 页面把第一条消息构造为 `@[<名称>](avn-bot:<id>) <输入的文字>`。模型从中读到要传给 `automation_update` 的 ID，消息按发送内容记录，用户气泡像处理 `avn-session` 提及一样把它折叠为 Bot 标签。工具描述本身已要求更新前确认，因此页面不发送任何指令文字。

点击想法只会填入总览的输入框，从不提交。各起始页面和新对话的空白起始界面打开时都滚动到顶部，因为它们共用对话栏中唯一的滚动容器。

页面沿用原有卡片样式：总览卡片的摘要链接到 Bot 页面，Bot 页面固定一张带相同名称与计划区块和操作行的卡片，选项菜单与其他选项菜单的打开方式一致。新增“按角色”类别，包含八个角色模板。侧栏中的托管文件夹通过 `workspaceTitle` 命名为“Runs”。

## 考虑过的方案

**保留输入框优先的页面，只改写“调整”提示词。** 原始 ID 和“新 Bot”占位文字仍会留在用于编辑的输入框中。

**在消息之外附加隐藏上下文。** 任何进入模型请求的内容都必须能从会话日志重建；把提及写入已记录的消息即可满足，无需新的会话事件。

**单独的创建页面 `/bots/new`。** 已实现后又移除：带输入框的总览即可完成同样的工作，无需再多一个容易迷路的地址。

## 影响

Bot 页面只在第一条消息中标明 Bot；同一对话中的后续消息依赖模型记住它。在页面上不经对话直接修改 Bot 名称或计划仍待实现。
