# Agent Note：桌面设备开着时，Aeven Web 上的对话在用户的桌面设备上运行

Status: implemented

[English](2026-11-10-remote-runs-web-chats-on-the-desktop.md) | 中文

## 问题

在 chat.aeven.io 上开始的对话总是在 Aeven Cloud 的监狱中运行，即使用户的桌面设备在线，带着它的文件夹、应用、电脑操控和浏览器。[同步对话的归属设备](../architecture/2026-11-10-synced-conversation-home.zh.md)让云端对话留在云端，也让桌面设备可以接手对话，但没有任何机制把网页输入发给桌面设备。用户的产品决定是默认远程，不提供设置也不弹出提示，没有可用桌面设备时回退到网页。

## 决策

- **在线状态。** 没有 `keepConnected` 的设备在其中继连接打开期间，每隔 `presenceMs`（60 秒）在账户同步设备列表中自己的条目上写入 `seenAt`（`avn-sync-yjs`）。
- **默认。** 在始终在线设备上，`homeOf` 把还没有设备运行过的对话发给 `seenAt` 在 `presenceWindowMs`（150 秒）内的桌面设备。有多台这样的桌面设备时，它选择运行了账户最近更新对话的那台，因为每台打开的桌面设备每分钟都会写入标记，最新的标记并不能说明用户在哪台设备前，选不出时才按最新标记选择。它还把最近一回合在某台桌面设备上运行的对话发回该桌面，除非它的标记已过期。否则对话像以前一样在云端运行。
- **投递。** 控制器通过同步收件箱转发这类输入，附带发送者的会话凭据，并在新的可选字段 `to` 中写明目标。目标设备立即接手，其他桌面设备从不接手发给别处的输入，始终在线设备等待 `remoteFallbackMs`（10 秒）后自己运行。这个等待比 `inputGraceMs` 的 3 秒更长，0.3.42 桌面设备在 3 秒后会接手任何输入，因此早于 `to` 的桌面设备只要开着仍会先接手。
- **覆盖。** 在 Aeven Web 上，选项菜单提供“在 <桌面设备> 上继续”（`session.continueOn`，目标为 `desktop`），桌面设备保留“在 Aeven Cloud 中继续”和“在这台电脑上继续”。`moveTo` 接受账户的任意设备。

会话事件、日志格式和 `SESSION_FORMAT_VERSION` 都没有变化；`seenAt`、`to` 和归属信息中的 `desktop` 都是旧版本会忽略的可选字段。

## 考虑过的替代方案

为每台设备建一个心跳文档，或在中继端实现在线状态，需要新的同步文档或中继协议；在现有设备条目上加一个字段、只由桌面设备每分钟写一次，就足以让始终在线设备做出选择。

把每个网页对话都发给从不写入在线标记的桌面设备，会在该桌面关闭时让每个对话都延迟一个回退时间，因此 0.3.42 桌面设备只会收到它已持有的对话或用户移给它的对话的网页输入。

## 影响

桌面应用开着时，chat.aeven.io 上的新聊天在桌面设备上运行，可以使用它的电脑操控和浏览器。休眠或关闭超过 150 秒的桌面设备收不到任何内容，云端立即作答。在该窗口内掉线的桌面设备会造成一次 10 秒的回退，之后云端已运行该回合，对话留在云端。默认路由需要桌面设备使用会写入 `seenAt` 的版本；显式移动在 0.3.42 上也可用。

## 验证

session-sync、sync-yjs、session-controller 和 ui-conversation 的测试通过（1003 个）。端到端检查是在 chat.aeven.io 上输入一个电脑操控请求，并由桌面应用运行。
