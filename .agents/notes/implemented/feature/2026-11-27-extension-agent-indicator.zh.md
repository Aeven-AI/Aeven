# Agent Note：扩展标签页显示代理的存在、当前步骤以及何时需要用户

Status: implemented

[English](2026-11-27-extension-agent-indicator.md) | 中文

## 问题

在 Aeven 浏览器扩展驱动的标签页中，代理留下的痕迹只有它的指针和 Chrome 的调试提示条。没有任何东西表明代理占用的是哪个标签页、它在那里做什么、某一步在等用户处理，或者代理已经完成。Claude in Chrome（1.0.109）会在页面四周显示光晕、显示状态标签、更换标签页图标，并在其标签组名称前加状态标记。读者希望 Æven 的扩展也有这些。

## 决定

扩展通过调试器控制某个标签页期间，`apps/chrome-extension/src/indicator-page.ts` 会在其中绘制三样东西：

- 视口四周的光晕，使用代理指针的蓝色（`#339cff`）；
- 底部的状态标签，在 `#0b6fd8` 底色上以白色 Google Sans Flex、字重 550 写明当前步骤；
- 用 Æven 图标替换页面的标签页图标。

worker（`background.ts`）在每次操作开始时绘制它们，操作结束后再画一次，因为导航会替换文档；它在调试器分离前移除它们。它们位于封闭的 shadow root 中并使用构造样式表，字体则以 worker 从扩展自带副本读取的字节加载，因此页面的样式及其样式和字体内容安全策略都无法阻挡。页面标题从不改动，因为浏览器会把标题记入历史记录。

标签组名称以标记显示状态，与 Claude 的 ⌛/✅ 相同：操作时为 ⌛Æven，某一步等用户处理时为 ✋Æven，完成时为 ✅Æven。代理未完成就停止操作时，组名恢复为 Æven。标签组从 `Aeven` 改名为 `Æven`，仍带旧名称的组会被找到并沿用。

应用通过现有 `operate` 请求的新值 `indicate` 把移交和回合结束告诉扩展，与代理的操作走同一条 `chromeAutomate` 路径。`packages/client/ui-sidebar-browser/src/client/extension-attention.ts` 记录每个会话的代理在当前回合中操作过的扩展标签页：

- 移交时发送带有代理说明的 `input`；
- 回合结束时发送 `done`，除非还有移交在等待。

扩展显示 `input` 直到代理再次操作，显示 `done` 四秒钟，两者都会弹出通知，点击通知会把该标签页带到前面。这增加了 `notifications` 权限，安装时不会出现警告。文案随浏览器语言显示为英文、中文或西班牙文。

## 考虑过的替代方案

**像 Claude in Chrome 那样，在每个页面上用内容脚本或 `chrome.scripting` 绘制。** 这需要 `<all_urls>` 主机权限，Chrome 会为此发出警告，并会停用已安装的扩展，直到每位用户重新批准。扩展操作时本就持有的调试器可以在同样的标签页中绘制，无需新的授权。

**即使调试器分离，也在整个回合中保留指示。** 那意味着要在步骤之间的每次停顿中一直持有调试器，连同 Chrome 的调试提示条，或者只为绘制而再次附加。因此指示跟随调试器，只有等待标签例外，调试器分离时它会留在页面上。

**在页面标题前加上 `Æven · `。** 它在标签栏中很醒目，但浏览器会把带前缀的标题存入历史记录，以及期间创建的书签。改由标签组标记来显示状态。

**在模型的截图中隐藏指示。** 应读者要求暂缓。标签和光晕会出现在代理对该标签页截取的截图中。

## 影响

- 指示、标签组标记和通知随扩展 0.3.38 一同发布，同时带有 WebSocket 和原生消息回退。`input` 和 `done` 通知需要包含此变更的桌面应用或网页客户端；配合较旧的版本时，指示和 ⌛ 标记照常工作。
- 某一步在等待时调试器已经分离的标签页，会保留等待标签、光晕和图标，直到页面导航或代理再次操作，因为移除它们需要调试器。
- 调试器分离后才到达的 `done` 只会显示通知和 ✅ 标记。
- 同一窗口中的所有代理标签页共用一个标签组标记，因此它显示的是其中任意一个的最新状态。
