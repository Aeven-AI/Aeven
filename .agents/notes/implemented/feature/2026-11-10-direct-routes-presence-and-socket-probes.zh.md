# Agent Note: 直连路由、正常关闭时的存在标记与套接字探测

Status: implemented

[English](2026-11-10-direct-routes-presence-and-socket-probes.md) | 中文

## 问题

Aeven 设备互相连接时有三个缺口：

- **直连依赖 mDNS。** 账户的两台桌面设备只有在组播发现找到彼此时才会通过本地网络连接。访客网络和办公网络会丢弃组播，不同子网互相看不到，跨站点的 tailnet 也不传递 mDNS，于是更新和转发的输入只能退回中转服务器。
- **关闭的桌面设备仍算在线。** 桌面设备每分钟打一次 `seenAt` 标记，并在 150 秒内算作在线。应用退出后，Aeven Cloud 最多还会在两分半钟内把新对话转发给它，每次都要等十秒回退才作答。
- **失效的套接字无人察觉。** 浏览器不暴露 WebSocket Ping 帧，操作系统可能在页面挂起时杀掉套接字而不触发 close 事件。从睡眠中唤醒的笔记本或回到页面的手机，会一直保留一个什么也收不到的套接字，直到下一次 TCP 超时。

## 决策

- **通告的路由。** 每台未设置 `keepConnected` 的设备在每次存在标记时，把自己的私有和 Tailscale（100.64.0.0/10）IPv4 地址及连接端口作为 `routes` 写入加密设备文档中的条目。局域网传输会拨打在 `routeWindowMs`（默认 150 秒）内打过标记且未标记离线的设备的路由，每次重试轮换到该设备的下一条路由；mDNS 的结果仍然优先。现有握手证明账户密钥，因此已归属另一台机器的地址永远无法建立连接。只接受来自回环、私有、链路本地和 tailnet 地址的连接。始终在线设备既不通告也不拨打路由。这一做法借鉴了 t3code 的已学习路由列表。
- **正常关闭时标记离线。** 释放时，未设置 `keepConnected` 的设备以 `offline: true` 重写其条目并保留最后的 `seenAt`，最多等待 `leaveMs`（默认 1.5 秒）让发件箱到达中转服务器。会话同步把标记为 `offline` 的设备视为离开，不论其标记时间；下一次标记会去掉该标记重写条目。
- **套接字探测。** 连接期间，页面重新可见、`pageshow`、`online` 以及 Network Information 的 `change` 事件会让 `ConnectionController.probe()` 请 Gateway 打开一个到 `$probe` 的流，这是任何 Host 都不提供的端点。所有版本的 Host 都会回一个 `error` 帧，因此探测无需改动协议。在 `probeTimeoutMs`（默认 8 秒）内没有收到任何帧就替换套接字。这一做法借鉴了 t3code 连接监督器的探测。

## 考虑过的替代方案

**用 `tailscale serve` 通过 HTTPS 在 tailnet 上暴露桌面 Host。** 推迟：这会把浏览器可访问的 Host 暴露给 tailnet 上的每台设备，需要单独的认证决策。通告 tailnet 地址即可实现设备间直连，而不暴露 Host。

**应用层心跳帧。** 否决：未知的帧类型会使客户端整个套接字失效，因此部署前加载的页面会陷入重连循环，除非双方协商该帧。未知端点探测无需协商即可达到同样效果。

## 后果

设备的私有地址和 tailnet 地址会通过加密设备文档对账户的其他设备可见。拨打一台最近打过标记但从这里不可达的设备，每 `lanRetryMs` 会失败一次连接。应答慢于探测超时的 Host 会收到一次本不需要的重连。

## 验证

同一账户的两台桌面设备处于没有组播的网络，或跨站点处于同一 tailnet 时，在一次存在标记内直接连接。退出一台桌面设备后，Aeven Web 的对话框立即显示它离线，新的网页对话在 Aeven Cloud 中运行，无需等待十秒。在打开 chat.aeven.io 时让笔记本挂起再唤醒，会在探测超时内重新连接。
