# Agent Note: 按需以管理员身份运行（Windows）

Status: implemented

[English](2026-10-13-on-request-windows-elevation.md) | 中文

## 问题

harness 能限制进程的文件效果，也能让一个人为某次调用放宽该限制，但无法以宿主的管理员令牌运行一条命令。Windows 不允许运行中的进程自行提升令牌，因此提权总是经由用户账户控制的同意提示新建一个进程——而通往它的每条路径都要经过人。 [沙箱决策](2026-07-06-sandbox.zh.md) 已把这条轴记为缺失：其升级词表只放宽文件效果，且有意不携带权限维度。操作者要的正是缺的那一半：在他需要时从 Aeven 以管理员身份运行一条命令，PowerShell 或命令提示符皆可，并且在干净安装下无需手工安装任何东西。

## 决策

交付一个包 `@aeven/tool-elevation`，在 Windows 上注册面向模型的 `elevated` 工具：`shell`（`powershell` 或 `cmd`）、`command`、必填的 `justification`，以及可选的 `timeoutMs`。

工具先询问 `ctx.approval`。该请求的会话授权作用域为 `privilege:standard->administrator`、覆盖类型为 `'privilege'`——该值已加入宿主的 `SessionGrantCoverage` 联合与客户端的 `ApprovalSessionCoverage`，并带自己的同意文案。与 `'sandbox'` 分离是刻意的：放宽文件访问的授权绝不能批准一次提权运行。除 `allowed-once` 之外的任何结果都会在启动任何进程之前以 `ELEVATION_DENIED` 让调用失败。

运行时把命令写入一个新临时目录中的任务文件（`job.ps1` 或 `job.cmd`，以 UTF-8 写入且不带字节序标记，因为 `cmd.exe` 会把标记读成第一个命令词的一部分），并通过 `ctx.subprocess` 启动一个普通的 PowerShell。该 PowerShell 执行 `Start-Process -Verb RunAs -Wait -PassThru`，并以提权进程的退出码退出，因此退出码像任何子进程一样传回。提权进程拥有自己的控制台，因此它合并后的输出经由同一目录中的一个文件传回；读取后删除该目录。提示被关闭会让 `Start-Process` 抛出异常，启动器在 stderr 上报告，工具将其呈现为 `ELEVATION_DENIED`。截止时间与调用的中止信号都会终止启动器。不安装也不预建任何东西，因此在干净安装下即可用。

## 考虑过的替代方案

### 带平台后端的 `ctx.elevation` 能力接缝

先构建，后移除。该接缝只有一个消费者（本工具）和一个后端（Windows），正是 `packages/AGENTS.md` 所说的“只有一个内部调用方的公共服务方法”这一坏味道。它多出两个包、每次运行生成的包装脚本与启动器、一个需要轮询并重新校验的结果文件，以及一个未被使用的提权会话协议。出现第二个平台或第二个消费者时，接缝才值得存在。

### 在 `SandboxMode` 中加入 `administrator` 值

拒绝。文件效果与令牌权限是正交的事实：`danger-full-access` 的调用仍可能未提权，而 `read-only` 的调用仍可能需要管理员令牌来修改系统设置。 `WIDER_MODES` 是把请求对照某次调用的文件策略来校验的，若把权限折入其中，阶梯就会在这两个维度之一上说谎。

### 自动点击同意提示，或干脆去掉它

拒绝。提示本身就是机制，而不是机制前面的障碍。当 `PromptOnSecureDesktop = 1` 时，同意发生在一个屏蔽合成输入的桌面上，而且没有任何代码路径能让*当前*进程变成提权进程——诚实的上限是：harness 请求，人在操作系统层面回答，工作在一个独立的提权进程中运行并有回传通道。调低 `ConsentPromptBehaviorAdmin` 或关闭 `EnableLUA` 是拆掉锁，而不是配好钥匙，而且它们本身就需要提权。

### 常驻的提权执行器

目前拒绝。接受一次提示之后便静默执行，确实方便且持久——这正是问题所在：它是一把在用户身份下运行的任何进程都能转动、且一直存在的钥匙。审批请求提供的会话授权已覆盖正当的重复场景——同一次提权、同一会话、读者的明确同意——并随会话过期。

### 用管道回传提权进程的输出

这并非被否决，而是不可能：由同意流程创建的进程，在本进程能保留其 stdout 的任何意义上都不是本进程的子进程，并且它拥有自己的控制台。由提权侧写出、由提供者校验的文件，是同时满足这两个事实的唯一通道。

## 后果

所得：提权在干净安装下即可用——没有安装步骤，运行之间不携带状态——并且模型可通过一次工具调用、在两次同意之后抵达它。文件效果轴未被触碰；同时需要更宽文件访问的命令仍走沙箱通道升级，两次同意彼此独立。

代价与限制，由该包的 README 拥有：仅限 Windows，其他平台不注册该工具；一次调用一条命令；捕获输出保留可配置的尾部；超时会终止启动器，而不是终止已在提权侧运行的命令，也无法关闭已显示在屏幕上的提示；任务文件位于同一用户可写的目录中，因此被攻陷的同用户进程可在同意与执行之间替换它。

## 测试

没有测试文件：本变更是在操作者明确要求排除测试的前提下完成的。`tsc -b packages/sandbox/tool-elevation` 干净。提权侧运行的脚本已在未提权状态下针对两种 shell 执行，所在目录路径包含单引号：一个多行 PowerShell 任务返回了它的 `exit 7` 以及 stdout 与错误流，一个 `cmd` 任务返回了它的 `exit /b 3` 与输出。`Start-Process -Verb RunAs` 这一步本身需要人在提示前操作；该机制在包存在之前已手工验证，一次提权运行的 `net session` 报告 `High Mandatory Level`，而调用方 shell 报告 `Medium`。没有快照覆盖工具 schema 或审批文案。
