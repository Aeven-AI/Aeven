# Agent Note: 连接在最终退避档继续重试

Status: implemented

[English](2026-11-10-connection-retries-past-the-final-tier.md) | 中文

## 问题

[连接恢复决策](2026-08-28-web-connection-recovery-control.zh.md)在 10s 档的重试失败后结束自动恢复，即断开约 15 到 25 秒之后。部署后重启 Aeven Web 的 Host 用时更长，因此每个打开的页面都会发布 `disconnected`、停止重试，并保持失效，直到读者重新加载或点击 **立即重连**。

## 决策

`ConnectionController` 在最终档继续重试：每次尝试等待 10s 上限的 50–100%，期间状态保持 `disconnected`，因此指示器仍提供 **立即重连**。前面的各档、手动重连、离线暂停和可见性重试均不变。本记录只取代恢复决策中的终态。

## 考虑过的替代方案

**保留终态，并在页面获得焦点时重新加载。** 否决，因为放在第二块屏幕或展示屏上的页面不会重新获得焦点，而它恰恰是必须在无人操作时恢复的页面。

**把上限继续增大到分钟级。** 暂时否决：Host 重启是最常见的中断，持续几十秒；中断期间每个标签页每 5–10 秒一次请求，相比健康页面每两秒一次的 WebSocket 心跳可以忽略。

## 后果

Host 恢复应答后，页面在一个最终档延迟内自行恢复。长时间中断期间，每个打开的标签页每 5–10 秒尝试一次连接。

## 验证

在打开 chat.aeven.io 的情况下重启 `aeven-hosted` 服务，且停机时间长于前面各档之和：页面无需重新加载即重新连接。
