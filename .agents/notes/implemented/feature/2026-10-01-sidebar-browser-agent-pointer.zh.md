# Agent Note: The agent pointer in the browser pane

Status: implemented

[English](2026-10-01-sidebar-browser-agent-pointer.md) | 中文

## Problem

右侧边栏面板把 agent 的指针绘制在 guest（面板内承载页面的 `<webview>`）之上。其中四项性质没有单一归属者，且各自都以可见的方式失败。chrome 控件处，指针瞄准元素的**左边缘**，因为面板里唯一的瞄准规则是为地址栏写的 —— 输入的地址从字段左侧开始；用在按钮上，箭头就落在它按下的东西左边。弹层绘制在指针**之上**：三点菜单以 portal 挂载，其背景模糊把菜单后的箭头压暗并涂抹。chrome 控件**根本按不动**：`reload`、`back`、`forward` 经应用桥接被当作未知操作拒绝，于是用来表示动作的指针无法抵达它本应按下的按钮。指针还会**比它所依据的布局活得更久**：页面在静止指针下滚动后，箭头留在元素原先所在的位置；而无目标的滚动会从一份陈旧的指针位置记录出发，于是箭头从视口正中进入页面，而不是从读者最后一次看到它的地方进入。

## Decision

**瞄准按目标种类区分。** 按钮与链接取其盒子在两个轴向上的中心。地址栏是唯一例外，取左边缘加 `ADDRESS_TEXT_INSET_PX`，因为地址是从那里开始的文本。面板的 `centreOf`（元素）与 `leftOf`（地址栏）为这两种情形命名，于是规则在调用处可读，而不是藏在注释里。`CURSOR_TIP_OFFSET_PX` 补偿 overlay 自身的半盒约定 —— overlay 把指针的盒子居中在给定的点上，而绘制的箭头尖端是盒子的左上角 —— 使尖端落在面板所指的点上。同一个偏移也适用于 shell 上报的 guest 坐标，那些坐标是元素中心。

**指针的层位于页面的顶层。** 它作为 `position: fixed` 且 `z-index: 1300` portal 到 `BODY`，其盒子在挂载时、窗口尺寸变化时与滚动时由面板矩形写入。portal 是要求而非偏好：菜单是直接挂在 `BODY` 下的 `position: fixed; z-index: 1100` portal，因此它与整个面板子树平级，子树内任何 z-index 都无法绘制到它之上。带 `backdrop-filter` 的弹层会模糊其下绘制的一切，这正是指针变暗并被涂抹的原因。

**chrome 控件由名称指认，而非由 shell 定位。** 指针载荷携带 `action: 'control'` 与一个 `control` 名称（`back`、`forward`、`refresh`、`capture`、`more`、`zoom-in`、`zoom-out`、`zoom-reset`，地址栏则为 `navigate`）。shell 指认控件；面板找到它、把指针放到其中心并点击它。控件先在面板自身的 chrome 行中查找，再在文档中任何可见元素中查找，因为三点菜单的各行被 portal 到面板之外。按下会等待指针抵达，但绝不超过按下本身应耗的时间：读者置于另一个窗口之后的窗口会节流动画帧，而一个以该动画为条件的按下将永不触发。chrome 动作还会清除 shell 对指针页面位置的记录，因为指针离开了页面，去往一行并不在页面中的控件。

**页面移动后，指针回到它所在的元素上。** guest 自行上报它的滚动：桌面端为每个 guest 添加一个 CDP 绑定，并向每个文档安装一段上报脚本 —— `Page.addScriptToEvaluateOnNewDocument` 覆盖其后创建的文档，而每次导航都会向该导航打开的文档安装这段脚本，因为一次发生在两个文档之间的安装会让绑定无人调用。宿主窗口把每份上报转发给面板，面板重新测量它所在的元素并把指针放到该元素上；移动持续期间按面板自身的节流频率执行，停止后再执行一次。shell 自己执行的滚动的每一步都以 `action: 'scroll'` 上报，这是面板判断“指针正在自行定位”的信号；在手势过程中重新瞄准会与手势自身的定位相争。无目标的滚动会记录指针停下的点，于是下一次滚动从指针实际所在的位置开始它自己的手势。

**面板只绘制指针，别的什么都不画。** overlay 以 `decorations: false` 挂载，因此它不创建盒子，也不绘制点击光环、点击闪光或输入光标。动作是否落下由页面自身的反应呈现，而 agent 在读者正在阅读的页面上留下印记并不属于 overlay 的职责。保留下来的是指针自身的动作：它移动到它所操作的对象、按下，并停留在那里直到空闲淡出。

## Alternatives considered

- **提高面板的 z-index** 以越过菜单：菜单与面板平级，这样做是把菜单藏到面板内容之后，而不是把指针抬到菜单之上。
- **把指针层留在面板内部**并给它更大的 z-index：实测失败 —— 无论其内元素携带什么，整个面板子树都输给菜单自己的层。
- **在按下前等待 overlay 抵达**：实测失败，窗口位于另一个窗口之后时该动画永不推进。
- **让控件沿用地址栏的规则、瞄准其左边缘**：实测在水平轴上偏 −16 px，这正是读者报告为“指针偏在按钮左侧”的偏移。
- **给指针所操作的元素套上光环**：该光环曾被绘制并实测精确落在其元素上，随后应读者要求移除 —— 它标记的是读者正在阅读的页面，而指针自身的位置已经说明了它在操作什么。
- **在 shell 执行滚动期间重新瞄准指针**：实测为相互干扰 —— 面板在手势自身的各步之间把指针放回其元素上，使指针落后于它正在滚动的页面。
- **让面板轮询 guest 的滚动偏移**：否决 —— 要么每帧跨桥接做一次测量，要么猜测一个间隔，而页面本身就能上报它移动的那一刻。

## Consequences

指针属于窗口而非面板，因此面板几何的任何变化都必须重新放置它的盒子；该同步由面板负责。每个被按下的控件都需要一个 `data-control` 名称，没有名称的控件无法被指针抵达。地址栏始终是唯一的瞄准例外。overlay 的半盒约定与面板的尖端偏移是同一条规则的两半，必须一同修改。重新瞄准依赖 guest 可以拒绝的两项安装：一个附加调试器的绑定，以及一段按文档安装的上报脚本。无法接受它们的 guest 会把失败写入应用自身的日志，其指针此后停在最后一次动作放置的位置；除此之外不降级。每份滚动上报让面板多做一次对锚定元素的测量，而持续滚动的页面按面板的节流频率测量，而非每份上报一次。绘制的只有指针自身的动作，因此本面板不创建 overlay 的盒子、光环、闪光与光标，需要它们的调用方必须挂载不带 `decorations: false` 的 overlay。

## Verification

在运行中的 Electron 应用里实测，以指针尖端相对其目标计：refresh 为 `−1,−1` 且 guest 重新加载，back 为 `−1,−1`，forward 为 `−1,−1`，capture 为 `0,0`，更换网址时尖端位于地址文本起点且页面加载，页内链接点击为 `0,0`。缩放序列读出 `100% → 110% → 125% → 110%`，尖端落在每个控件上。页面滚动 160 px 时，锚定元素移动 160 px，指针移动 159 px，余下 1 px 偏差，且面板每次滚动收到一份上报（滚动 90 px 时为 `reports: 1`）。一次按下把指针记录在 guest 自身像素的 `58,107` 之后，无目标的滚动 200 px 把它移到 `58,157` —— 自身水平位置加上 50 px 漂移 —— 而视口正中为 318；随后一个 chrome 动作清除了页内记录，下一次无目标滚动从 `58,74` 进入，即该行的进入内缩加同样的漂移，再滚一次继续到 `58,124`。在 `decorations: false` 下，overlay 的根只持有指针层、指针与其精灵，且一次按下落下期间盒子、标签、光环、闪光与光标节点的计数均为零。菜单打开时指针清晰可见，是 portal 层的证据。`@aeven/experimental-browser-overlay` 的测试套件 90/90 通过。
