# Agent Note: Subagent 树内协调

Status: implemented

[English](2026-11-04-subagent-tree-coordination.md) | 中文

## 问题

委托工作可能需要兄弟之间或与更深后代通信。仅限直接父级的消息迫使中间节点转发并保持在线。无限制的子级启动可能耗尽模型和 Host 资源，而轮询 agent 列表会消耗请求却无法等待有用输入。

## 决策

现有继续执行管理器在同一棵树内路由模型编写的消息。每个 Activation 捕获确切在线的根。冷投递校验持久化 subagent 血缘，仅恢复目标，保留其持久父级，并将输入归于实际发送方。普通 fork 构成独立根。浏览器 Queue 投递保留直接父级授权；中断保留祖先授权。

服务拥有的容量池将可继续子级的启动、驻留和清理与一次性运行一起计数，一次性运行直到调用方释放才退出池。根不占槽位。准入失败而非排队，回滚与释放会归还槽位。默认值与 base bundle 上限为 16，以容纳已报告的 15 子级工作负载。

`list_agents` 为每个受管理调用方呈现根与可继续成员。`wait_agent` 观察下一步输入，不消费它或启动其他 agent，并在每条退出路径移除计时器与订阅。现有转发消息呈现显示发送方会话 id。

树内模型权限与发现取代[可继续对话](2026-07-28-continuable-subagent-conversations.zh.md)和[持久发现](2026-07-22-durable-subagent-catalog-and-list-agents.zh.md)中仅限直接关系的部分。这些记录保留描述符、生命周期与读取路径的理由。子级组合、提供方接口、worktree、嵌套策略与当前 UI 仍由各自机制负责；[共享任务板](2026-11-04-shared-task-board.zh.md)基于这一树身份构建。

## 考虑过的替代方案

替换完整上游运行时会引入子级 preset 选择与无关会话改动。扩展现有管理器保留现有提供方与组合。通过创建者转发会使投递依赖它们的驻留。在容量已满时排队，可能使占用槽位且等待后代的祖先发生死锁。

## 后果

兄弟可以交换消息，但不能互相中断。在线根仍是必要条件，容量仅在进程内生效。存储会话不占槽位。一次性调用方仍负责释放。协调不附带新的 UI 控件或面板。

## 验证

聚焦的运行时测试覆盖兄弟来源、无关树拒绝、仅目标冷恢复、嵌套与一次性容量，以及槽位复用。工具测试覆盖已有输入、steering、取消与卸载。录制的 SDK 会话固定发现行为与组装后的控制 schema。
