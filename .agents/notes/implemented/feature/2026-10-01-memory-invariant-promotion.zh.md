# Agent Note: 提升操作写入已确认不变量文档

Status: implemented

[English](2026-10-01-memory-invariant-promotion.md) | 中文

## Problem

不变量读取路径交付了一个没有任何界面能填充的块。`memory-context` 会把 `$AVN_HOME/memory/invariants/<owner>.json` 渲染进系统提示，而产品中没有任何东西写入该文档，因此每一位所有者脚下的底线始终为空。上一条笔记把这一缺口记为下一步；本条笔记把它补上。

两个位置事实排除了显而易见的写入方。`memory-context` 由预设按代理挂载，而预设把自身服务发布在 `isolate` 领域之后，因此它提供的服务对提供设置页面的宿主平面 Remote 不可见。并且该块使用的是来自该插件自身配置的上限来渲染，若由另一个包写入，就会持有决定“被提升的陈述能否真正到达请求”的那个数字的第二份副本——读取方丢弃写入方已接受的陈述，而这正是本功能要消除的静默丢失。

管理 Remote 完全没有不变量操作，设置 → 记忆只能修正或忘记模型记录下的内容。用户可以删除一条错误记忆；却无法声明某件始终应当被知晓的事，也没有哪条模型写入的记忆能保证不是编造的。

## Decision

`@aeven/memory-invariants` 在宿主平面拥有该文档：格式、渲染器、上限与变更操作，以 `ctx.memoryInvariants` 发布。`avn-base` bundle 挂载该行，因此每个 profile 都带有这个块，且该行不依赖记忆提供者——当召回什么都没有返回时，必须存在的正是这个块。预设作用域可以访问宿主服务，因此按代理的消费者无需与提供者共处一个包即可读取它。

存储同步地从所有者的文件作答，仅当大小或修改时间发生变化时才重新读取。两者都以 bigint 比较，因为在毫秒粒度下，同一 tick 内两次等长写入无法区分，会话会渲染它已经拥有的那个块。每次写入都用提示所用的同一个渲染器渲染候选文档，并在某条陈述放不下时整体拒绝，一条陈述无法放入空块时给出 `too-long`，块已无空间时给出 `full`。另一种做法——接受该陈述但不把它放进块——等于为一条永远不会到达的陈述付费。写入以一步替换文件，因此并发装配的提示读到的要么是旧文档，要么是新文档。

`@aeven/memory-context` 在每次装配时从服务读取该块，并把它的段落注册在顺序 `116` 上，位于记忆指引之后，因为模型对提示中较后部分赋予更高权重，而这些正是必须成立的陈述。`@aeven/api-memory-manager` 是唯一的写入方，通过四个新的 Remote 方法；设置页面把它们放在两处：记忆卡片上的 `始终记住`，提升卡片已经展示的那条事实；以及“长期事实”面板，列出当前生效的陈述、显示已用字符与上限，并可编辑或移除条目。

上限默认 1500 字符，而不是读取路径交付的 500。一个在用户不修改期间保持稳定的块位于可缓存的提示前缀中，因此它的成本低于其 token 数所暗示的水平，其大小是产品选择。可比较的常驻界面更大：Claude Code 建议单个记忆文件不超过 40,000 字符，并在其指令前加一句显式优先级声明；Hermes 冻结一份 3,575 字符的快照。在未启用缓存的多代理基准中，实测记忆注入占账单成本的 12%，而把检索窗口从 32 条降到 2 条使注入 token 减少 28.7%，准确率变化在种子波动范围内——因此上限在写入时强制执行，而不是交给读取方去信任。

该块的指引句声明优先级但不授予权限：这些陈述优先于召回的记忆、默认行为或推测；用户后续的请求可以覆盖它们；它们不授权用户未曾要求的任何工作。

## Alternatives considered

- **由 `memory-context` 提供该服务。** 预设的服务位于 isolate 领域之后，宿主平面 Remote 看不到它，最终还是需要一个宿主平面的提供者。
- **由 Remote 写入、把格式作为模块共享，保留两个存储实例。** 同一个文件上有两个上限和两份缓存，上限更大的写入方会接受读取方会丢弃的陈述。
- **块满时驱逐最旧的陈述。** 它从不拒绝提升，也不需要拒绝界面，但它会在不告知用户的情况下删除一条用户已确认的陈述。
- **通过模型工具进行提升。** 文档将因此可由模型主动写入，而这正是让编造的记忆无法进入每次提示的保证。
- **在 `memory-context` 内增加第二个 `startup` 式入口。** 宿主构建入口固定为 `index`、`invariant` 和 `startup`，而提供者不属于其中任何一个；为一行而放宽构建，代价高于它所要避免的新包。
- **现在就做工作区作用域的陈述。** 还没有任何界面能命名工作区，而文档的版本字段让以后增加作用域字段是安全的。

## Consequences

只有当写入装得下那个块时，陈述才会到达模型，因此用户从拒绝信息中得知该舍弃哪一条，而不是发现某个事实静默地从未出现在任何请求中。

文档是每位所有者一个文件、整体写入，因此第二个写入方会与第一个竞争。没有任何东西记录是哪条记忆提出了该陈述，也没有任何东西把该陈述与后续召回作比较：修正那条记忆后，陈述会一直保留到用户在设置中编辑它，而冲突由指引按“优先陈述”解决。

所有者作用域是唯一的作用域。项目约定要么为该账户的每个项目提升，要么完全不提升。

长期事实的设置界面没有 spec：`MemorySection.tsx` 位于按文件覆盖率门禁之外，因为没有 spec 导入它——设置 → 记忆页面的其余部分此前也是如此。本次变更把五个 locale 键改名为点号形式（`tabs.*`），这是客户端 UI i18n 门禁所接受的键形式。

## Verification

`@aeven/memory-invariants` 带有三十个用例的 spec：可读文档、不可解析的 JSON、未知版本、缺字段的条目、按所有者隔离、首次读取后发生变化的文档、会逃出目录的所有者 id、框架顺序、过长条目整体略过、字符上限、上报成本与最长陈述、指引不计入预算、写入的陈述可从磁盘读回、单行归一化、重复提升刷新同一条而不重复占用块、最新在前、空文本被拒且不写文件、长于块的陈述以 `too-long` 被拒、无空间的块以 `full` 被拒且文档逐字节不变、不留临时文件、写入仅作用于其所有者、能看到另一实例的写入、编辑保持位置与标识符、编辑未知标识符、编辑为空、编辑后放不下、移除释放块空间、移除未知标识符。`pnpm exec vitest run packages/memory/memory-invariants packages/memory/memory-context` 通过 38 个测试，提供者、消费者、Remote 与设置客户端的 `tsc -b` 均无错误，宿端与客户端构建均完成。

线上验证是重启后的宿主：从设置 → 记忆提升一条陈述后，真实请求的系统提示中出现该不变量块；移除该陈述后它再次消失。
