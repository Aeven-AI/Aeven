# Agent Note：认证屏幕带上官网的徽记

Status: implemented

[English](2026-11-02-auth-screens-carry-the-mark.md) | 中文

## Problem

`@aeven/client-ui-auth-aeven` 逐字移植了 Aeven 官网的登录与注册屏幕，移植保留了布局，却把左右分栏中的黑色半边空在那里：在官网上，那一半会把 Æven 徽记从暗处画出来，让徽记内部的一点光回应指针，并在指针停下后自行走动。移植后的屏幕在该列显示一片空白，而两个界面本应看起来一模一样；它们的密码输入框也无法让人看清自己输入了什么。

## Decision

徽记及其动效以官网自己的代码（而非模仿）搬进移植后的包：

- `MarkBackdrop` 在 `.graphics-container` 内渲染官网的图层树——`.auth-corner`、带 `.wide` 与 `.tight` 光晕的 `.auth-graphic`、`.auth-mark`，以及包住那点光的 `.auth-torch`——并以相同的数值启动同一批 GSAP 时间线：入场（角光在 2.6 秒内到 `0.9`；图形在 `0.12` 处以 1.9 秒从 `xPercent: -92` 到 `0`，其淡入为 1.7 秒；徽记 1.5 秒、从 `0.55` 开始；紧光晕到 `0.62`、宽光晕到 `0.4`），2.8 秒时交棒给以 `62% 38%` 为原点、`1.014` 的 17 秒呼吸缩放，指针的 `quickTo` 对为 `0.3`/`0.34` 秒、`power3`，停驻的光在 `(-0.24 w, -0.28 h)`，以及指针停下 2600 毫秒后开始的 8.5 秒自行游走。
- `gsap` 成为该包的依赖。要求是两个界面动得一模一样，而官网的动效是一条耦合的时间线：入场交棒给循环，指针跟随交棒给自行游走；手写的等价实现会在原版第一次改动时偏离。
- 样式表仍是 vendored 的那一份。新增规则追加在 `src/vendor/aeven-auth.css` 中、auth 视图的选择器链之下，因此没有任何规则会碰到页头自己的 `.auth-mark`，该文件也能继续与官网的 `_Authenticate.scss` 逐行对照。
- `prefers-reduced-motion` 显示静止的画面并什么都不启动：样式表带有最终透明度，组件则直接设置同样的值，而不播放入场。
- 密码输入框获得一个可见性开关：用 Lucide 的 `eye` 与 `eye-off` 路径做成 `type="button"` 按钮，在 `password` 与 `text` 之间切换，焦点留在输入框内，标签取自语言词典（`field.showPassword` / `field.hidePassword`，三份词典齐全）。

## Alternatives considered

- **用 CSS 或 Web Animations API 重写动效。** 两者都无法表达官网脚本所拥有的交接——入场时间线启动一个循环，跟随让位给自行游走——除非重建同一套调度，而那会得到第二份必须与第一份保持同步的动画。
- **整体复制官网编译后的 SCSS。** 官网的规则是全局的，而认证屏幕并不是这个客户端唯一绘制 `.auth-mark` 的地方：屏幕的页头也有一个，因此每条追加的规则都限定在 auth 视图的选择器链下。
- **把可见性开关放到共享的输入基元上。** 目前没有其他使用方需要它，而该基元的输入 `type` 是固定的；在出现第二个使用方之前，开关属于认证包自己的 `Input` 组件。

## Consequences

认证屏幕现在在运行时依赖 `gsap`，它被打进在插件图之前启动的客户端 bundle。时间线数值就是官网的数值，因此官网徽记动效的改动必须在这里同步——该文件在开头已写明这一点。开关只在 `type="password"` 时出现，其文案与本包中其他所有面向用户的字符串一样由语言词典拥有。
