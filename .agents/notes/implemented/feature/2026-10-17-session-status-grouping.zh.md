# Agent Note: 会话状态分组

Status: implemented

[English](2026-10-17-session-status-grouping.md) | 中文

## 问题

侧边栏的第二种分组模式 **In one list**（单列表）把所有 Session 合并成一条按更新时间排序的列表。更新时间回答的是"我最近碰过什么"，而不是"什么在等我"：一个卡在待批准上的 Session 除状态点外与其他行并无区别；当有多个 Session 同时进行时，读者必须逐行查看才能找出正在等自己的那个。

## 决策

### 按状态取代单列表

`SessionGroupBy` 为 `'workspace' | 'status'`。视图选项里的第二个分组项是 **按状态**；扁平列表、它的 `deriveFlat` 派生、它的浏览器本地顺序记账（`FLAT_SESSION_ORDER_KEY`）以及它的置顶分支都被删除，而不是与新模式并存。持久化的视图 store 迁移到 `avn.workspace.view.v6`，因此已存的 `flat` 偏好会退化为工作区呈现，而不会以 action 无法产生的值作为初始状态。

### 三个派生分组

`deriveStatusBuckets` 把每个可见 Session 投影到 **需要输入**、**进行中**、**已完成的工作** 三个分组，顺序即如此。`sessionBucket` 只读取行上已有的实时事实：待处理交互优先于其他任何事实（等待读者的 Session 是被阻塞，而不是在工作），其次是该 Session 自身的运行、运行中的 subagent 后代与其仍在运行的后台任务，其余均视为已结算。归属是列表投影的纯函数，因此当 Session 开始工作、等待或结算时，行会自行更换分组，无需事件或存储记录这次移动；刷新后重建的是同一份排布。

每个分组按时间从新到旧列出其行，并保留工作区分组的五行折叠与**显示全部**。分组默认展开其行，直到读者折叠它——它们就是列表本身，而不是读者主动开启的分段；折叠状态按分组键记录在与工作区分组共用的展开记录中。分组不接受重排序拖拽，展示时也不显示排序选项，因为顺序由活动决定；工作区的记账不受影响。

临时的新会话空白行在发出第一条消息前停留在**需要输入**：这个会话正等待读者开口，因此状态分组会显示它，而不是让新会话只在创建它的 Workspace 视图中可见。选中 Session 不会重新展开已折叠的分组：用户的折叠会保持到其亲自展开；只有要揭示的行位于五行折叠之后时，该分组的**显示全部**才会展开。`GroupNode.bucket` 携带分组判别值，使表头行绘制词典文案而不是 Workspace 标题；已归档分段也通过同一字段携带 `bucket: 'archived'`。

## 考虑过的替代方案

**在按状态之外保留单列表** —— 第三个分组项保留的列表，其"最近更新"语义在每个分组内部已经具备；它唯一独有的产物是手动顺序，而只要 Session 换组，手动顺序就失效。删除该模式同时移除了 `deriveFlat`、一份顺序记账和一条置顶路径。

**只显示非空分组** —— 空的**需要输入**分组恰恰是读者想要的答案（"没有在等我"）；隐藏它会把"没有"变成"不确定"，而且随着工作开始与结束，文件夹集合会在读者眼前变动。

**让新会话空白行不进入任何分组** —— 创建它的 Workspace 视图会列出它，但在状态分组中开始的新会话会在第一条消息发出前从这个正在查看的视图中消失。

**在分组内保留拖拽与排序选项** —— 分组内的手动顺序会在其 Session 更换分组的瞬间被丢弃，手势会承诺派生无法守住的结果。

**像工作区分组那样默认折叠** —— 分组就是列表本身，默认折叠会让这个模式渲染成三个空文件夹。

## 影响

- 侧边栏先回答"什么在等我"：待批准、待审计划与待回答的问题无论其他工作是否在跑，都排在列表最前。
- 状态分组首次忽略 Workspace 归属：来自每个 Workspace 的 Session 都会出现在分组中，包括由**显示自动化**选项控制的托管 Workspace。
- `apps/web` 的 e2e 用例（`workspace-management`、`schedule-after`）仍在驱动已被删除的 **In one list** 菜单项，按过期内容保留未改。

## 验证

`tree.client.spec.ts` 钉住分组成员与顺序、分类优先级（待处理优先于运行，后代与任务计为在飞）、新会话归入需要输入，归档/隐藏/subagent 排除，以及折叠行为与 `containsCurrent`。`workspace-browser.client.spec.tsx` 钉住菜单替换与其隐藏的排序选项、行随 Session 开始与结算在分组间移动、分组默认展开且折叠在选择后仍然保持并可由用户点击重新展开、新会话在第一条 prompt 后从需要输入移入进行中，以及揭示触发的溢出展开。`browser-styles.client.spec.ts` 删除已删除的扁平列表间距规则。
