# Agent Note: 已确认的不变量存在于每一次请求中

Status: implemented

[English](2026-10-01-memory-invariants.md) | 中文

## Problem

召回是一次查找，而查找可能什么都返回不了。在本部署上、标识符修复之前实测：四十五次回合起始召回中有七次丢掉了全部候选，五次完全没有返回记忆，而回合照旧运行、看上去一切正常。用户说过一次并期望一直成立的事实——希望如何回答提问、某个服务跑在哪个端口——在检索之下没有任何底线，因此一次静默未命中就会让依赖它的那次会话付出代价。

仅有“存在”并不是一个设计。系统提示中的块会在每一次请求上被付费，而且模型无法跳过它，这意味着其中一条错误条目会永久错误，并占用当前请求本就需要注意力。始终存在的记忆，其失败模式并不是“缺失”，而是“无法被忽略、且不能出错”。

## Decision

`@aeven/memory-context` 会把该所有者**已确认的不变量**渲染为一个小而始终存在的系统提示区块，排序在记忆指引之前。

该块是 Aeven 自己的文件，`avnHomePath('memory', 'invariants')/<owner>.json`，通过调用方自身的 home 解析而不是靠配置，因此其存在既不需要配置也不需要开启。它受 `invariantsMaxChars` 约束（默认 500），放不下的一条不变量会整条略过而不是被截断。该 section 按 agent 注册在该 agent 自己的作用域中，`text` 是一个在每次组装时求值的 provider；存储以文件大小与修改时间为键做缓存，因此一次组装只花一次 `statSync`，仅在文档真正变动时才解析。

两条性质使这个块可以安全地不可跳过：

- **只有用户能提升条目。** 这里没有任何内容由模型自行写入，因此模型推断出来的记忆——最可能自信出错的那一类——永远不会成为每一次请求的永久组成部分。
- **它是上下文，不是权威。** 该块像被召回的 memory 一样被读取，也同样可以被忽略。它从不触达执行点；必须约束某个动作的陈述属于 guard。

## Alternatives considered

- 照搬冻结快照设计：一个由模型撰写、约 3,500 字符、在会话开始时注入的大型策展块。基于三点被否决。成本每次请求都要付；快照看不到写入它的那次会话期间保存的任何内容；而提示中由模型撰写的散文，恰恰是模型出错时无法被召回的那种内容。
- 提升每一条被频繁召回、或带有结果证据的记忆。频繁只说明它被重复过，不说明它是对的，而不变量这一层正是“出错即永久”的那一层。
- 把不变量放在记忆 provider 中。provider 被刻意设计为可替换，而必须在更换 provider 后存活的那一层，最不该依赖它。
- 用一次辅助模型调用来整合该块。它会运行在请求路径上，而本计划禁止这一点；该块在不调用模型的情况下被读取并渲染，存储只花一次文件系统 stat。

## Consequences

在有什么东西写入某个所有者的文档之前，该块不贡献任何内容，而提升入口尚未构建：本次变更交付的是存储、边界与渲染器，填充它们的 Settings → Memory 路径是下一步。缺失或不可读的文档会渲染出空块而不是部分块，因此失败模式是一个空的层级，而不是一条错误陈述。

`memory-context` 现在会读取宿主的 home 路径服务并按 agent 注册，因此它以 `agents` 作为依赖。没有 Aeven home 的组合——SDK 或单用户测试——不贡献该块。

该块是建议性的，因此提升了一条不变量的用户得到的是“存在”，而不是“遵从”。让它产生约束是另一套机制：把一条被召回的偏好提升为执行点所读取的规则。

## Verification

一个十二例的 spec 覆盖了可读文档、不可读 JSON、未知版本、缺少字段的条目、空所有者、框架与顺序、过长条目整条略过、字符边界、按所有者隔离、首次读取后发生变化的文档，以及会逃出自身目录的所有者 id。`pnpm exec vitest run packages/memory/memory-context/tests` 通过该包三个 spec 的二十六项测试，`pnpm run typecheck` 无错误。

未度量：一次未命中在多大程度上会改变结果，以及一条被提升的不变量是否会改变 agent 的行为。两者都需要本 harness 尚未保留的逐回合记录；一旦提升入口存在，第二项就会在 `scripts/benchmark-memory.ts` 中被度量。
