# Agent Note: 在工具调用位置显示生成图片

Status: implemented

[English](2026-10-02-generated-images-at-tool-calls.md) | 中文

## 问题

Turn 过程折叠时，工具卡片内的生成图片会消失。读者看不到生成占位视图，助手复述图片还可能产生另一份副本，或让显示依赖后续模型回复。

## 决策

Imagine 为 `generate_image`、`codex_image_generate`、`codex_image_edit` 和 `grok_imagine_image` 注册原子视图。既有工具调用节点拥有提示词、运行／结果状态和持久图片块。运行调用在加载标记之上保留提示词控件；完成后以共享附件图库或失败状态替换状态。框就是图片显示时所处的盒子——单张图片以 3:2 占满对话列，单张竖图以 2:3 占其三分之二，多张图片在列内平铺——尚无图片的调用按自身参数给出的形状取框，即 `WIDTHxHEIGHT` 尺寸或 `W:H` 宽高比，因此占位内容预留的正是图片随后填充的那一个盒子。显式指定的图片张数各预留一个框，包括附件加载阶段。

可重放的 Turn 索引记录图片调用 id、已显示附件 id 和已知产物路径。Chat 让包含这些图片调用的调用树在过程展开控件之外保持可见；Tool 在保留各原子图片视图时隐藏普通祖先和相邻调用。展开过程恢复这些普通行。索引不包含图片字节，也不增加 HTTP 请求或会话事件。

通用工具卡片省略已由图片视图拥有的生成附件，包括父级代码执行结果转发的副本。重复索引中生成产物的助手图片块与 Markdown 图片源会被抑制；其他撰写图片保留既有解析器。工具描述和结果摘要说明生成图片已显示，不得重复、嵌入或通过路径呈现。类型化工作区副本输出仍可用；直接工具结果在既有展示元数据中记录这些路径。

这部分取代了 [工具结果图片在卡片中渲染](../architecture/2026-09-02-tool-result-images-render-in-the-card.zh.md)：其他带图片的工具保留通用卡片图库及其共享渲染器。附件包通过 Conversation 图片缓存保留加载、重试、灯箱和下载行为。

## 提示词控件

每个图片框左下角带有一个圆形提示词控件，取代图片下方的说明行。它沿用图库自身的圆形控件外观——不加投影、不带悬停态的白色圆盘，配 16 px 的 lucide `terminal` 字形——并改由应用统一的 tooltip 自述名称。点击后在与连接器技能弹窗相同的对话框中打开提示词：位于模态蒙层之上、居中的卡片，标题行带整段提示词的一键复制与关闭控件。调用运行期间控件位于加载层之上，失败框中同样保留，因此生成失败时提示词仍可查看。多图调用的每个图片框各自带有控件，打开的都是该调用唯一的提示词。标题、复制、已复制、关闭与控件名称等文案均取自 `imagine` 字典。

## 影响

图片显示从已记录的调用开始，无需助手复述。普通最终助手回复仍在工具结果之后。嵌套代码派发图片调用与直接调用共享相同的位置和图片所有者。视频生成保持独立，因为任务提交可能在视频字节存在之前完成。

## 验证

按用户要求，验证仅限 TypeScript 检查与构建：不运行测试套件或实际生成调用。

## 备选方案

展开过程组以显示图片也会暴露无关工作，且仍没有占位视图。依赖 Markdown 复述会让位置取决于模型行为。在工具节点之外渲染第二份图库会重复所有权，并可能在两处显示同一附件。占位视图无需进度事件，因为调用／结果生命周期已被记录。把提示词留在图片下方的说明行里，会让提示词与它生成的图片失去视觉关联，并让每个长提示词都占用对话列高度。锚定在控件旁的浮层能让提示词留在对话自身的层中，但会被图片框的圆角裁剪，也形成应用既有对话框之外的第二套形态；共享模态卡片与应用中其它详情视图的形态一致。
